# 操作日志 功能需求规格说明书

## 文档信息

- 基线 Feature：无
- 变更组：无
- 变更根节点：无
- 历史基线链：无

---

## 1. 概述

### 1.1 功能背景

平台的评估运营、配置维护、题库审核、账号台账等关键操作分散在各业务页执行，此前无任何留痕通道：维度权重何时被谁调整、大模型何时切换、账号何时被禁用，事后无法追溯。操作日志为全平台提供统一的操作审计能力，记录关键操作的执行人、对象、结果与变更内容，供运营审计时查询回溯。

### 1.2 本功能业务目标

1. 关键操作可追溯：平台账号的全部写操作（配置维护、评估运营、题库管理、用户管理等）与登录行为落库留痕，每条记录可定位操作人、操作对象、操作结果与变更前后内容。
2. 审计查询可用：操作日志页提供操作人、操作类型、操作结果、时间范围四维筛选与分页浏览，详情弹窗承载完整记录，支持按当前筛选导出 xlsx。
3. 记录通道零漏记：中间件统一拦截全部写接口兜底落库，关键配置域由 Service 埋点补充操作对象与变更对比语义，后续新增接口自动纳管。

### 1.3 与 PRD 拆分的对应关系

本 feature 即 PRD 5.2.2 的 F12（操作日志查询），承载系统基础模块的操作日志 1 个功能点。PRD 4.12.3 的日志查询子功能在本页承载，记录通道（中间件与关键域埋点）作非页面功能随本 feature 交付。经需求沟通决策：操作类型按业务域细化为八类（原型四类不够用）；记录范围为手动写操作 + 登录 + 批次级系统节点；日志保留 180 天定期清理；详情弹窗经易用性决策去掉来源 IP 与操作终端两字段。

## 3. 页面与功能总览

### 3.1 页面清单

| 序号 | 页面名称 | 页面形式 | 职责说明 | 包含功能 |
|-----|---------|---------|---------|---------|
| 1 | 操作日志页 | 独立页面（`_authenticated` 下 `/system/operation-log`） | 审计查询中枢：筛选区 + 日志列表 + 分页 + 导出 | 条件查询、条件重置、日志导出、详情查看 |
| 2 | 操作详情弹窗 | 弹窗对话框 | 单条日志的完整信息展示：基本信息 + 变更详情（变更对比表或文本摘要） | 关闭弹窗 |

### 3.2 页面跳转流程

```
[点击顶栏「系统配置 → 操作日志」] → [操作日志页]
    ├── 输入筛选条件 → 点击「查询」 → [操作日志页（结果刷新）]
    ├── 点击「重置」 → [操作日志页（条件清空，结果刷新）]
    ├── 点击「导出日志」 → [浏览器下载 xlsx]
    └── 点击行内「详情」 → [操作详情弹窗] → 点击「关闭」 → [返回操作日志页]
```

**流程说明：**

1. 运营人员从顶栏系统配置组的操作日志入口进入操作日志页，页面加载日志列表（默认无条件，按操作时间倒序）。
2. 需要定位特定记录时，输入操作人姓名、选择操作类型、操作结果或时间范围后点击查询，列表按条件刷新。
3. 需要留存审计材料时，点击导出日志按当前筛选条件下载 xlsx。
4. 需要查看单条完整记录（含变更前后对比）时，点击行内详情打开弹窗。

## 4. 页面功能详细说明

### 4.1 页面 1：操作日志页

#### 4.1.1 页面概述

**页面形式：**参见第3.1节页面清单

**页面职责：**全平台操作日志的统一审计查询页。上部为筛选区（操作人、操作类型、操作结果、时间范围四项），中部为日志列表（时间、操作人、操作类型、操作对象、详情摘要、结果六列 + 行内详情操作），底部为分页。列表按操作时间倒序排列。挂在系统配置导航组下，接通现有导航占位。

#### 4.1.2 涉及字段

##### A. 查询字段（列表页专用）

| 字段名称 | 字段类型 | 数据来源 | 默认值 | 业务含义 |
|---------|---------|---------|--------|--------|
| 操作人 | 文本 | 用户输入 | 空 | 按操作人姓名模糊匹配（通用规范 18 条），系统任务行（操作人为「系统」）同样可检 |
| 操作类型 | 下拉单选 | 系统预设（八类枚举，见 4.1.4 规则1） | 全部类型 | 按业务域筛选日志类型 |
| 操作结果 | 下拉单选 | 系统预设（成功/失败） | 全部 | 筛选操作执行结果 |
| 时间范围 | 日期范围 | 用户输入 | 空 | 按操作时间筛选，起止两端以自然日边界收拢（起始日 00:00:00、结束日 23:59:59） |

##### B. 显示字段

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 业务含义 |
|---------|---------|---------|---------|--------|
| 操作时间 | 文本（yyyy-MM-dd HH:mm:ss） | 数据库（operation_logs.created_at） | 列表加载 | 操作发生时刻，通用规范 9 条秒级精度 |
| 操作人 | 文本 | 数据库（落库时从 JWT 上下文取账号姓名；系统任务固定「系统」） | 列表加载 | 操作执行者标识，无工号 |
| 操作类型 | 标签 | 数据库（operation_logs.module） | 列表加载 | 八类业务域标签，配色见 4.1.5 交互逻辑 |
| 操作对象 | 文本 | 数据库（关键域埋点注入的业务对象描述；纯中间件行为路径级描述） | 列表加载 | 操作针对的业务对象（如「维度「任务适配判断力」聚合权重」「测试任务 T20260805」） |
| 详情摘要 | 文本 | 数据库（operation_logs.summary） | 列表加载 | 一句话操作摘要；过长截断悬浮展示全部（通用规范 11 条） |
| 结果 | 标签 | 数据库（success/fail） | 列表加载 | 成功/失败两态标签 |
| 详情 | 行级按钮 | — | 用户点击 | 打开操作详情弹窗 |

#### 4.1.3 功能与按钮

**用户可操作功能：**

- **条件查询**
  - 触发按钮：查询
  - 按钮级别：页面级
  - 按钮位置：筛选区末尾
  - 触发方式：点击按钮（操作人输入框支持回车触发）
  - 权限要求：已登录平台账号
  - 加载状态：结果列表显示加载中（查询为读操作，按钮本体无 loading 要求，通用规范 23 条针对数据修改类按钮）
  - 功能说明：按筛选区四项条件查询日志，分页回到第 1 页。空条件即全量倒序。

- **条件重置**
  - 触发按钮：重置
  - 按钮级别：页面级
  - 按钮位置：筛选区查询按钮旁
  - 触发方式：点击按钮
  - 权限要求：已登录平台账号
  - 加载状态：同条件查询
  - 功能说明：清空全部查询条件并回到无条件全量列表（通用规范 20 条），分页回到第 1 页。

- **日志导出**
  - 触发按钮：导出日志
  - 按钮级别：页面级
  - 按钮位置：列表标题栏右侧
  - 触发方式：点击按钮
  - 权限要求：已登录平台账号
  - 加载状态：按钮显示 loading 至下载开始
  - 功能说明：按当前筛选条件导出日志 xlsx（通用规范 16 条：有查询条件则导对应数据）。导出文件字段与生成逻辑见 4.1.4 规则 4。导出本身为只读行为，经易用性决策不记入操作日志。

- **详情查看**
  - 触发按钮：详情（链接按钮）
  - 按钮级别：行级
  - 按钮位置：列表操作列（固定展示，通用规范 12 条）
  - 触发方式：点击行内按钮
  - 权限要求：已登录平台账号
  - 加载状态：不适用（行数据已随列表加载，弹窗无二次请求）
  - 功能说明：打开操作详情弹窗，展示该行完整记录。

**前端自动流程：**

- **页面数据自动加载**
  - 触发时机：页面加载时
  - 说明：按当前筛选条件（初始为空）加载第 1 页日志列表，加载完成前显示加载状态；本页无轮询。

#### 4.1.4 业务规则

- **规则1：操作类型八类枚举**
  - 规则描述：操作类型按业务域划分为八类：登录（login）、用户管理（account）、维度与权重（dimension）、系统参数（system_params）、大模型配置（llm_config，含集成密钥维护）、题库管理（question_bank，含题目维护、批次审核、量表引入、AI 生成）、评估运营（assessment，含手动批次创建与测试任务运营）、系统任务（system_job，批次级节点）。
  - 触发条件：筛选下拉选项、列表与详情的类型展示。
  - 约束说明：枚举与导航业务域一一对应；集成密钥随大模型配置页维护（需求澄清决策 14），归 llm_config 类；测试任务的发起/重发/取消归 assessment 类（原型「测试管理」并入）。系统任务类仅承载系统自动写入的批次级节点（见 5.2）。

- **规则2：记录范围与结果口径**
  - 规则描述：入日志的操作为三类——平台账号全部写接口调用（成功与失败各一条，失败记录业务错误摘要）、登录成功与登录失败（失败仅记凭证错误通用口径摘要，保持反枚举设计）、系统自动任务的批次级节点。纯读接口（列表、详情、导出、统计）不入日志。
  - 触发条件：写接口被调用、登录请求发生、系统任务节点推进。
  - 约束说明：登录失败不区分账号不存在/密码错误/账号禁用（与账号域反枚举一致，四路径统一摘要「凭证校验未通过」）；操作结果 success/fail 以接口业务结果为准（业务错误码非 0 记 fail），参数校验失败同样记 fail 并摘要错误信息。

- **规则3：变更对比呈现口径**
  - 规则描述：详情弹窗的变更详情区分两种形态——关键域埋点操作（维度、活跃度规则、系统参数、大模型配置、集成密钥、账号台账）输出字段级变更对比表（变更前红色删除线、变更后绿色加粗）；其余操作（评估运营、题库管理、登录、系统任务）输出文本详情段落。
  - 触发条件：打开详情弹窗。
  - 约束说明：新增/删除类操作无「变更前/后」语义，统一走文本摘要形态；变更对比数据由 Service 埋点在写操作时构造，新建/密码类字段不出现在对比表中（密码永不落日志）。

- **规则4：导出文件定义**
  - 规则描述：导出 xlsx，文件名 `操作日志_YYYYMMDD_HHmmss.xlsx`（时间为导出时刻）。字段：操作时间、操作人、操作类型（中文名）、操作对象、详情摘要、结果（成功/失败）六列，与列表显示字段一致（不含行内操作）。数据来源 operation_logs，筛选条件与当前列表查询完全一致，排序同为操作时间倒序，单次导出上限 10000 行，超限时截断并在文件首行备注实际导出行数。
  - 触发条件：点击导出日志。
  - 约束说明：导出走独立 GET 接口旁路统一响应结构（同个人画像导出先例），blob 响应按 Content-Type 判别错误。

- **规则5：列表排序与分页**
  - 规则描述：列表按操作时间倒序排列，分页沿用通用规范 1 条（默认 10 条/页，可选 10/20/30）。
  - 触发条件：列表加载。
  - 约束说明：操作时间为唯一排序键，同秒内不保证次序（雪花 ID 落库，检索可详情区分）。

#### 4.1.5 交互逻辑

- 操作类型标签配色：八类分属不同语义色（登录 info、用户管理 secondary、维度与权重 warning、系统参数 secondary、大模型配置 destructive 点缀、题库管理 success、评估运营 primary、系统任务 outline 弱化），复用设计系统语义色 token，系统任务弱化以区分人工与自动。
- 失败结果行：结果列失败标签用 destructive 色，行内其余列不做整行染色（低频审计页保持克制）。
- 空状态：无匹配记录时列表区显示空态提示（暂无日志记录）；新库首访日志为空属正常态。
- 详情弹窗内滚动：内容超高时弹窗内部滚动（原子件已兜底），无额外处理。

#### 4.1.6 权限要求

参见第2.2节页面访问权限，本页面无特殊权限规则。

### 4.2 页面 2：操作详情弹窗

#### 4.2.1 页面概述

**页面形式：**参见第3.1节页面清单

> 弹窗无数据修改行为，关闭按钮的 loading 状态不适用（依据：通用规范 23 条针对数据修改类按钮）。变更对比与文本详情的分流规则归 4.1.4 规则 3，弹窗仅按数据形态渲染。

**用户可操作功能：**

  - 触发按钮：关闭（弹窗 footer）与右上角关闭图标
  - 按钮级别：页面级（弹窗内）
  - 按钮位置：弹窗底部
  - 触发方式：点击按钮或图标
  - 权限要求：已登录平台账号
  - 加载状态：不适用
  - 功能说明：关闭详情弹窗返回列表，无状态残留（重开取行数据重建）。

#### 4.2.4 业务规则

无额外业务规则（分流与呈现口径归 4.1.4 规则 3，空值回显沿用通用规范 10 条）。

#### 4.2.5 交互逻辑

- 弹窗打开即完整展示，无加载态与骨架（零请求）。
- 变更对比表与文本详情段落互斥渲染：有 changes 结构渲染对比表，否则渲染文本详情。

#### 4.2.6 权限要求

参见第2.2节页面访问权限，本页面无特殊权限规则。

## 5. 非页面功能详细说明

### 5.1 操作日志记录通道（中间件兜底 + 关键域埋点）

#### 5.1.1 功能概述

**触发方式：**API 中间件（事件监听式）
**触发时机：**受保护写接口（全部为 POST 请求）完成响应后、登录接口完成响应后
**功能职责：**统一拦截并落库操作日志。中间件层自动捕获账号（JWT 上下文姓名）、请求路径与方法、业务结果（响应 code 是否 0）、时间；关键配置域由 Service 在业务执行时经 gin.Context 注入操作类型、操作对象、详情摘要与变更对比结构，中间件合并为一条记录。未埋点的写接口自动以路径级语义落库（操作对象为「接口路径 + 动作」，摘要为请求概述），保证零漏记。

#### 5.1.2 处理流程

1. 写接口请求进入鉴权后的记录中间件（挂载于 JWT 之后，登录接口单独挂载）。
2. 中间件透传请求给业务 handler，业务执行。
3. Service 埋点（仅关键域）：在写操作成功路径上，将操作类型、操作对象、摘要、变更对比（before/after 字段级结构）写入 gin.Context 约定键；失败路径不注入或注入失败摘要。
4. 中间件在响应后读取业务响应 code（0 为成功）与注入的埋点数据，组装日志记录。
5. 异步落库（带缓冲通道，不阻塞业务响应；落库失败仅记 ERROR 日志，不影响业务结果）。

#### 5.1.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 操作人 | JWT 上下文（account_id、姓名）；登录接口取请求 username | 日志操作人列 | 登录失败时操作人记请求中的 username 原值 |
| 操作类型与对象 | Service 埋点注入 | 类型标签与对象描述 | 未埋点接口按路径规则推断业务域 |
| 变更对比 | Service 埋点构造（写前读旧值，写后取新值） | 详情变更对比表 | 密码与密钥类字段不进入对比结构 |
| 业务结果 | 响应 code | success/fail 判定 | 业务错误摘要取 message |

#### 5.1.4 业务规则

- **规则1：**记录范围遵循 4.1.4 规则 2 的三类口径；纯读接口不入日志。
- **规则2：**落库异步执行且失败不阻断业务：日志通道故障时业务照常，仅 ERROR 日志留痕。
- **规则3：**埋点注入的数据仅在中间件可见期内有效（单请求生命周期），不跨请求复用。
- **规则4：**敏感信息拦截：密码（含密文）、API Key、集成密钥明文、评分理由原文不入日志任何字段；密钥类操作的对象描述用脱敏掩码。

#### 5.1.5 异常处理

| 异常场景 | 处理方式 | 错误提示/日志 |
|---------|---------|--------------|
| 日志落库失败（DB 异常） | 丢弃该条记录，业务不受影响 | ERROR 日志记失败记录摘要 |
| 埋点注入数据缺失 | 降级为路径级语义记录 | 无 |
| 异步通道积压超限 | 丢弃最旧记录，保业务内存安全 | WARN 日志 |

#### 5.1.6 与其他功能的关联

- **上游依赖：**JWT 中间件（操作人上下文）、各关键域 Service（埋点注入）。
- **下游影响：**操作日志页（5.3 查询接口的数据源）、日志清理任务（5.2）。

### 5.2 系统任务批次级节点记录

#### 5.2.1 功能概述

**触发方式：**worker 任务执行节点
**触发时机：**批次创建完成、批次区间执行完成（终态）、批次失败超阈告警写入、测试任务自动逾期取消、建议生成完成或失败
**功能职责：**系统自动任务在批次级节点写入操作日志（操作人固定「系统」），供审计侧还原全自动链路的关键事件。tick 判定、逐人评估、单会话抽取等过程细节不记录。

#### 5.2.2 处理流程

1. worker 任务在节点完成处调用日志写入（同步落库或并入既有写事务旁路，实现期定）。
2. 组装记录：操作人「系统」、操作类型 system_job、操作对象（批次号或任务号 + 区间）、摘要（节点结果一句话）、结果（节点成败）。

#### 5.2.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 批次/任务标识 | assessment_batches、测试任务表、建议表 | 操作对象描述 | 携区间信息 |
| 节点结果 | 各任务执行返回 | 摘要与成败 | 降级与告警属失败类节点 |

#### 5.2.4 业务规则

- **规则1：**仅批次级节点入日志（建批、区间完成、告警写入、逾期自动取消、建议生成终态），过程细节不记，防日志膨胀。
- **规则2：**节点写入失败不阻断主任务（同 5.1.4 规则 2 的旁路口径）。

#### 5.2.5 异常处理

| 异常场景 | 处理方式 | 错误提示/日志 |
|---------|---------|--------------|
| 节点日志写入失败 | 跳过，主任务不受影响 | ERROR 日志 |

#### 5.2.6 与其他功能的关联

- **上游依赖：**P2_ASM_001 跑批编排、P2_TST_001 主动测试任务、P2_TMD_001 建议生成任务的节点回调。
- **下游影响：**操作日志页的系统任务类数据源。

### 5.3 操作日志查询接口

#### 5.3.1 功能概述

**触发方式：**API 调用（操作日志页加载、查询、分页）
**触发时机：**进入操作日志页或变更筛选条件
**功能职责：**分页查询操作日志，支持操作人模糊、操作类型精确、操作结果精确、时间范围四维筛选，按操作时间倒序返回。行数据内嵌详情所需全量字段（摘要、变更对比、文本详情），详情弹窗零二次请求。

#### 5.3.2 处理流程

1. 接收查询请求（JWT 鉴权）。
2. 校验筛选参数（类型与结果枚举合法性、时间范围起止顺序），非法值返回参数错误。
3. 组装查询条件（操作人走 LIKE 转义，时间范围按自然日边界收拢）。
4. 分页取数（默认 10/页），按操作时间倒序。
5. 组装返回，雪花 ID 以字符串传输。

#### 5.3.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 日志记录 | operation_logs（本 feature 新建表） | 列表与详情数据 | 含变更对比 TEXT 序列化字段 |
| 操作人姓名 | 落库时冗余存储 | 列表展示 | 不回查账号表，账号删除后日志仍可读 |

#### 5.3.4 业务规则

- **规则1：**接口纯只读，无写入；查询本身不记操作日志（读行为）。
- **规则2：**操作人模糊匹配必须转义 LIKE 通配符（多库方言约束）。

#### 5.3.5 异常处理

| 异常场景 | 处理方式 | 错误提示/日志 |
|---------|---------|--------------|
| 筛选参数非法 | 返回参数错误（HTTP 200 + 业务错误码） | 前端 toast 提示 |
| 查询失败 | 返回内部错误 | ERROR 日志 |

#### 5.3.6 与其他功能的关联

- **上游依赖：**5.1 记录通道落库的数据。
- **下游影响：**操作日志页与导出接口（4.1.4 规则 4，共享同一查询口径）。

---

### 5.4 操作日志导出接口

#### 5.4.1 功能概述

**触发方式：**API 调用（操作日志页点击导出）
**触发时机：**用户点击导出日志
**功能职责：**按当前筛选条件生成 xlsx 流式下载，字段与上限见 4.1.4 规则 4。旁路统一响应结构（GET blob 响应），错误按 Content-Type 判别。

#### 5.4.2 处理流程

1. 接收导出请求（JWT 鉴权），复用 5.3 的参数校验与查询口径。
2. 按筛选条件取数（上限 10000 行，操作时间倒序）。
3. 生成 xlsx（六列，同列表显示字段）并流式返回，文件名 `操作日志_YYYYMMDD_HHmmss.xlsx`。

#### 5.4.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 日志记录 | operation_logs | 导出内容 | 与列表同查询口径 |

#### 5.4.4 业务规则

- **规则1：**导出为只读行为，经易用性决策不记入操作日志。
- **规则2：**超 10000 行截断并在文件首行备注实际行数。

#### 5.4.5 异常处理

| 异常场景 | 处理方式 | 错误提示/日志 |
|---------|---------|--------------|
| 生成失败 | 返回错误（Content-Type 判别） | 前端 toast 提示导出失败 |

#### 5.4.6 与其他功能的关联

- **上游依赖：**5.3 查询口径复用。
- **下游影响：**无。

### 5.5 操作日志定期清理任务

#### 5.5.1 功能概述

**触发方式：**定时任务（Asynq scheduler）
**触发时机：**每日一次（低峰时点，实现期随 scheduler 注册）
**功能职责：**删除操作时间早于 180 天的日志记录，控制存储增长。保留窗口 180 天为固定常量（经易用性决策不进系统参数页）。

#### 5.5.2 处理流程

1. 定时触发，计算清理边界（当前时间减 180 天）。
2. 按主键分批删除边界前的记录（批量删除，避免长事务锁表）。
3. 记录本次清理条数（INFO 日志）。

#### 5.5.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 过期日志 | operation_logs | 清理对象 | 操作时间早于边界 |

#### 5.5.4 业务规则

- **规则1：**只删数据不删表结构；删除分批执行，单批大小实现期定。
- **规则2：**清理任务失败交调度重试，下个周期自然补偿（幂等：重复删除无副作用）。

#### 5.5.5 异常处理

| 异常场景 | 处理方式 | 错误提示/日志 |
|---------|---------|--------------|
| 清理执行失败 | err 透传交调度重试 | ERROR 日志 |

#### 5.5.6 与其他功能的关联

- **上游依赖：**Asynq scheduler（既有定时基建）。
- **下游影响：**操作日志页可查窗口为最近 180 天。

## 6. 数据状态定义

操作日志为追加型审计数据，无业务状态机：记录落库后仅被定期清理任务物理删除（5.5），不提供任何修改、撤回或人工删除入口。结果字段（success/fail）为落库时一次性判定，无转换。
