    ```go
    // gate 是底座全局在飞限制 + FIFO 排队器（specs §2.4 能力4）。
    type gate struct {
        // slots 容量 MaxConcurrency；queue 为 FIFO 等待队列，容量 QueueSize
    }
    func newGate(maxConcurrency, queueSize int) *gate
    // Acquire 排队获取在飞槽位：有槽立即占用；无槽进入 FIFO 队列；
    // 队列满返回 ErrQueueFull；ctx 取消返回 ctx.Err() 而非无限等待。
    func (g *gate) Acquire(ctx context.Context) error
    // Release 释放在飞槽位：优先放行队首等待者，队列空则归还槽。
    func (g *gate) Release()
    ```
  - 关键逻辑：`slots chan struct{}`（容量 MaxConcurrency）非阻塞获取；获取失败则入队等待。FIFO 保证：等待者按到达顺序放行，用通道或 mutex+等待链表实现，不引入优先级。队列满判定在入队前（队列长度 ≥ QueueSize → ErrQueueFull）。排队不占用在飞额度，只有放行后才计入。Release 与 Acquire 并发安全，同一槽只能释放一次（调用方保证单次，但 Release 内部用 select 兜底防重复放行）。

  **验收锚点：**
  - 核心断言：
    - `TestGateMaxConcurrency`：`newGate(4, 1024)` 并发启动 10 个 goroutine Acquire，统计同时在飞数 ≤ 4，全部成功
    - `TestGateQueueFull`：`newGate(1, 2)` 并发 5 个 Acquire，返回 ErrQueueFull 的数量 ≥ 2（用 `errors.Is(err, ErrQueueFull)` 判定）
    - `TestGateFIFO`：goroutine 依次 Acquire 记录放行顺序，断言等于到达顺序
    - `TestGateCtxCancel`：占用全部槽后发起新 Acquire，ctx 提前取消 → 返回 `context.Canceled`，不阻塞
  - 验证命令：`cd hr-backend && go test ./internal/integration/llm/ -run TestGate -count=1`

  **文件：**

  - 测试：`hr-backend/internal/integration/llm/retry_test.go`（由实现者按 TDD 指导创建）

  **契约：**
  - 签名：
    ```go
    // retryWithBackoff 对限流与瞬时错误按指数退避重试（specs §2.4 能力3）。
    // fn 返回 nil 即成功；返回 *httpError 时按 cfg 判定是否重试。
    func retryWithBackoff(ctx context.Context, cfg Config, fn func() error) error
    ```
  - 关键逻辑：
    - 重试判定 `isRetryable(he *httpError, cfg Config) bool`：`he.timeout == true` 可重试；`he.status` 在 `cfg.RetryOnStatus` 内可重试；否则不可重试立即返回（401、400 等确定性错误不重试，specs §2.4 能力3 注意事项）。
    - 等待时长：`he.status == 429 && he.retryAfter > 0` 用 Retry-After 时长；否则指数退避 `InitialBackoff * 2^attempt`，封顶 `MaxBackoff`。
    - 循环次数：初试 + MaxRetries 次重试，重试耗尽返回最后一次 `*httpError`（由 client 层 classify 为 ErrRateLimited / ErrRetryExhausted / ErrTimeout）。
    - `ctx.Done()` 在等待期间触发即返回 `ctx.Err()`。
    - `cfg.RetryOnStatus` 为空时用默认 `[429, 500, 502, 503, 504]`。

  **验收锚点：**
  - 核心断言：
    - `TestRetry429Recover`：fn 前 3 次返 `&httpError{status: 429}`、第 4 次 nil，`MaxRetries=3`、`InitialBackoff=1ms` → 返回 nil，fn 调用次数 == 4
    - `TestRetry429Exhausted`：fn 恒返 `&httpError{status: 429}`，`MaxRetries=3` → 返回的 `*httpError.status == 429`，fn 调用次数 == 4
    - `TestRetryNoRetry401`：fn 返 `&httpError{status: 401}` → 立即返回不重试，fn 调用次数 == 1
    - `TestRetry5xxExhausted`：fn 恒返 `&httpError{status: 500}` → 返回的 `*httpError.status == 500`，fn 调用次数 == 4
    - `TestRetryRetryAfter`：fn 首次返 `&httpError{status: 429, retryAfter: 50ms}`、二次成功 → 返回 nil，且首二次调用间隔 ≥ 50ms（记录时间差断言）
    - `TestRetryCtxCancel`：fn 恒返 `&httpError{status: 429}`，`MaxRetries=10`，ctx 在 20ms 后取消 → 返回 `context.Canceled`
    - `TestRetryNotRetryableTimeoutValue`：fn 返 `&httpError{timeout: true}`，`MaxRetries=3` → 返回的 `*httpError.timeout == true`，fn 调用次数 == 4
  - 验证命令：`cd hr-backend && go test ./internal/integration/llm/ -run TestRetry -count=1`
  - 预期输出：`ok  sili-smart-hr/backend/internal/integration/llm`

  **specs 依据：**
  - 章节范围：§2.4 能力3 指数退避重试、§2.2 cfg 重试参数、§5.1 测试方案
  - 技术规格索引：
    - [TS1] §2.4 能力3：429 尊重 Retry-After、指数退避倍增、401/400 不重试
    - [TS2] §2.2 参数列表：MaxRetries=3、InitialBackoff=30s、MaxBackoff=120s、RetryOnStatus=[429,500,502,503,504]
