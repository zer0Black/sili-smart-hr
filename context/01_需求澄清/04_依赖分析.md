# 04 依赖分析

> 本系统是兄弟系统 sili-smart-api（基于 new-api 的 LLM 网关）的下游数据消费方，评估能力依赖其对话日志资产，LLM 评分与阅卷走平台在大模型配置页自配的模型。两者松耦合：会话日志访问通过集成密钥鉴权调用 sili-smart-api，LLM 调用使用大模型配置页维护的地址与密钥。首期不引入组织架构，故不依赖组织主数据。本文只描述依赖关系，不涉及接口细节、SQL 与技术实现。

## 依赖概览

外部依赖集中在三类：一是 sili-smart-api 的会话日志库，作为对话分析评估的唯一数据源；二是平台自配的大模型，作为全量评分、AI 管理能力出题、阅卷的能力通道，模型地址与密钥由运营人员维护，可指向 sili-smart-api 网关也可直连其他模型；三是 sili-smart-api 的用户体系，提供人员标识到人名的映射。另有 IM 或邮件推送通道用于向员工推送一次性作答链接。会话日志与用户体系依赖 sili-smart-api，LLM 与推送通道的归属由配置决定。

## 依赖关系矩阵

| 本系统功能 | 依赖的外部系统 | 依赖类型 | 依赖说明 |
|:--|:--|:--|:--|
| 对话分析能力评估（S01） | sili-smart-api 会话日志库 | 数据依赖 | 读取员工会话日志作为 AI 使用能力评估的信号来源 |
| 使用活跃度统计 | sili-smart-api 会话日志库 | 数据依赖 | 从会话日志统计使用频率、轮次、最近使用时间 |
| LLM 评分、出题、阅卷（S01、S02、S04、S08） | 平台自配大模型 | 能力依赖 | 调用大模型配置页排他启用的模型完成特征抽取、综合评估、AI 管理能力题生成、统一阅卷 |
| 九型人格测评（S02） | 九型标准量表来源 | 数据依赖 | 引入经过验证的标准九型量表作固定题库 |
| 人员信息与画像归属 | sili-smart-api 用户体系 | 数据依赖 | 获取人员标识到人名的映射 |
| 主动测试作答推送（S02） | IM/邮件推送通道 | 能力依赖 | 向被测员工推送一次性作答链接 |

## 依赖详情

### sili-smart-api 会话日志库（ClickHouse）

- **依赖本系统的功能**：对话分析能力评估（S01）、使用活跃度基线统计
- **依赖类型**：数据依赖
- **依赖内容**：员工会话日志，承载会话标识、人员标识、发生时间、会话消息全文、token 数、轮次、工具调用次数等。会话按会话标识组织，首轮存全量、后续轮存增量，分析时需通过详情接口拼回完整会话内容。这是 AI 使用能力评估不可替代的独有资产。
- **数据流向**：外部 → 本系统
- **访问方式**：经集成密钥鉴权访问会话日志接口；集成密钥与 LLM 的 API Key 同属平台对外对接密钥，在大模型配置页统一脱敏展示、轮换与连通验证，不再单设独立的集成密钥页（决策 14）

### 平台自配大模型

- **依赖本系统的功能**：会话级特征抽取、跨会话综合评估、AI 管理能力题生成、统一阅卷
- **依赖类型**：能力依赖
- **依赖内容**：LLM-as-judge 评分是评分质量与一致性最高的手段，底层 4 维与上层 4 维的全量评分、AI 管理能力题的生成与阅卷统一走大模型配置页排他启用的模型；模型的服务商、API 地址与密钥由运营人员维护，可指向 sili-smart-api 网关也可直连其他模型服务商（九型人格用标准量表，不走生成）
- **数据流向**：双向（本系统发起调用，模型返回评分与生成结果）
- **约束**：一个活跃员工一周可能产生数十个会话，全公司周跑批调用量可观，成本、限流与跑批时长需按周频核算

### sili-smart-api 用户体系

- **依赖本系统的功能**：人员信息展示、个人画像与团队看板的归属标识
- **依赖类型**：数据依赖
- **依赖内容**：人员标识到人名的映射。首期仅取人名，部门归属、团队归属、组织架构对接全部后置
- **数据流向**：外部 → 本系统
- **待确认项**：用户接口是否含组织信息需在架构设计阶段进一步确认，影响后续组织架构对接

### 九型标准量表来源

- **依赖本系统的功能**：九型人格测评（S02）
- **依赖类型**：数据依赖
- **依赖内容**：经过验证的标准九型人格量表题目与计分映射，作为固定题库
- **数据流向**：外部 → 本系统
- **待确认项**：具体量表选型（如 RHETI 等）与授权方式留 PRD

### IM/邮件推送通道

- **依赖本系统的功能**：主动测试发起（S02）的一次性作答链接推送
- **依赖类型**：能力依赖
- **依赖内容**：向被测员工推送一次性作答链接，员工经链接进入轻量作答页提交后链接失效
- **数据流向**：本系统 → 外部
- **待确认项**：具体推送通道（企业 IM 或邮件）的选型与对接方式待定；首期通道暂未接入，作答链接由 HR 在评测运营中心作答链接弹窗复制后经 IM 或邮件手动分发，待通道对接后改为自动推送（决策 15）

## 依赖风险与约束

sili-smart-api 会话日志是本系统评估的数据命脉，其接口稳定性、字段可见度与集成密钥可用性直接决定评估能否运行。会话日志的工具可见度有限，通常只记录是否使用工具及调用次数，工具定义、调用参数、system prompt 是否留存需在架构设计阶段核实，影响工具相关维度的评分置信度。LLM 评分走平台自配模型，其可用性、限流与计费成本是中型规模下的硬约束，跑批节流与失败兜底（见 E03）围绕此约束设计。
