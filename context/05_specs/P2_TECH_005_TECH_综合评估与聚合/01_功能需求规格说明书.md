# 技术组件规格说明书

## 1. 概述

### 1.1 组件名称

综合评估与聚合（Assessment Evaluator / Scorer / Activity）

### 1.2 组件描述

engine 的三个计算子域：evaluator 读单人周期内全部会话特征档案，组装 prompt 一次性调 LLM 评完 AI 使用能力全部启用维度（0-100 整数分加脱敏理由）；scorer 把维度分按权重聚合为模块分与总览分（数据不足维度标记 evidence_insufficient 并从聚合中剔除）；activity 纯规则统计会话频率与轮次，按有效会话数分级活跃/低频/未使用，不调 LLM。本组件产出到评分与聚合结果落库为止，个人画像快照生成归 F6 评估运营域（消费本组件落库数据二次汇聚）。

### 1.3 创建背景

T4 会话特征抽取已把原始对话压缩为脱敏特征档案（session_features 表），PRD 技术泳道 T5 是档案到评分的最后一公里：单人周期内全部档案须一次性喂给 LLM 综合评估（跨会话证据互证，逐会话评分既贵又割裂），评出的维度分要按维度配置的权重聚合成模块分与总览分，使用活跃度作为能力评分的基线要纯规则统计。三者共用一次取数、一次落库，共同构成周期跑批的计算内核，被 T6 pipeline 编排驱动，周期批量与手动定向分析复用同一套处理器。

上游实证（2026-09-05 抽样，本周评估窗口 2026-08-30 23:00 起）：窗口会话总量 14078，最活跃单人窗口内 143+ 会话且 turn_count=1 占比约六成，与 T4 抽取规格披露的工作型 tc=1 / 自动化客户端人群签名吻合。单档案千字符级（T4 设计约束），最活跃人单周期档案集可达 100k+ 字符，evaluator 输入必须做预算控制，这是本组件档案集分层组装能力的直接动因。

T4 规格附录 7.2 留下 C01-C13 消费侧约束清单（证据稀薄误判、人群签名识别、降权语义等），本组件必须逐条承接，承接映射见 2.4 能力1 与附录 7.2。

## 2. 组件接口

### 2.1 能力清单

| 序号 | 能力名称 | 能力类型 | 说明 |
|------|---------|---------|------|
| 1 | 跨会话综合评估 | 基础 | 读单人周期全部特征档案，组装评分 prompt 一次调 LLM 评完对话分析全部启用维度，产出各维 0-100 整数分、脱敏理由与证据充足性标记；零有效档案时不调 LLM 直接落全维度降权行 |
| 2 | 档案集分层组装 | 基础 | 档案集超预算时的输入控制：周期统计汇总块（规则聚合，全量必进）+ 逐会话档案块（按证据密度降序、预算内截取），prompt 内披露可见档案占比 |
| 3 | 使用活跃度统计 | 基础 | 纯规则统计会话列表与档案表 status 分布，产出活跃/低频/未使用分级（基于有效会话数口径）与人群签名标注，不调 LLM |
| 4 | 人群签名识别 | 基础 | 承接 T4 C08-C12：按列表口径与档案 status 分布（含 client 列）识别自动化客户端、旁路族群、阈值误杀三类签名，输出 evidence_note 标注与处置（活跃度口径修正或数据不足标注），不作硬拦截 |
| 5 | 多维打分与聚合 | 基础 | 维度分按权重聚合为模块分与总览分（insufficient 维度剔除、剩余权重归一化），聚合口径统一服务对话分析与主动测试评分，幂等重算 |
| 6 | 单人周期评估原子入口 | 基础 | 供 T6 编排的一人一次组合入口：活跃度统计 → 综合评估 → 聚合落库，含幂等（已 success 跳过、failed 翻转），周期批量与手动定向分析复用 |

> **能力类型说明**：基础=核心必需能力 | 高级=增强型能力 | 扩展=可选能力

#### 配置项说明

```go
// 评估行为常量，包内定义，调整走代码变更发版。
const (
    MinValidProfilesForEval = 1     // 有效档案数下限：周期内 success 档案数 < 此值时跳过 LLM，
                                    // 落全维度 evidence_insufficient 评分行（零有效档案人群：
                                    // 未使用、旁路族群、自动化客户端，见 2.4 能力4）
    MaxProfileSetTokens = 30000     // 档案集 token 预算（evaluator 单人输入，非用户内容）
    MaxProfileSetChars  = MaxProfileSetTokens * 3 // 字符执行口径（1 token ≈ 3 字符，与 T4 同折算）：
                                    // 周期统计汇总块必进不占此预算判定（紧凑数字，千字符级），
                                    // 逐会话档案块（三块文本）合计超此值按证据密度截取
    MaxRationaleChars = 200         // 单维度评分理由字数约束，写在 prompt 模板文本内（模板为包内
                                    // 字符串常量，随模板版本化），落库校验容差 2 倍（超 400 判
                                    // schema 失败走重试），与 T4 摘要约束的承载机制同构
    ScoreMin = 0                    // 绝对分下界（0-100 整数分制，锚点区间约定见维度配置）
    ScoreMax = 100                  // 绝对分上界
)

// 活跃度分级阈值经维度配置读取（P2_DIM_001 活跃度规则：活跃判定下限默认 10、
// 低频判定下限默认 5），本组件不重复定义默认值，运行时从 dimension 域读取。

// Period 是评估区间（闭开区间，Unix 秒）。
type Period struct {
    Start int64 // 含
    End   int64 // 不含
}

// DimensionSpec 是参与评分的维度口径快照（从 dimension 域读取启用维度组装）。
// 取数时快照落评分行，保证历史评分可追溯（配置变更下次跑批生效，历史不重算）。
type DimensionSpec struct {
    Code         string  // 维度编码（唯一键，如 AI_INSTRUCTION）
    Name         string  // 维度名称
    Module       string  // 所属模块（AI 使用能力 ai_usage；聚合按模块分组）
    PromptText   string  // 评分提示词（仅对话分析维度非空）
    AnchorText   string  // 评分锚点（0-100 分值区间对应能力表现）
    Weight       int     // 模块内聚合权重百分比（0-100）
    InOverview   bool    // 是否参与总览分
}

// ProfileDigest 是从 session_features 行解析的档案消费视图（T4 FeatureProfile 的
// 消费侧裁剪：本组件只读四块内容与 status，不感知抽取内部结构）。
type ProfileDigest struct {
    SessionKey string
    Status     string          // success / failed / skipped
    Client     string          // 客户端标识（T4 分层探测落库列，人群签名维度）
    Stats      ProfileStats    // 统计块（success 与 failed 行均有；skipped 行零值）
    HasBlocks  bool            // success 行为 true（Summary/Instruction/Behavior 三块可用）
    ProfileJSON string        // 原始档案 JSON（success 行），仅内存临时持有
}
```

#### 评分 prompt 组装规则（C01-C13 承接映射）

prompt 模板为包内字符串常量（系统段 + 维度段 + 证据段 + 统计段 + 指令段），证据段与统计段的组装规则逐条承接 T4 消费侧约束：

| T4 约束 | 承接设计（组装进统计参考块或 prompt 指令） |
|---------|------------------------------------------|
| C01 零输入会话指令稀薄 | 统计块含 UserMsgCount 合计与零输入会话数；prompt 指令明确：指令类维度证据稀薄时标 insufficient，禁止把证据不足判为低分 |
| C02 narrative_absent 可信度降级 | 统计块含 narrative_absent 会话占比；价值产出与审查把关维度按占比作证据降权参考 |
| C03 工具证据粒度 | prompt 披露：工具证据仅达工具名与字符数级别，工作域归纳精度有限 |
| C04 同首指令哈希按重做 | prompt 指令：CmdReuseHashes 同首指令命中一律按重做/重试解读，不作知识沉淀复用证据计分，不设间隔条件 |
| C05 粘贴量联合判读 | 统计块含 PasteCharCount 合计、粘贴消息条数、UserMsgCount 三者联合呈现；prompt 指示单一事件主导的粘贴量不读作持续高约束供给习惯 |
| C06 failed 行参与降权 | 统计块含 failed 档案数；该部分会话仅统计块可用，LLM 段证据缺失 |
| C07 续接会话回顾文本 | 统计块含 continuation 会话数；prompt 指示续接推进会话的叙述混有上会话回顾，指令与价值判读联合识别防双重计数 |

人群签名类约束 C08-C12 的承接在能力4（规则侧），不进 prompt。

| Aggregate | ctx, tokenName, period | (*AggregateResult, error) | 多维打分与聚合（能力5）：读该人该周期全部评分行（含 F7 阅卷写入的主动测试维度）重算聚合行，幂等 |

```go
// EvaluateResult 是单人周期评估的组合结果。
type EvaluateResult struct {
    Activity  *ActivityStat     // 活跃度统计行（EvaluatePerson 路径产出）
    Scores    []DimensionScore  // 维度评分行（含 insufficient 标记行）
    Aggregate *AggregateResult  // 聚合结果（EvaluatePerson 路径产出）
    Skipped   bool              // true 表示零有效档案跳过 LLM（评分行仍落库：全维度 insufficient）
    Reused    bool              // true 表示命中既有 success 评分行复用未调 LLM（幂等，见能力6）
}

// DimensionScore 对应评分记录表 dimension_score（关键列，DDL 细节归 04 接口数据设计）：
// id（雪花）、token_name、period_start、period_end、dimension_code、module、
// score（int，insufficient 时落 0）、rationale（TEXT，脱敏理由）、insufficient（bool）、
// evidence_json（TEXT：周期 success 档案 session_key 清单 + 统计摘要快照，规则产出
// 全量追溯，不用 LLM 引用防幻觉）、source（conversation/active_test）、model_name、
// prompt_version、status（success/failed）、error_code、created_at。
// 唯一索引 (token_name, period_start, dimension_code)。
type DimensionScore struct {
    DimensionCode string
    Module        string
    Score         int
    Rationale     string
    Insufficient  bool
    EvidenceJSON  string
    Source        string // conversation（本组件）/ active_test（F7 阅卷）
    Status        string // success / failed
}

// AggregateResult 对应聚合结果表 aggregate_score（关键列）：id（雪花）、token_name、
// period_start、period_end、module、module_score（float，可空）、overview_score（float，
// 仅全模块行落值）、included_json（参与聚合维度与权重快照）、excluded_json（被剔除的
// insufficient 维度清单）、created_at。唯一索引 (token_name, period_start, module)。
type AggregateResult struct {
    ModuleScores map[string]*float64 // 模块分（模块编码 → 加权平均，全剔除时 nil）
    Overview     *float64            // 总览分（全部参与维度的加权平均，跨模块直聚合）
    Included     map[string][]string // 模块 → 参与聚合维度编码清单
    Excluded     map[string][]string // 模块 → insufficient 剔除清单
}

// ActivityStat 对应活跃度表 activity_stat（关键列）：id（雪花）、token_name、
// period_start、period_end、session_count（列表口径）、valid_session_count、
// skipped_count、total_turns、active_level（active/low_freq/unused）、
// population_note（人群签名标注文案键，见能力4）、client_dist_json（按 client 列
// 聚合的会话分布）、created_at。唯一索引 (token_name, period_start)。
type ActivityStat struct {
    SessionCount     int
    ValidSessionCount int
    SkippedCount     int
    TotalTurns       int
    ActiveLevel      string // active / low_freq / unused
    PopulationNote   string // 空串=正常人群；枚举见能力4
    ClientDist       map[string]int
}

// ProfileSet 是档案集分层组装产物（喂 LLM 的输入视图，仅内存临时持有）。
type ProfileSet struct {
    SummaryBlock  string   // 周期统计汇总块（规则聚合全部档案 Stats，全量必进）
    SessionBlocks []string // 逐会话档案块（success 档案按证据密度降序、预算内截取）
    VisibleCount  int      // 进视图的档案数
    TotalSuccess  int      // 周期 success 档案总数（截断披露：VisibleCount/TotalSuccess）
}
```

#### 错误码定义

| 错误码 | 说明 | 处理建议 |
|--------|------|---------|
| ErrNoDimensions | 无启用的对话分析维度（dimension 配置缺失或全部停用） | 评估无法运行的配置前置问题：不落评分行，error 上抛交 T6 记 ERROR，运营到维度配置页补齐 |
| ErrLLMEvalUpstream | LLM 评估调用失败（底座重试耗尽，含超时/排队满/限流耗尽态） | 落 failed 评分行（全维度占位，error_code 记因），当期聚合照常推进（该周期无对话分析维度分），补跑时重评 |
| ErrSchemaInvalid | LLM 输出未通过评分 schema 校验（重试一次仍失败） | 同 ErrLLMEvalUpstream 落 failed 行，补跑重评；观测指标 eval_schema_fail_ratio 集中抬升时核查当前启用模型 |
| ErrNoValidProfiles | 周期内零有效档案（success 数 < MinValidProfilesForEval） | 业务态非错误：跳过 LLM，落全维度 insufficient 评分行 + 活跃度行（人群签名 note），Evaluate 返回 Skipped=true 且 err=nil |
| ErrDimensionConfigRead | 维度配置或活跃度阈值读取失败 | 配置域数据访问异常：error 上抛交 Asynq 任务级重试，不落评分行 |
| ErrStoreWrite | 评分/聚合/活跃度落库失败 | 不落行，error 上抛交 Asynq 任务级重试；重试耗尽该人本周期无评分行，属 eval_fail_ratio 分子已知漏计项（观测替代见 6.2） |

### 2.4 能力详细说明

#### 能力1: 跨会话综合评估

**描述**: 单人周期一次 LLM 调用评完全部对话分析维度。流程：读维度口径快照（启用 + 数据来源=对话分析的维度，含提示词与锚点）→ ListByPersonAndRange 取档案（按 last_turn_time ∈ [Start, End) 内存二次过滤，末轮归属对齐活跃度口径）→ 人群签名识别（能力4）→ 零有效档案走 ErrNoValidProfiles 业务态 → 档案集分层组装（能力2）→ 组装 prompt → 经 LLM 调用底座调用当前排他启用模型 → schema 校验（失败重试一次，宽容解析同 T4：剥 markdown 围栏、截取首个含 dimensions 键的顶层平衡 JSON）→ 逐维度落评分行（rationale 落库前过 Redact 兜底脱敏，防御纵深）。

prompt 五段结构：系统段（人才能力评估评分员角色 + 输出 JSON schema 约束）、维度段（逐维度：名称 + 评分提示词 + 评分锚点，来自维度配置原文）、证据段（ProfileSet 逐会话块，每块带 session_key 标签）、统计段（ProfileSet 汇总块 + C01-C07 承接数据，见 2.2 组装规则表）、指令段（0-100 整数分、证据不足标 insufficient 且 score 置 null、理由 ≤200 字、同首指令按重做解读等判定纪律）。TokenName 组装前剥离，人员归属落库时回填，人名不进 LLM 上下文。

**评分输出 schema**（LLM 按 JSON 输出，逐维度）：

```json
{
  "dimensions": [
    {"code": "AI_XXX", "score": 72, "insufficient": false, "rationale": "维度评分理由（≤200字）"},
    {"code": "AI_YYY", "score": null, "insufficient": true, "rationale": "证据不足说明"}
  ]
}
```

schema 校验规则：code 须命中维度段集合（多出的丢弃、缺失的按 insufficient 补行）；score 非 null 时须为 0-100 整数；rationale 超 MaxRationaleChars×2 判失败。校验通过后，缺失维度与 insufficient=true 维度统一落 insufficient 行（score 落 0、标记 true），理由取 LLM 输出或配置的缺省文案。

**接口定义**:
```go
// Evaluate 对单人周期执行综合评估（不含活跃度与聚合）。
func (e *Evaluator) Evaluate(ctx context.Context, tokenName string, period Period) (*EvaluateResult, error)
```

**调用示例**:
```go
res, err := ev.Evaluate(ctx, "李雪涛", Period{Start: weekStart, End: weekEnd})
if err != nil { return err }   // 配置读取/落库失败交任务重试
if res.Skipped {
    slog.Info("eval skipped: no valid profiles", "token", tokenName)
    return nil
}
```

**注意事项**:
- 成本收敛：严格每人周期一次 LLM 调用；「会话量小的周期合并抽取与综合评估为一次调用」的优化属 T6 pipeline 编排范围（架构 3.1.2 成本控制条款），本组件保持接口独立
- 评分口径快照：DimensionSpec 在取数时快照进评分行（evidence_json 附维度口径摘要），维度配置变更后已产出历史不重算（与 DIM 规格规则1 配置生效时机一致）
- LLM 输出的维度 code 有幻觉面，以维度段集合为白名单收敛，缺失补 insufficient 行，禁止直接信任 LLM 枚举
- rationale 是 LLM 从已脱敏档案生成的文本，落库前仍过 Redact 正则集兜底（T4 能力5 的 Redact 函数复用，档案侧已脱敏，此为第二道防线）
- 档案集与 prompt 仅内存临时持有，禁止写日志、缓存与数据库（隐私架构，与 T4 同口径）

#### 能力2: 档案集分层组装

**描述**: evaluator 输入的预算控制。两层结构：

第一层周期统计汇总块：对全部档案（success/failed/skipped 三态）的 Stats 做规则聚合，产出紧凑数字块，无条件全量进 prompt（千字符级，不参与预算判定）。字段：会话总数/有效数（success+failed）/skipped 数、UserMsgCount 合计与零输入会话数、InterruptCount 合计、PasteCharCount 合计与粘贴消息条数、ToolCounts 汇总（top 10）、TurnKindCounts 汇总、SpecFingerprints 汇总（kind 计数 + 去重 hash 数 + 章节标题并集规模）、CmdReuseHashes 去重统计（同首指令命中组数）、continuation 会话数、narrative_absent 会话数、failed 档案数。此块即 C01-C07 承载数据的载体。

第二层逐会话档案块：success 档案的三块文本（Summary/Instruction/Behavior）逐会话组装（每块前缀 session_key 标签），按证据密度降序排列，合计字符数超 MaxProfileSetChars 时截取预算内前 N 个。failed 档案只有统计块（其 Stats 已汇总进第一层），不进第二层。

**证据密度排序**（确定性规则）：density = UserMsgCount×3 + 工具调用总量×1 + SpecFingerprints 数×2 + PasteCharCount>0 ? 2 : 0，降序；同密度按 session_key 字典序稳定排序。设计取向：指令、规约、粘贴是能力维度的主信号，工具量是次信号，密度高的档案优先可见。

**截断披露**：prompt 证据段头部注明「以下为 {VisibleCount}/{TotalSuccess} 个会话档案（按证据密度选取）」，LLM 知悉证据被截取；统计汇总块始终全量，截断只影响逐会话细粒度证据，分级判定的宏观依据不缺失。

**接口定义**:
```go
// AssembleProfileSet 分层组装档案集，纯读不调 LLM 不落库。
func (e *Evaluator) AssembleProfileSet(tokenName string, period Period) (*ProfileSet, error)
```

**调用示例**:
```go
set, err := ev.AssembleProfileSet(tokenName, period)
fmt.Printf("visible %d/%d, summary %d chars\n", set.VisibleCount, set.TotalSuccess, len(set.SummaryBlock))
```

**注意事项**:
- 预算判定只统计第二层字符数（三块文本），session_key 标签与分隔符不计（控制结构开销不侵占证据预算）
- 实测参照：最活跃人单周期 143+ 会话、单档案千字符级，全集可达 100k+ 字符，超 90k 预算触发截取属正常路径而非异常；首轮跑批后按 eval_visible_ratio 指标（6.2）观测截取面，若普遍低于 50% 评估下调档案单块规模（T4 模板约束）或上调预算
- skipped 行不进任何层（空壳会话对能力评估无信号价值，其计数已在汇总块的 skipped 数）

#### 能力3: 使用活跃度统计

**描述**: 纯规则统计，不调 LLM。两路输入形态：StatPersonByKey 内部经 P2_TECH_002 拉取周期窗口会话列表（全量拉取后按 token_name 内存分组，中文 token_name 上游过滤不可用，T4 3.2 既定约束）；StatPerson 由调用方传入已拉取列表。统计口径：

1. **窗口归属**：会话按 last_turn_time ∈ [Start, End) 归属本周期（末轮归属规则，边界会话只计一次，会话横跨窗口时前窗口末轮即归属锚点）
2. **列表口径计数**：SessionCount = 窗口内该人会话总数；TotalTurns = turn_count 合计
3. **有效会话数**：ValidSessionCount = 档案表 status ∈ {success, failed} 的行数（skipped 不计入有效；列表口径与档案口径的差值即 skipped_count + 拉取未落行数）
4. **分级判定**：ActiveLevel 按 ValidSessionCount 与维度配置活跃度阈值比较（≥ 活跃下限 → active；≥ 低频下限 → low_freq；否则 unused），阈值运行时读取（默认活跃 10 / 低频 5）
5. **人群签名**：调 IdentifyPopulation（能力4），签名 note 随行落库

落库 activity_stat 行，唯一索引 (token_name, period_start)，重算幂等覆盖（Aggregate 同款 upsert 语义：同人同周期重跑时按唯一索引更新，历史周期行不动）。

**接口定义**:
```go
// StatPersonByKey 拉列表并统计（内部经 P2_TECH_002）。
func (a *Activity) StatPersonByKey(ctx context.Context, tokenName string, period Period) (*ActivityStat, error)

// StatPerson 对调用方传入的列表统计（sessions 须已按窗口过滤）。
func (a *Activity) StatPerson(sessions []conversationlog.SessionSummary, tokenName string, period Period) (*ActivityStat, error)
```

**调用示例**:
```go
stat, err := act.StatPersonByKey(ctx, tokenName, period)
if err != nil { return err }  // 列表拉取重试耗尽等，交任务重试
slog.Info("activity", "token", tokenName, "level", stat.ActiveLevel,
    "valid", stat.ValidSessionCount, "note", stat.PopulationNote)
```

**注意事项**:
- 分级基于有效会话数而非原始会话数：自动化客户端人群列表口径虚高（C08），经 status 过滤后其 ValidSessionCount 趋零，分级自然落 unused/low_freq，这是活跃度侧承接 C08 的主通道
- 全员循环逐人调 StatPersonByKey 会重复全量拉取列表：T6 编排时应一次拉全量列表内存分组后逐人调 StatPerson（2.5 高级用法示例）；StatPersonByKey 仅供定向分析等单人场景
- 列表分页须串行翻页（T4 3.2：并发多页返回重复首页数据），本组件按 token_name 分组后按 session_key 去重兜底
- TotalTurns 是列表口径（含 skipped 会话的轮次），表征使用强度；能力证据口径在档案侧，两者语义分离不混用

#### 能力4: 人群签名识别

**描述**: 承接 T4 C08-C12 的规则侧识别，纯函数。输入周期会话列表与档案集，输出人群签名与 evidence_note，只标注不拦截：签名命中只影响活跃度口径修正与评分行的 insufficient 标记，不阻断评估流程。

| 签名 | 判定规则（按序，命中即止） | 处置 |
|------|--------------------------|------|
| auto_client（自动化客户端） | 档案全 skipped 或有效档案占比 < 20%，且列表会话量 ≥ 低频下限（列表量正常但档案趋零，C08 签名） | ActiveLevel 强制降为 unused；评分行全维度 insufficient；note 记 evidence_note.auto_client |
| bypass_orchestrator（编排工具旁路） | 档案全 skipped 且列表会话量 ≥ 低频下限，与 auto_client 判据重合时先核 client 列（C10：client ∈ {workbuddy, omo} 优先判旁路，真实能力证据在父会话本系统不可见） | 不强制降级：ActiveLevel 按有效会话数自然落 unused，评分行 insufficient；note 记 evidence_note.bypass，画像呈现「数据不可见」而非「零能力」 |
| threshold_overskip（阈值误杀） | 档案全 skipped 且列表会话量 ≥ 低频下限且 client 非旁路族（C12：kept 7-9 边缘误杀形态，签名与旁路重合） | 同 bypass 落 insufficient；note 记 evidence_note.threshold，画像标注阈值边界（运维侧经代码变更评估下调 MinKeptMessages 可恢复） |
| work_tc1（工作型 tc=1） | tc=1 会话占比高但档案多为 success（C09 签名重合区分：先核 status 分布再定性） | 正常人群不处置：档案 success 证明单请求内多轮真实工作，不降权不标注 |

判定次序设计：auto_client 的「档案趋零」判据是强信号，但与 bypass/threshold 三者共享「档案全 skipped」表型，区分轴是 client 列与 success 占比：success 占比 ≥ 20% 走 work_tc1 正常路径；client ∈ 旁路族判 bypass；其余档案趋零形态判 auto_client；threshold 签名保留给后续跑批数据区分（首期与 bypass 同表型暂并列，note 文案区分）。C11（会议整理子请求稀释）不构成整人签名（散布于正常用户名下，本人另有 success 兜底），识别规则不覆盖，其影响已在档案集稀释中自然消化。

**接口定义**:
```go
// IdentifyPopulation 人群签名识别，纯函数不调 LLM 不落库。
// sessions 为周期窗口列表（token_name 过滤后），profiles 为对应档案集。
func IdentifyPopulation(sessions []conversationlog.SessionSummary, profiles []ProfileDigest) PopulationSignature

type PopulationSignature struct {
    Kind string // normal / auto_client / bypass_orchestrator / threshold_overskip / work_tc1
    Note string // evidence_note 文案键，空串为 normal
}
```

**调用示例**:
```go
sig := IdentifyPopulation(sessions, profiles)
if sig.Kind != "normal" {
    slog.Info("population signature", "token", tokenName, "kind", sig.Kind)
}
```

**注意事项**:
- 签名判定是启发式规则，误判代价是 note 标注偏差（画像呈现口径），不阻断任何评估路径；首轮跑批后按 6.2 population_signature_ratio 观测各签名占比，偏离预期时调判定阈值
- note 文案键经 i18n 前端呈现（F6/F9 消费），本组件只落枚举键不落中文文案，避免文案变更动数据
- client 列依赖 T4 分层探测（P2_TECH_004）落库，探测 unknown 时 bypass 判定退化为 auto_client 表型并列（可接受近似，观测侧按 client_dist_json 人工核对）

#### 能力5: 多维打分与聚合

**描述**: 维度分到模块分到总览分的规则聚合，不调 LLM。聚合输入是评分行全量（conversation 与 active_test 两 source 并列，主动测试维度由 F7 阅卷写入，本组件统一聚合）：

1. **聚合域**：同人同周期全部 status=success 评分行；insufficient 维度与 failed 维度（无分）剔除出聚合
2. **模块分**：模块内参与总览（InOverview）且非剔除的维度，按权重加权平均，保留一位小数；模块内全部剔除时该模块分置 nil（画像呈现「数据不足」）
3. **总览分**：全部参与维度的加权平均（跨模块直接聚合，权重即各维度权重百分比），保留一位小数；无任何参与维度时置 nil
4. **权重归一化**：剔除 insufficient 维度后剩余权重和为 W'，模块分/总览分按 W' 归一化（等价于剔除维度权重清零后重分配），口径见 2.3 AggregateResult 的 included/excluded 快照
5. **幂等重算**：Aggregate 按唯一索引 upsert（同人同周期同模块覆盖更新），F7 阅卷新增评分行后重调即刷新聚合；历史周期行不动（配置变更历史不重算）

**聚合公式**（模块分，总览分同构）：

```
module_score = Σ(score_i × weight_i) / Σ(weight_i)，i ∈ 参与维度
```

**接口定义**:
```go
// Aggregate 重算单人周期的聚合行（读全部 source 评分行），幂等。
func (s *Scorer) Aggregate(ctx context.Context, tokenName string, period Period) (*AggregateResult, error)
```

**调用示例**:
```go
agg, err := sc.Aggregate(ctx, tokenName, period)
if err != nil { return err }
slog.Info("aggregate", "token", tokenName, "overview", *agg.Overview,
    "excluded", len(agg.Excluded["ai_usage"]))
```

**注意事项**:
- 权重和偏离 100 是配置侧常态（DIM 规则只建议不强制）：聚合按实际权重归一化，不校验不纠偏，画像侧呈现权重快照即可解释
- 九型人格等参考性维度（InOverview=false）不进聚合，只落评分行供画像补充解读
- 聚合与评分解耦：F7 阅卷链路写入评分行后自调 Aggregate 刷新，本组件不感知阅卷时机（T6/F7 编排）
- float 落库精度：模块分/总览分保留一位小数（round half up），跨库 float 存储用 float64 列（GORM 通用类型）

#### 能力6: 单人周期评估原子入口

**描述**: 供 T6 编排的一人一次组合入口。执行序列：活跃度统计（StatPersonByKey）→ 综合评估（Evaluate，含档案取数、签名识别、组装、LLM、评分落库）→ 聚合（Aggregate）→ 返回组合结果。幂等规则：

1. 该人该周期已有全部 success 评分行（维度数齐全且无 failed）时，跳过 LLM 调用直接复用（Reused=true），活跃度与聚合照常重算（列表数据与 F7 评分行可能已变）
2. 存在 failed 评分行时重评：删旧 failed 行后走完整 Evaluate（failed 翻转语义与 T4 档案行同构，但评分行是整体重评非单维补评，LLM 一次调用产出全维度）
3. 周期批量与手动定向分析复用本入口：定向分析传入更窄 period，落库行按 (token_name, period_start) 隔离，与周期批量行并存

周期批量时 T6 先一次拉全量列表分组，逐人调 EvaluatePerson 前把分组列表经 StatPerson 注入（2.5 完整示例）；本入口的 StatPersonByKey 路径仅供单人场景，避免全员循环重复拉取。

**接口定义**:
```go
// EvaluatePerson 单人周期评估原子入口（活跃度 → 评估 → 聚合）。
// sessions 可空：空时内部 StatPersonByKey 拉取；非空时直传 StatPerson 免二次拉取。
func (e *Evaluator) EvaluatePerson(ctx context.Context, tokenName string, period Period, sessions []conversationlog.SessionSummary) (*EvaluateResult, error)
```

**调用示例**:
```go
res, err := ev.EvaluatePerson(ctx, tokenName, period, nil)
if err != nil { return err }  // 交 Asynq 任务级重试
if res.Reused { slog.Info("eval reused", "token", tokenName) }
```

**注意事项**:
- 组合入口不包事务：三表落库各自独立（活跃度行、评分行、聚合行），中途失败重跑时已落库行按幂等规则收敛，不回滚（评估数据可重算，无需跨表原子性）
- LLM 段失败（ErrLLMEvalUpstream/ErrSchemaInvalid）落 failed 评分行后组合入口继续执行聚合（聚合自然剔除 failed 维度），当期推进优先，补跑时重评；活跃度行不受 LLM 失败影响照常落库
- error 通道只留给基础设施类错误（配置读取失败、落库失败、列表拉取重试耗尽），交 Asynq 重试；业务态（零档案跳过、LLM 降级）不占 error 通道，与 T4 错误分流哲学一致

## 3. 技术约束

### 3.1 性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 活跃度统计耗时 | ≤ 500ms / 人（不含列表拉取网络耗时） | 纯内存规则统计（分组、去重、status join、阈值比较） |
| 档案集组装耗时 | ≤ 200ms / 人（150 档案内） | 全量 Stats 聚合 + 密度排序 + 截取，内存操作 |
| 综合评估 LLM 调用 | ≤ 120s / 人（单次调用口径，正常路径） | 受 LLM 响应主导；底座重试与最坏路径由 2.2 的 420s ctx 预算承载 |
| 聚合耗时 | ≤ 100ms / 人（20 维度内） | 评分行读取 + 加权平均 + upsert，线性复杂度 |
| 档案集预算 | 逐会话块合计 ≤ MaxProfileSetChars（90000 字符，30000 token 折算） | 统计汇总块必进不占预算；截取按证据密度，超限属正常路径（1.3 实证） |
| 并发吞吐 | 由 worker 并发度承载，LLM 在飞 ≤ 4（底座全局） | 一人一任务；评估调用是周期跑批的吞吐瓶颈，成本按周频核算 |
| 内存占用 | 档案集与 prompt 会话级临时持有 | 处理完成即释放，无跨人缓存 |

### 3.2 兼容性要求

### 3.3 安全要求

| 安全项 | 要求 | 实现方式 |
|--------|------|---------|
| 对话原文不进本组件 | 本组件只消费脱敏档案，不接触原文 | 档案自 session_features 表读取（T4 已脱敏），无原文通道；档案集与 prompt 仅内存临时持有，禁止写日志、缓存与数据库 |
| 评分理由脱敏 | rationale 落库前过 Redact 正则集 | T4 Redact 函数复用（第二道防线：档案侧已脱敏，LLM 复述仍可能拼出敏感形态） |
| 人名不进 LLM 上下文 | prompt 组装前剥离 TokenName | 人员归属落库时回填 token_name 列 |
| 日志最小化 | 日志只含 token_name、period、计数、维度 code、错误码 | 禁止输出档案内容、prompt 文本、rationale 原文（rationale 落库供画像消费，不进日志） |
| 人员标识最小化 | 三表只存 token_name 归属字段 | 无工号（系统无工号约束），无 user_id 冗余（全库恒 1 无区分度） |
| 评分可追溯 | 每维度评分行携带 evidence_json | 支撑证据的 session_key 清单与统计摘要快照（规则产出非 LLM 引用），服务 PRD 评分可解释诉求 |

## 6. 监控与运维

### 6.1 日志规范

| 日志级别 | 使用场景 | 示例 |
|---------|---------|------|
| DEBUG | 组装统计、单次评估成功 | profile set assembled token=... visible=45/143 summary_chars=2100 |
| INFO | 人群签名命中、零档案跳过、评分复用 | population signature token=... kind=auto_client / eval reused token=... |
| WARN | schema 校验失败重试、档案集截取触发 | eval schema invalid, retrying token=... / profile set truncated token=... visible=45/143 |
| ERROR | LLM 评估失败、落库失败、配置读取失败 | eval failed token=... code=ErrLLMEvalUpstream |

日志字段只含 token_name、period、维度 code、计数与错误码，禁止输出档案内容、prompt 文本、rationale 原文（隐私架构）。

### 6.2 监控指标

| 指标名称 | 指标类型 | 说明 | 告警阈值 |
|---------|---------|------|---------|
| eval_fail_ratio | 比率 | 单周期综合评估失败率（failed 评分行人次 / 评估人次）。口径披露：ErrStoreWrite 落库失败的人次无评分行，漏计属已知口径，ERROR 日志计数辅助观测（与 T4 extract_fail_ratio 同构） | ≥ 10% 触发工作台待处理告警（对齐架构 2.2 约定） |
| eval_schema_fail_ratio | 比率 | schema 校验失败占 LLM 调用比 | ≥ 20% 观测（模型 JSON 能力或 prompt 退化信号，参照 T4 问题3） |
| eval_visible_ratio | 比率 | 档案集截取面：VisibleCount/TotalSuccess 的人均加权均值 | 人均值 < 50% 连续两周期观测（评估调整 T4 单档案规模或本预算，见 2.4 能力2 注意事项） |
| population_signature_ratio | 比率 | 各人群签名占评估人次比（按 Kind 分桶） | 无告警，仅观测（首轮跑批回填基线，偏离预期时调判定阈值） |
| unused_ratio | 比率 | 未使用人群占比（ActiveLevel=unused） | 无告警，仅观测（对齐 PRD 未使用人群识别功能的数据基础） |
| eval_duration | 延迟 | 单人综合评估耗时分布（含 LLM） | p99 > 180s 观测（正常路径 LLM 主导 ≤ 120s） |
| aggregate_duration | 延迟 | 单人聚合耗时分布 | p99 > 1s 观测 |

### 6.3 告警规则

| 告警名称 | 触发条件 | 严重程度 | 处理建议 |
|---------|---------|---------|---------|
| 评估失败率超阈 | 单周期 eval_fail_ratio ≥ 10% | 中 | 运营经工作台决定是否补跑（复用手动定向分析入口），补跑走 failed 评分行重评 |
| schema 失败集中 | eval_schema_fail_ratio ≥ 20% | 中 | 核对当前排他启用模型与大模型配置，必要时切换模型后补跑；检查 prompt 模板版本 |
| 档案集截取面过大 | eval_visible_ratio 人均值 < 50% 连续两周期 | 低 | 评估下调 T4 档案单块规模（走 T4 模板变更）或上调 MaxProfileSetTokens（代码变更），二者取一 |

### 6.4 故障排查

#### 常见问题

**问题1: 大批人员评分全 insufficient**
- 现象: 某周期大量人员全维度 insufficient，population_signature_ratio 中 auto_client/bypass 占比抬升
- 原因: 上游注入形态变更致档案大量落 skipped（T4 黑名单失效连锁），或真实人群变化（新自动化工具接入）
- 解决: 先查 T4 的 skip_ratio 与 inject_residual_ratio（按 client 拆分），确认档案侧根因；本组件签名判定只是下游呈现，修复在 T4 参数页或规则层

**问题2: 评分理由质量差或维度分异常**
- 现象: rationale 空泛、分数集中某档、跨人无区分度
- 原因: 档案集截取面过大（eval_visible_ratio 低，证据不足）、维度提示词或锚点配置质量问题、模型能力不足
- 解决: 按序排查：eval_visible_ratio 确认证据面 → 维度配置页核对提示词与锚点 → 大模型配置页核对启用模型；prompt 模板调整走代码变更

**问题3: 聚合分与画像呈现不一致**
- 现象: 模块分/总览分与画像页呈现对不上
- 原因: F7 阅卷写入后未触发 Aggregate 刷新（编排遗漏），或权重配置变更后历史行未重算（属设计内：配置下次跑批生效）
- 解决: 核对 included/excluded 快照定位口径差异；编排侧确认阅卷后刷新调用；配置变更等下周期自然收敛

**问题4: 活跃度分级与直觉不符**
- 现象: 会话量很大的人被判 unused/low_freq
- 原因: 有效会话数口径（skipped 不计），该人多为自动化客户端或旁路会话（签名 note 可证）
- 解决: 查 population_note 与 client_dist_json 确认人群归类；属设计内口径（C08 承接），如需人工复核按 client 分布核对
