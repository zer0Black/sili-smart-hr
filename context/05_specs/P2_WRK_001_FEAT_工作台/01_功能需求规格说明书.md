## 1. 概述

### 1.1 功能背景

平台的评估生产链路（周期批量评估 P2_ASM_001、主动测试 P2_TST_001）与结果消费链路（个人画像 P2_PRF_001、团队看板 P2_TMD_001）均已贯通，但运营人员登录后的落地页仍是脚手架占位页，看不到本期评估态势与需要处置的待办，需要自行进入各业务页拼凑全局。工作台作为登录后的默认落地页，把分散在评测运营中心、团队看板、人员画像中的关键态势与待处理计数聚合一屏，并就近提供跳转。

### 1.2 本功能业务目标

1. 态势一屏可见：登录即见本期跑批态势（最新周期批次状态、下次跑批时点）与结果态势（两模块综合分、活跃率、未使用人数及环比），无需逐页查找。
2. 待办有数可依：跑批失败超阈告警次数与主动测试逾期任务数以统计卡呈现，异常就近跳转处置。
3. 人群就近定位：短板与未使用两类需要关注的人（各前 5）在工作台直接列出，逐行跳转个人画像详情完成处置。
4. 团队速览可下钻：团队整体画像（双模块雷达、九型构成、共性短板与研判）以精简形态呈现，完整消费跳团队看板。

### 1.3 与 PRD 拆分的对应关系

本 feature 即 PRD 5.2.2 的 F11（工作台），承载工作台模块的工作台总览 1 个功能点。PRD 4.7.3 中的三个子功能（本期评估态势、需关注人群入口、待处理项提醒）均在本页承载。经需求沟通决策：原型 index.html 的四块结构全保留，首屏新增态势与待处理统计卡区，评估区间切换移除（工作台固定本期，历史趋势经团队看板承载）；PRD 4.13/4.14.6 原「向导完成后工作台就近提示未完成配置项」的职责经决策取消，运行配置就绪情况由系统状态页承载，PRD 与 P1_SYS_001 规格同步修订。

## 3. 页面与功能总览

### 3.1 页面清单

| 序号 | 页面名称 | 页面形式 | 职责说明 | 包含功能 |
|-----|---------|---------|---------|---------|
| 1 | 工作台首页 | 独立页面（`_authenticated` 根路由 `/`，登录后默认落地） | 总览与跳转中枢：态势与待处理统计卡、团队能力演进、团队整体画像速览、需要关注的人 | 态势与待处理卡跳转、能力演进图查看、画像区跳转团队看板、关注人群跳转个人画像 |

### 3.2 页面跳转流程

```
[登录成功 / 点击顶栏「工作台」] → [工作台首页]
    ├── 点击态势区跑批状态卡 → [评测运营中心页（F6）AI 使用能力 tab]
    ├── 点击待处理区告警统计卡 → [评测运营中心页（F6）]
    ├── 点击待处理区逾期统计卡 → [评测运营中心页（F7）测试任务 tab，携已逾期状态筛选]
    ├── 点击演进区未使用人数卡 → [人员画像列表页（F9），仅看未使用开关开启]
    ├── 点击画像区共性短板标签 → [人员画像列表页（F9），短板维度筛选预填]
    ├── 点击画像区「查看完整团队看板」 → [团队看板页（F10）]
    ├── 点击关注表行「查看画像」 → [个人画像详情页（F9），携人员标识]
    └── 点击关注表「查看全员画像」 → [人员画像列表页（F9）]
```

**流程说明：**

1. 运营人员登录成功后默认落地工作台首页，页面加载四个区块的数据。
2. 需要跟进跑批或处置告警时，点击对应统计卡跳转评测运营中心。
3. 需要处置逾期测试任务时，点击逾期统计卡携已逾期筛选直达任务列表。
4. 需要深入团队分析时，经画像区入口进入团队看板；需要定位短板或未使用人群时，经短板标签与未使用人数卡携筛选进入人员画像列表；需要逐人处置时，经关注表或全员入口进入个人画像。

## 4. 页面功能详细说明

### 4.1 页面 1：工作台首页

#### 4.1.1 页面概述

**页面形式：**参见第3.1节页面清单

**页面职责：**登录后的总览入口与待办中枢。自上而下依次为态势与待处理统计卡区（跑批态势 + 告警/逾期计数 + 数据更新时间）、团队能力演进区（两模块综合分近 8 期折线 + 四张环比关键数卡）、本期团队整体画像速览区（双模块雷达 + 九型构成 + 共性短板标签 + 研判摘要）、需要关注的人（至多 10 行表格）。固定展示本期（最新落库区间），不设区间切换；历史趋势经团队看板与能力逐期趋势页消费。

#### 4.1.2 涉及字段

> 工作台为纯只读展示页，无输入与数据写入，无查询字段，字段校验不适用（依据：全部区块为聚合数据只读消费，跳转条件由点击行为承载）。

#### 4.1.4 业务规则

- **规则1：固定本期口径**
  - 规则描述：工作台全部区块按最新落库区间取数，不提供评估区间切换；历史区间趋势经团队看板区间切换与能力逐期趋势页消费。
  - 触发条件：页面加载。
  - 约束说明：「最新落库区间」以聚合数据实际落库行为准推导，不按周期配置推算，口径同 F10 区间下拉。

- **规则2：告警计数口径**
  - 规则描述：告警次数为 0/1 布尔计数：最新落库区间内存在任一告警信号记录（每批次至多一条，见 F6 §5.2.4 规则4）即计 1，否则计 0；区间内多条批次（如定时批次告警后手动补跑成功）不清零、不累计，恒为 1。
  - 触发条件：页面加载。
  - 约束说明：口径为「本期是否有未处置的失败超阈告警」的存在性判定，取最新落库区间全部批次的信号记录整体判定；告警的核查与补跑决策跳评测运营中心完成。

- **规则3：需关注人群口径与排序**
  - 规则描述：短板人群 = 本期 AI 使用能力或 AI 管理能力任一模块总分 < 60（F9 待提升等级线，总分取整后判定）的人，按两模块最低总分升序取前 5；未使用人群 = 本期未使用（口径同 F10 未使用）的人，按最近活跃距今天数降序取前 5；两类合并为至多 10 行表格，短板人群在前。
  - 触发条件：页面加载。
  - 约束说明：两类各自至多 5 人、不跨类补足，合计不足 10 行时按实际人数列出。最近活跃距今天数 = 本期区间终点与该人最近一条非未使用（活跃/低频）activity_stats 行周期终点之差；无任何统计行者自首个落库区间的起点起算。未使用人群无评分数据，两模块总分列显示待评估；短板人群与未使用人群按口径天然互斥（未使用者无聚合行）。

- **规则4：空态引导**
  - 规则描述：系统尚无任何落库批次时：态势区显示「尚未发起评估」提示与跳评测运营中心的引导入口；能力演进区、画像速览区显示暂无数据提示；关注表格显示空态。运行配置未就绪的场景经系统状态页排查，工作台不做配置提示。
  - 触发条件：无批次记录或无聚合数据时按区块分别判定。
  - 约束说明：各区块独立空态，不因单一区块无数据阻断整页渲染。

- **规则5：研判与短板数据源**
  - 规则描述：画像速览区的共性短板标签与研判摘要直接复用 F10 团队看板同源数据（共性短板判定规则、team_training_suggestions 最新建议行），工作台不新建生成逻辑、不落库。
  - 触发条件：页面加载。
  - 约束说明：尚无建议行（首批跑批后生成任务未完成或失败）时研判摘要区显示暂无数据，不阻断短板标签展示。

#### 4.1.5 交互逻辑

- 环比方向色：模块综合分上升与活跃率上升为正向色，未使用人数减少为正向色，反之负向色；无上一区间数据时环比区段不显示。
- 关注表格无数据行填充：两类人群合并展示，活跃度标签沿用 F9 列表页标签形态（Badge：未使用中性弱化，活跃/低频同基础样式）。
- 图表悬浮：折线与雷达悬浮显示区间与分值明细，同 F10 交互。

#### 4.1.6 权限要求

参见第2.2节页面访问权限，本页面无特殊权限规则。

## 5. 非页面功能详细说明

### 5.1 工作台聚合数据接口

#### 5.1.1 功能概述

**触发方式：**API 调用（工作台首页加载）
**触发时机：**进入工作台首页
**功能职责：**一个只读聚合接口，一次返回工作台全量数据：最新区间批次态势（状态、下次跑批时点、数据更新时间）、告警与逾期计数、两模块近 8 期综合分序列与环比、活跃率与未使用计数、双模块维度均分、九型快照、共性短板、研判摘要、需要关注的人清单（至多 10 人）。聚合实时计算不落库。

#### 5.1.2 处理流程

1. 接收工作台加载请求（JWT 鉴权）。
2. 查询最新落库区间及其批次记录，推导批次状态、数据更新时间与告警信号存在性计数（0/1，口径见 4.1.4 规则2）。
3. 汇聚近 8 期两模块维度均分与综合分序列、活跃度三态计数、九型快照、共性短板与最新研判行。
4. 按规则 3 口径计算需要关注的人清单（至多 10 人）。
5. 组装返回，雪花 ID 字段以字符串传输。

#### 5.1.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 批次记录与告警信号 | assessment_batches / 告警信号表（F6 已建） | 态势卡与告警计数 | 终态批次取最新终态批次口径同 F6 |
| 测试任务 | 测试任务表（F7 已建） | 逾期计数 | 已逾期状态计数 |
| 聚合数据 | activity_stats / dimension_scores / aggregate_scores（F6/T5 已建） | 综合分、活跃率、维度均分、关注人群 | 近 8 期序列实时计算 |
| 九型快照与培训建议 | 九型快照 / team_training_suggestions（F10 已建或复用其聚合口径） | 九型构成与研判摘要 | 研判取最新建议行 |
| 全员名单 | userapi 客户端（上游集成） | 活跃率分母与关注人群姓名 | 实时拉取 |

查询失败的异常兜底由 5.1.4 规则2 与 5.1.5 异常处理表统一覆盖：上表任一数据源查询失败时对应区块返回空标记，接口整体不因单源失败失败。

#### 5.1.4 业务规则

- **规则1：**接口为纯只读聚合，无写入行为；聚合口径与 F10 看板接口共用的部分保持同源计算，避免两套口径。
- **规则2：**上游任一数据源查询失败时对应区块返回空标记，接口整体不因单源失败失败（空态引导按区块呈现）。

#### 5.1.5 异常处理

| 异常场景 | 处理方式 | 错误提示/日志 |
|---------|---------|--------------|
| 全员名单拉取失败 | 活跃率与关注人群区块返回空标记 | ERROR 日志记上游错误码 |
| 聚合数据查询失败 | 对应区块返回空标记 | ERROR 日志 |

#### 5.1.6 与其他功能的关联

- **上游依赖：**F6 批次与告警信号、F7 测试任务、T5 聚合三表、F10 九型快照与培训建议、userapi 名单。
- **下游影响：**无（终端消费页）。
