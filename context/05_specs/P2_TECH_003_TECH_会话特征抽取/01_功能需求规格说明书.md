# 技术组件规格说明书

## 1. 概述

### 1.1 组件名称

会话特征抽取（SessionFeatureExtractor）

### 1.2 组件描述

逐会话读入 AI 编程助手原始对话全文，裁剪框架注入噪音后压缩成结构化会话特征档案（统计数字、内容摘要、用户指令片段、行为特征四块 JSON），供跨会话综合评估消费，本组件只抽取不评分。

### 1.3 创建背景

系统需要把兄弟系统 sili-smart-api（LLM 网关）沉淀的 AI 对话日志周期性转化为人员能力画像。上游对话日志是 Claude Code 类 AI 编程助手会话：消息中框架注入（system-reminder 包裹的 CLAUDE.md / AGENTS.md、技能文档、agent 类型清单、文件全文回显、total_tokens 遥测）占绝对多数，真实用户原话每会话仅数条；tool_use/tool_result 在网关侧已脱敏为"工具名 args=N / result=N"长度元数据。直接把原始对话喂给下游评估既浪费 token 又稀释有效信号，必须先经本组件裁剪压缩成脱敏特征档案。



### 1.4 技术栈

| 技术 | 版本 | 用途 |
|------|------|------|
| Go | 1.25 | 实现语言，与 hr-backend 一致 |
| Gin | v1 | 无自有 HTTP 接口，仅运行于进程内供 worker 调度 |
| GORM | v2 | 特征档案落库（TEXT 列存序列化 JSON，多库兼容） |
| Asynq | - | 异步任务承载，抽取任务由 worker 调度触发 |
| LLM 调用底座（P2_TECH_001） | - | 压缩对话调用的唯一通道，排他启用唯一模型 |
| 会话日志集成（P2_TECH_002） | - | 会话列表与详情的唯一拉取通道 |

## 2. 组件接口

### 2.1 能力清单

| 序号 | 能力名称 | 能力类型 | 说明 |
|------|---------|---------|------|
| 1 | 会话裁剪 | 基础 | 按注入三分类规则清洗原始 messages（框架噪音丢弃、规约提取指纹、正文保留），产出喂 LLM 的裁剪视图（纯规则，不调 LLM） |
| 2 | 特征抽取 | 基础 | 裁剪视图喂 LLM 产三块（摘要/指令片段/行为特征），统计块由规则并入，合成四块档案 |
| 3 | 档案落库 | 基础 | 特征档案按 session_key 幂等持久化（success/failed 状态），成功即跳过，失败降级保留统计 |
| 4 | 短会话过滤 | 基础 | 抽取前置判定（唯一权威规则见 2.4 能力4）：真实用户消息数为零且保留类消息 < MinKeptMessages 的零输入空壳会话，或非零但 < MinUserMessages（阈值调高后激活）的会话跳过抽取，仅留元数据计数；内容判据放行后统一复核零响应（无 AI 叙述无工具证据即跳过）（turn_count 无残缺判定力，不作过滤条件） |
| 5 | 指令脱敏 | 基础 | 指令片段入库前剥离文件绝对路径、密钥、内网地址等敏感串 |
| 6 | 批量抽取编排入口 | 高级 | 供 worker 逐会话调用的单会话抽取入口（拉详情在 P2_TECH_002，跑批编排在后续 pipeline feature） |

> **能力类型说明**：基础=核心必需能力 | 高级=增强型能力 | 扩展=可选能力

```go
}
```

### 2.3 输出定义

#### Events / 返回值

| 事件名/方法名 | 参数 | 返回值 | 说明 |
|--------------|------|--------|------|
| Extract | SessionKey, Detail, TokenName | (*ExtractionResult, error) | 单会话抽取：过滤判定、裁剪、LLM 调用、落库一次完成（详情由调用方拉取传入） |
| ExtractByKey | SessionKey, TokenName | (*ExtractionResult, error) | worker 主路径：组件内部经 P2_TECH_002 拉详情后执行 Extract 全流程（能力6） |
| Trim | Detail | (TrimmedView, TrimStats) | 只跑裁剪不调 LLM 不落库，供调试与测试 |
| ShouldSkip | Detail | (bool, SkipReason) | 短会话过滤判定，纯规则 |

> 概念签名省略 ctx context.Context，实际签名以 2.4 各能力接口定义为准。Extract/ExtractByKey 的 ctx 超时预算 ≥ 550s（最坏情形叠加：详情拉取 190s（30s × 4 次执行 + 退避 10s+20s+40s）+ LLM 段 360s（底座装配 MaxRetries=1 且 MaxRetryAfter=60s：429 带 Retry-After 时单次 callOnce 最坏 60s 超时 + 60s 退避 + 60s 重试超时 = 180s，schema 校验失败后的一次组件级重试共 2 次完整调用）；此前的 440s 口径按 5s 指数退避推导、未计入 Retry-After 封顶 60s，已修订），由底座承载，Asynq 任务侧不再叠加更短超时；6.2 extract_duration 的 p99 > 120s 观测线是单会话抽取耗时的观测阈值（正常路径 LLM 主导 ≤ 60s 级），与 550s 预算上限是观测线与预算线两个口径。

```go
// ExtractionResult 是抽取结果。
type ExtractionResult struct {
    Skipped    bool            // true 表示被短会话过滤跳过，无档案产出
    SkipReason string          // 跳过原因（min_user_messages / empty_shell / detail_invalid / session_not_found。
                              // session_not_found 属终态化补充 reason：上游已删除会话的残留 failed 行翻 skipped 时使用）
    Profile    *FeatureProfile // 非 nil 时为本次产出的档案
    Reused     bool            // true 表示命中既有行复用未调 LLM：success 行复用（成功即跳过）与
                              // skipped 行终态复用（不重拉不重判）两种形态，Status 如实回传行状态
    Status     string          // success / failed / skipped，落库状态；Reused=true 时如实回传既有行状态
                              //（success 行复用回 success，skipped 行终态复用回 skipped）；业务空
                              //（ErrNotFound 不落行）为空串，空串不属三态值域（无行状态可回传），
                              // 消费方判业务空以 Skipped=false 且 Reused=false 且 Profile=nil 组合识别
}

// TrimmedView 是裁剪视图（喂 LLM 的中间产物，仅内存临时持有）。
// 行格式约定：每行以方括号标签前缀打头，四类标签 [USER]/[AI]/[TOOL]/[EVENT]，
// 标签后接单空格再接内容；多行内容（用户粘贴、assistant 长叙述）首行打标签、
// 后续行原样缩进跟随，不做转义。喂 LLM 用纯文本行而非 JSON：粘贴代码/日志
// 转义失真最伤证据保真，且逐消息 JSON 包裹的结构开销与压缩目标相悖。
type TrimmedView struct {
    Lines     []string // 逐行视图：指令、assistant 叙述、工具摘要、事件标记
    CharCount int      // 裁剪后字符数
}

// TrimStats 是裁剪统计（诊断与监控用，不落库）。
type TrimStats struct {
    TotalMessages   int // 原始消息数
```

#### 错误码定义

| 错误码 | 说明 | 处理建议 |
|--------|------|---------|
| ErrLLMUpstream | LLM 调用失败（底座重试耗尽，含超时/排队满/限流类瞬时错误的耗尽态） | 降级落 failed 档案行（统计块与 error_code），当期评估照常推进，补跑时重抽 |
| ErrDetailFetch | 详情拉取确定性失败（鉴权失效/参数非法/信封契约破坏/部署配置缺失（ErrNotConfigured）/兜底状态桶（ErrUnexpectedStatus，不含 429），对应 P2_TECH_002 的确定性错误全集） | 落 failed 档案行终态化（Stats 零值与 error_code），不交任务重试（重试恒失败烧预算）；密钥修复后补跑可重抽翻转；既有 failed 行元数据（turn_count 与时间列）复用原值，防覆写为 epoch 对时间窗查询永久不可见；首次落行（库内无既有行）无元数据可复用，turn_count 落 0、时间列落 epoch（time.Unix(0,0)，NOT NULL 列不可空），行经补跑成功翻转后由 detail 元数据覆盖，epoch 行为窗口查询不可见属已知取舍（该场景行状态为 failed 终态，T5 按人取数以 status 分布识别人群，时间窗筛选漏过 epoch 行影响限于该行自身）。网络、超时、5xx 与 429 限流（ErrRateLimited，瞬时错误）类瞬时错误仍走 error 通道交 Asynq 重试 |
| ErrSchemaInvalid | LLM 输出未通过档案 schema 校验 | 重试一次仍失败降级落 failed 档案行（统计块与 error_code），补跑时重抽 |
| ErrContextLengthExceeded | 底座 token 预算预检失败（用户输入自身超 LLM 单次上限的极端粘贴场景，见能力1 注意事项） | 降级落 failed 档案行（统计块与 error_code），与 ErrLLMUpstream 在 error_code 可区分（超限属会话内容规模问题，重抽同样超限，补跑价值低；区分后观测可分别统计） |
| ErrNotFound | 会话记录不存在（上游业务空，IsNotFound 白名单识别） | 业务空处理：不落档案行，记 INFO 日志返回（Result 三字段全空值态：Skipped=false、Reused=false、Status=空串、Profile=nil） |
| ErrDetailInvalid | 详情缺 session 或 messages 为空 | 跳过该会话并记日志；落 skipped 元数据行（SkipReason 记 detail_invalid，终态不重拉，见 2.4 能力3），避免补跑时反复重拉同一批无效会话 |
| ErrEmptyShell | 裁剪后真实用户输入为 0 且保留类消息 < MinKeptMessages 的空壳会话 | 落 skipped 元数据行（SkipReason 记 empty_shell，终态不重判，见 2.4 能力3），不消耗 LLM 调用 |
| ErrStoreWrite | 档案落库失败 | 不落任何档案行，交 Asynq 任务级重试（任务返回 err）；重试耗尽本周期该会话无档案行，属 extract_fail_ratio 分子的已知漏计项（观测替代见 6.2），持续落库故障经 ERROR 日志计数暴露 |

ErrNotFound 的业务空口径见上表，与会话级失败（落 failed 行）的区分是其唯一增量。

**判定优先级（唯一权威定义）**，按序判定、命中即止：

0. 判定范围：三分类判定只作用于 text 类消息；tool_use/tool_result 元数据行无条件走第三类保留，不参与前缀匹配与内容分流（OMO 黑名单含 `Read `/`Write `/`Edit `/`Grep `/`PowerShell `/`TodoWrite ` 前缀，与工具元数据行 `Read args=111`、`TodoWrite 4 items` 的 text 前缀空间重叠，若把黑名单误应用到 tool_use 行会整类误杀工具证据，ToolCounts 失真）；transcript 重放区段内同样只有 tool_use/tool_result 行例外保留（历史会话转储的工具行仍属工具证据，按第三类无条件保留口径执行），其余区段内消息整块剥离。text/tool_use/tool_result 外的未知 Kind（上游网关演进新增值，实测当前值域仅此三值）：视同 text 进判定链按 role 兜底处置，防整类消息静默丢失；上游若新增携带大段转储的 Kind（如 thinking 推理全文），经参数页增补前缀或本条扩展显式收敛，防挤占视图预算
1. 内容语义白名单：指纹/噪音分流，含 command-args 提取通道（该通道以 `<command-args>` 标签存在性触发，先于黑名单判定）与 system 插话转述提取（先于黑名单：提取类优先于丢弃类，运维增补前缀撞插话 marker 时转述指令仍保全，specs 裁定）
2. 前缀黑名单（InjectPrefixes）。角色口径（specs 裁定）：黑名单对 user 角色全集生效；对非 user 角色收窄为模型生成物重放与 assistant 侧裁决产物子集（`<analysis>`、This session is being continued、`<block>`、`User: ` 转述前缀），OMO 工具转写家族与提示词碎片家族前缀仅限定 user/text 转储形态，对 assistant 叙述的前缀碰撞属误杀面（实测形态：assistant 真实短叙述 Read clearTaskRouteLayers. 被 Read 前缀整条误杀，唯一叙述的零工具会话会误落 empty_shell 终态不可逆）。收窄对经参数页配置的黑名单集合同样生效：非 user 角色按「配置集与收窄子集的交集」判定，运维为拦 user 侧新转储形态增补的前缀不会连带应用到 assistant 叙述，运维删除交集内条目（如 User: ）对 assistant 照常放开（配置集是 user 侧全集语义，条目级角色归属无法在参数页表达，子集交是防误杀底线）

前文各形态描述均按此链解读，InjectPrefixes 注释与本条同集合两视图，冲突时以本条为准。

system 角色的兜底规则：system/text 未命中任何已知语义（遥测、agent 类型清单（Available agent types 开头，经 system 兜底隐性覆盖丢弃）、插话转述、打断、Note: 开头的文件回显混排、The following skills are available 开头的技能清单、[SYSTEM NOTIFICATION 通知、TodoWrite 与 task tools 提醒、You are a title generator 标题生成提示）时按框架噪音丢弃。理由：system 通道承载的几乎全部是框架注入而非人类内容，且存在 60k+ 字符的混排巨型消息，保留进视图会挤占预算且无评估信号；上游若演进新增有价值的 system 语义，经参数页增补前缀放开。

规约指纹的设计动机：上层 4 维中 Skill 编写能力、知识沉淀与复用、Harness 编排驾驭三个维度依赖规约类证据，但同一人的 CLAUDE.md / AGENTS.md 会注入其几乎每个会话（单会话可达 9.8k 字符 CLAUDE.md 加 14.6k 技能文档），逐会话喂全文重复且昂贵。指纹方案保留信号：

1. 哈希跨会话变化即规约迭代证据（剥离日期段后哈希仅随规约正文实质修改变化）
2. 章节标题列表即结构质量证据
3. 单会话成本仅增几十字符

**接口定义**:
```go
// Trim 执行裁剪，纯函数不落库。
func (e *Extractor) Trim(detail *conversationlog.SessionDetail) (TrimmedView, TrimStats)
```

**调用示例**:
```go
view, stats := ext.Trim(detail)
slog.Debug("trim done", "kept", stats.KeptMessages, "chars", view.CharCount)
```

**注意事项**:
- 注入前缀黑名单经系统参数可配（键与出厂默认见 2.2 InjectPrefixes 注释），运维参数页增删，应对上游注入形态演进
- 黑名单匹配用前缀匹配，大小写敏感
- 用户真实输入无条件全文进裁剪视图，任何截断逻辑不得作用于用户输入（含日志/代码粘贴）；PasteCharCount 仅统计其规模
- 超预算截断只作用于 assistant 叙述与工具摘要（先短播报、再工具摘要、assistant 长叙述最后）；用户输入自身超 LLM 单次上限的极端粘贴场景不截断，走底座 token 预算预检失败进 failed 降级
- continuation 摘要（This session is being continued 开头）整块丢弃，其任务上下文价值由后续评估阶段按需回收，本期不保留
- 规约指纹的哈希用 SHA-256 前 16 位，计算前剥离 currentDate 日期段（按 `# currentDate` 标题切分），指纹本身脱敏（章节标题过 Redact）后落库，规约全文同样只在内存临时持有

#### 能力2: 特征抽取

**描述**: 两段合成四块档案。

第一段规则：裁剪阶段同步计算统计数字块 ProfileStats（轮次、真实用户消息数、打断次数、时长、裁剪字符数、按工具名计数、turn_kind 分布、续接标记、粘贴规模、规约指纹清单、指令规范化哈希），确定性数据不走 LLM。

第二段 LLM：裁剪视图组装 prompt（含档案 JSON schema 约束），经 LLM 调用底座调用当前排他启用模型，产出三块：

1. 内容摘要：工作域与技术栈归纳、任务价值信号
2. 用户指令片段：真实输入的代表性摘录，已脱敏
3. 行为特征：指令具体度、打断频率、审查把关类话语占比、粘贴日志/代码供分析的规模

prompt 除裁剪视图外附带统计参考块（实现回写收编）：真实用户消息数、打断次数、粘贴字符规模、轮次数四项确定性数字（规则产出，喂入供行为信号判定作量化依据，如 paste_scale 与 interrupt_style 的分档参考；视图内不含计数信息，缺该块时行为信号判定退回纯文本推断）。TokenName 剥离后组装（注意事项），统计数字不含人名。

两段合并为完整档案；LLM 段失败时统计块单独落库（见能力3 降级）。

**零真实用户输入会话**（continuation 续接推进会话等，见能力4 放行组）的 LLM 段行为：prompt 模板明确指示裁剪视图无 [USER] 标签行时 Instruction 输出空数组、禁止编造指令，行为特征中的指令具体度等指令类信号标记无证据；schema 校验放行空 Instruction 数组。防绕漏披露：compaction 压缩输出已按噪音丢弃（形态16），若上游演进出现新的模型生成物重放形态走 assistant 兜底进视图，其内嵌的历史指令引文会诱导 LLM 违规填充 Instruction，schema 无法区分引文与当会话指令，靠形态前缀收录兜底。此类会话的 Summary 与 Behavior 照常产出（工作内容从工具摘要与 assistant 叙述可见）。信号特征披露：该人群（长任务续接推进型，多为重度用户）的 UserMsgCount 系统性偏低，指令类证据密度天然稀薄，T5 综合评估设计评分 prompt 时须把 UserMsgCount 作为指令类维度评分的证据充足性参考，避免把证据稀薄误判为指令能力低下。

**零 assistant 叙述会话**（纯工具推进型，实测真实数据中大量存在：计划模式与续接推进会话的 assistant 侧可全部为 tool_use 元数据行，无一字叙述）的 LLM 段行为：prompt 模板明确指示裁剪视图无 [AI] 标签行时，Summary 依据 [TOOL] 工具摘要行（工具名与参数规模）归纳工作域与技术栈，并在 Behavior 中标记叙述缺失（narrative_absent）信号；审查把关类话语占比、指令具体度等以叙述或指令为分母的信号一律标记无证据，禁止输出数值。schema 校验放行 narrative_absent 标记形态。[AI] 行的判定前提是 compaction 压缩输出（形态16）已剥离：该输出是回顾重放非本会话叙述，漏剥离会让纯工具会话被误判为有叙述，掩蔽 narrative_absent 信号（实测：48 消息会话唯一 assistant 叙述即 16.5k 回顾）。信号特征披露：该人群的 Summary 可信度天然降级（证据粒度仅达工具名级别），T5 综合评估设计评分 prompt 时须对 narrative_absent 会话的价值产出与审查把关维度作证据降权，避免把叙述缺失误判为产出质量低下。

**零响应会话**（单侧投喂型：裁剪视图无 [AI] 标签行且无 [TOOL] 标签行，即零 AI 叙述零工具证据，会话只有用户侧输入未被回应）的 LLM 段行为：调 LLM 无工作证据可归纳，三块输出必然编造（实测：自动化客户端的提示词碎片会话即此形态，抽样 20 条零回复零工具，若放行 LLM 只能从提示词碎片编造 Summary/Instruction/Behavior）。处理规则：按空壳会话跳过，SkipReason 记 empty_shell，落 skipped 元数据行终态（见能力3），不消耗 LLM 调用。该防线与前缀黑名单双防线：黑名单拦已知碎片前缀（见 2.2 InjectPrefixes 与 2.4 能力1 形态15），零响应判定拦黑名单外的新碎片形态与单侧投喂会话（如用户粘贴文档后中断），前者管识别、后者管兜底。信号特征披露：真实用户单侧投喂后中断的会话同样被此规则跳过，其指令文本证据一并丢失，属可接受损失（无 AI 交互的输入对使用能力评估无信号价值，仅有活跃度计数价值，活跃度走列表口径不受影响）。

摘要与片段的长度约束（200 字级）由下游预算反推：T5 evaluator 每人周期一次、全部档案一次性喂入，活跃人员周会话量可达数十个，单档案文本块须压在千字符级才能保证档案集不挤爆 evaluator 输入。

**约束的承载与执行机制**：长度要求直接写在 prompt 模板文本内（如"摘要 200 字以内、片段每条不超 200 字"），模板是包内字符串常量，随模板版本化，不设独立命名常量；校验逻辑引用模板约定的同一字面值，避免魔法数字散落。执行机制分两档：

1. 摘要禁止机械截断。摘要是 LLM 生成物，结论性信息集中在句尾，按字符硬切会切断关键判断，且隐私架构下原文抽取后即丢弃，截断造成的信息损失不可恢复，直接影响价值产出质量与任务适配判断力两个维度的评分依据。正确做法是生成侧控制：字数要求写进 prompt 由 LLM 自行写短，落库前只做宽容校验（超约定上限 2 倍判 schema 失败，走既有重试路径重新生成）
2. 指令片段是摘录引用，LLM 生成时即遵守单条上限，兜底截断也只在句读边界（标点或换行）执行并加省略标记，禁止词中硬切；连续无句读无空白的无界串（长 URL、base64）属规格外极端形态，按上限硬切兜底（无边界可落时截词是最后防线）

约束调整走 prompt 模板的代码变更发版。

**注意事项**:
- TokenName 剥离后才组装 prompt，人员归属在落库时回填，防止人名进 LLM 上下文
- 用户真实输入进裁剪视图前过 RedactPatterns 输入侧脱敏（正则集同能力5），防止用户指令携带的密钥/内网地址进 LLM 上下文（3.3 安全表：敏感串不进 LLM 上下文）；assistant 叙述与工具元数据行进视图时同口径脱敏（复述与回显是敏感串进视图的次级通道）；PasteCharCount 按脱敏前原文长度计，指令规范化哈希按脱敏后文本计算
- LLM 输出必须通过 schema 校验才落库（含摘要超 prompt 约定上限 2 倍判失败），校验失败重试一次。解析前置宽容处理（实现回写收编）：LLM 输出剥 markdown 围栏包裹（```json ... ```，防主流模型默认围栏输出整类误判 schema 失败）；剥后仍非法时截取首个含 summary 键的顶层平衡 JSON 对象重试解析一次（兜底 JSON 后跟解释文字、前导说明含示例对象的形态；候选须含 summary 键，防示例对象劫持）。两档宽容后仍非法才判 ErrSchemaInvalid 走重试
- 统计块的 CmdReuseHashes 用指令规范化哈希（去空白、去路径后 SHA-256 前 16 位），跨会话命中即知识沉淀维度的复用证据；零真实输入会话该清单为空数组。复用证据的重复会话污染披露：实测存在同人同首指令的重复会话（70 会话抽样 13 组分钟级重试；另实测同人同一工作流的 3 份重做副本间隔数十分钟至小时级、统计信号完全一致），哈希无法区分复用与重试/重做。本组件不做去重（会话粒度的上游事实），T5 综合评估设计评分 prompt 时须对同人同首指令哈希命中一律按重做降权（不设间隔条件：分钟级重试与跨小时重做同源，间隔窗口条件会让小时级副本绕过降权被三重计数），不作为知识沉淀复用证据计分
- 成本参考因子口径：PRD 要求 token 数、轮数、用时喂入所有维度评估。部分会话消息内含 `<total_tokens>N tokens left</total_tokens>` 遥测（system 角色，多为独立消息，偶与其他注入混排），但其语义是按人配额池余量倒计时而非本会话消耗：不同人同时刻余量各异（池按人隔离）、同人跨会话余量会回升（配额重置）、同人并发会话共享同一池导致差值无法归因单会话，且有无遥测随上游模型路由而异。据此遥测不作 token 来源，维持裁剪字符数近似，轮数用时取实值
- 粘贴信号聚集披露：PasteCharCount 可被单一事件主导。实测两类形态：@CurrentContext 转储可占会话粘贴量的九成（编排工具每次请求注入约 1.1k 字符场景树，真实指令仅数条短句），同会话内同构 JSON 粘贴重复出现（同一图表数据以坐标微差形态粘贴多次，每次全额计数）。信号特征：背景约束供给子信号对重度编排工具/图表协作人群系统性偏高。反向偏差披露：语音输入人群（指令为语音转文本口语体，实测多段口语长文消息，句读换行无技术特征串）在多行即计粘贴的旧口径下会系统性误计，2.2 判据已补口语体排除（多行但无围栏/堆栈/路径特征不计），残余误差为含技术特征串的语音消息误计（无法区分手打与转写，属可接受近似）。T5 设计评分 prompt 时须把 PasteCharCount 与 UserMsgCount、粘贴消息条数联合判读，避免把单次任务的重复上下文供给误读为持续的高约束供给习惯，也避免把语音人群按新口径的残余粘贴量误读为主动供给背景约束的证据；Instruction 摘录方面 prompt 已指示摘录真实输入代表性片段，转储类长文本不应进摘录（LLM 生成侧约束）
- 对话原文与裁剪视图仅在内存临时持有，禁止写日志、缓存与数据库（隐私架构）
- 会话内回顾输出披露（实测 18 会话 2 例，均为续接推进会话）：模型在会话内直接输出长篇工作回顾（形态如 `# 会话详细摘要`、Feature 状态结构化摘要开头，数千字符），无 CRITICAL 压缩请求配对、无 `<analysis>` 包裹，走 assistant 兜底保留进视图。其内嵌的当会话需求归纳与历史指令引文对 Instruction 摘录的诱导与 compaction 输出同构，但无前缀特征可拦（属正常 assistant 叙述形态，不可按内容语义拦截）。T5 综合评估设计评分 prompt 时须知悉：续接推进会话的 [AI] 行中混有回顾文本，价值产出与指令类维度的证据判读须与 continuation 标记联合识别，防止上一会话遗留指令被双重计数
- tool_use/tool_result 元数据行的 N（args=N / result=N）为字符数口径（上游网关脱敏产物，实测样本 `Edit args=2055`、`tool_result result=223` 与字符长度同量级）；该类行的工作域归纳粒度仅达工具名级别，能力2 的 narrative_absent 披露（见上方零叙述会话段）同步界定其证据边界，供 T5 设计评分 prompt 时知悉

#### 能力4: 短会话过滤

**描述**: 抽取前置判定，判据全部取裁剪结果，turn_count 不参与（turn_count=1 会话可含真实用户输入与数十条工具调用，单请求内可完成子代理/IDE 驱动的完整多轮交互，turn_count 是请求边界语义，对残缺会话无判定力）。

**判定规则（唯一权威定义，2.1 能力清单第 4 行按此解读）**，按序判定：

1. 裁剪后真实用户消息数 ≥ MinUserMessages：放行
2. 0 < UserMsgCount < MinUserMessages：跳过，SkipReason 记 min_user_messages（当前 MinUserMessages=1 时该区间为空，仅在阈值调高后激活）
3. UserMsgCount = 0 时看保留类消息（工具摘要、assistant 叙述、事件标记）合计：≥ MinKeptMessages 放行；否则为空壳会话跳过，SkipReason 记 empty_shell。实现口径（specs 裁定）：保留类合计取预算截断前计数，与第 4 条结构化信号的存在性取截断前口径同一裁决：预算截断是视图控制手段而非证据否定，empty_shell 是 skipped 终态（不重判）误判不可逆，截断丢几条 AI 叙述不应翻转零输入会话的证据判定
4. 零响应判定（内容判据放行后统一复核，覆盖第 1 条与第 3 条两个放行组）：裁剪视图无 AI 叙述且无工具证据（无 [AI] 行且无 [TOOL] 行，事件标记行 [EVENT] 不构成工作证据）时跳过，SkipReason 记 empty_shell，防单侧投喂会话与提示词碎片会话产出编造档案（防线分工见能力2 零响应会话段）。第 3 条放行组的保留类消息含事件标记，理论上存在纯事件行凑满 MinKeptMessages 的形态（10+ 独立打断标记零输入零响应），统一复核口径下同样落 empty_shell

单指令长任务（一次输入后 AI 自主推进数十轮）与 continuation 续接推进会话（续接摘要按注入丢弃后用户输入为零，但工具与叙述是有效工作证据）均由内容判据放行。

10. 提示词碎片转储家族（git 状态、提示词章节头与正文段切片（含 # Text output 与 When you have enough information to act）、memory 条目转储、user 角色 total_tokens 独立消息、count 探针，见 2.4 能力1 形态15；实测该家族让自动化客户端人群全部 20 条抽样会话以 UserMsgCount=1 误放行，第十四轮复核黑名单外新碎片形态由零响应判定兜底拦截）
11. compaction 摘要请求（CRITICAL: Respond with TEXT ONLY 开头的压缩摘要请求模板，见 2.4 能力1 形态16；实测 21 会话 6 条命中，该请求非人类输入）

被滤会话落 skipped 元数据行（session_key、turn_count、跳过原因；profile_json 空，完整口径见 2.3 档案表注释）。活跃度统计（T5 activity）按 PRD 是纯规则统计会话列表元数据，直接取列表口径（turn_count、轮次时间），消费方是列表聚合，读取上游列表而非本表；skipped 行仅作抽取侧留痕与失败比例统计的口径澄清（分母用周期会话总量，非档案表行数）。信号特征披露（T5 activity 消费侧须识别降权）：自动化客户端人群（签名：同人分钟级会话间隔且 tc=1 占比极高，实测 47 分钟 183 条会话）在列表口径下呈最高活跃度，其会话多为单侧投喂零响应形态，经零响应判定落 skipped 后能力维度证据趋零，但活跃度计数仍虚高；T5 activity 设计分级规则时须结合档案表 status 分布识别该人群，避免把自动化客户端误判为最活跃高能力用户。签名重合区分披露：工作型 tc=1 人群（实测单人 tc=1 占比可达六成）的列表签名与自动化客户端重合（分钟级间隔且 tc=1 占比高），但会话内是真实工作证据（多轮真实指令、打断标记、工具链、成果叙述），黑名单正常放行、档案正常产出（UserMsgCount 5 至 11 条，success 落库）；T5 降权签名命中后须先核档案表 status 分布再降权：档案多为 success 的 tc=1 人群是工作型变体（单请求内完成多轮交互，属正常工作形态，不降权），档案全 skipped 才是自动化客户端。旁路族群：编排工具（codegraph/WorkBuddy 类）重度用户的工作发生在父会话，上游把权限裁决+transcript 重放复合请求拆成独立旁路会话落库（实测单人本期 2/2 会话全为此形态，全部落 skip），该人群可整周期零有效档案而列表口径会话量正常（签名：档案全 skipped 而周期列表会话量正常），T5 按人取数时须与自动化客户端人群并列识别，避免误入数据不足降权或被误读为零能力（其真实能力证据在父会话，本系统不可见）。旁路族群另含空 model_name 会议整理子请求（钉钉听记类工具经网关落库的 2 消息形态，system 提示加 user 模板指令零响应，落 empty_shell 终态，实测近期占比约 12%，兼容口径见 3.2）：该形态散布于正常工作用户名下（本人另有大量 success 会话兜底），影响为档案集稀释而非整人归零，与编排工具旁路的整周期归零形态区分。边缘误杀整人归零形态：kept 7-9 会话可占单人本期全部会话（实测单人本期 2/2 会话均落 kept 9/7 的 skip，带真实工具链与成果叙述），签名（档案全 skipped 且列表会话量正常）与旁路族群重合，T5 须并列入识别，处置区分：该形态属 MinKeptMessages 阈值误杀（非旁路），运维侧经代码变更评估下调 MinKeptMessages 可恢复，T5 侧先按数据不足降权呈现并在画像标注阈值边界。

**接口定义**:
```go
// ShouldSkip 纯规则判定，不调 LLM 不落库。
func (e *Extractor) ShouldSkip(detail *conversationlog.SessionDetail) (bool, string)
```

**注意事项**:
- 过滤省流量的对象只是空壳会话：MinUserMessages=1 拦零真实输入且无实质证据的会话，MinKeptMessages=10 拦裁剪后近乎全空的会话。阈值若按输入数取 2 会误杀单指令长任务与会话续接型工作流，两类恰是高能力用户的典型交互
- 边缘区间误杀披露（T5 消费侧知悉）：kept 7 至 9 区间混有真实小型工作会话（实测：tc=1 续接收尾会话带 8 条工具调用与真实成果叙述，kept=9 差 1 落 empty_shell 终态，工具计数证据随 skipped 行空 profile_json 一并丢失）与压缩旁路小会话（跳过正确），当前无判据区分。本人级别通常有其他放行会话兜底，影响为可解释损失；若跑批数据显示续接人群 kept 7-9 命中率显著，经代码变更评估下调 MinKeptMessages
- 阈值为包内常量（MinUserMessages=1、MinKeptMessages=10），调整走代码变更发版

#### 能力5: 指令脱敏

**描述**: 指令片段入档案前执行正则脱敏：Windows 绝对路径（盘符开头）、Unix 绝对路径、密钥形态（sk- 前缀串）、内网地址（10.x/192.168.x/172.16-31.x）分别替换为占位符（[PATH]、[SECRET]、[ADDR]）。粘贴规模与行为特征中的规模类数字引用 PasteCharCount 统一口径（含 IDE 选中文本与 @CurrentContext 上下文转储，不含重放块，语音转文本口语体长文不计粘贴，粘贴判定近似规则见 2.2 字段注释）。

**接口定义**:
```go
// Redact 对文本执行脱敏，纯函数，正则集为包内常量 RedactPatterns。
func Redact(text string) string
```

**注意事项**:
- 脱敏发生在 LLM 输出之后、落库之前，保证主库只见脱敏档案
- 脱敏正则集经系统参数可配（键与默认值见 2.2 RedactPatterns 注释），运维参数页增删
- 内网地址正则为防版本号误判，前导/尾随排除类含 `.`（句点）：IP 后紧跟英文句点的形态（英文句末句点、点连写日志、`10.0.0.1.example.com` 域名形态）整段回溯穷尽后不命中，属已知漏拦盲区；逗号/空格/中文句读/冒号分隔的正常形态不受影响
- Windows 路径正则的带空格目录盲区：路径体排除空白，`C:\Program Files\Git\bin` 形态在中段空格处截断，`[PATH]` 占位符后泄漏 ` Files\Git\bin` 余段（明文进视图与 LLM 上下文）。取舍：空白入路径体会把「C:\logs done」的后随正文整段吞进占位符、相邻第二路径截残漏脱敏，宁漏拦不吞正文；Unix 路径同款取舍。运维可在参数页增补自定义正则补拦带空格路径
- 运维自定义正则若含捕获组（如带定界组形态），替换为兜底占位符 [REDACTED] 时整段匹配（含定界符）被吞且相邻第二目标可能漏拦，注入侧对含捕获组正则记 WARN 披露该风险

#### 能力6: 批量抽取编排入口

**描述**: 面向 worker 的单会话抽取入口封装：输入 session_key，组件内部经 P2_TECH_002 拉详情、执行 Extract 全流程。跑批的周期调度、逐人聚合、失败重试编排属后续 pipeline feature（T6），本能力只提供可被逐会话调度的原子单元。周期跑批（F6 周期批量评估）与手动定向分析（F6 选定对象时段）复用同一入口与同一套幂等规则：定向分析拉取范围内会话后，已有 success 档案复用、failed 行重抽（skipped 行为终态不重抽，见 2.4 能力3）、新增会话抽取。

**接口定义**:
```go
// ExtractByKey 按会话键执行全流程（拉详情 + 抽取）。
func (e *Extractor) ExtractByKey(ctx context.Context, sessionKey, tokenName string) (*ExtractionResult, error)
```

**注意事项**:
- 供 Asynq 任务 handler 调用，任务粒度为一会话一任务
- 并发度由 worker 配置承载，本组件自身不加锁
- 拉详情错误分流（specs 裁定）：业务空双通道（信封 success=false 走 IsNotFound 白名单、HTTP 404 走 ErrNotFound）不落行返回，残留 failed 行终态化为 skipped（reason 记 session_not_found，元数据列复用既有行原值）；确定性错误（ErrUnauthorized/ErrBadRequest/ErrDecode/ErrNotConfigured/ErrUnexpectedStatus，P2_TECH_002 自述确定性不重试全集，429 已单列 ErrRateLimited 归瞬时）落 failed 终态行（error_code 记 ErrDetailFetch），既有行元数据复用原值，不交任务重试；瞬时错误（网络/超时/5xx/429 限流）走 error 通道交 Asynq 重试
- LLM 段错误分流（specs 裁定）：底座重试耗尽后的全部错误（含超时/排队满/限流类瞬时错误的耗尽态）按 ErrLLMUpstream 降级落 failed 行，当期评估照常推进，补跑时重抽翻转；error 通道只留给 ctx 取消类基础设施错误
- 任务 handler 对坏格式/空字段 payload 返回 nil 丢弃任务记 ERROR（构造侧确定性错误，重试恒失败）

## 3. 技术约束

### 3.1 性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 裁剪耗时 | ≤ 50ms / 会话（500 消息内，超限按线性外推观测，无硬性拒绝） | 纯字符串与正则处理，单会话内存操作 |
| 抽取耗时 | ≤ 60s / 会话（单次 LLM 调用口径，正常路径） | 受 LLM 响应主导，含 schema 校验与一次重试的最坏路径由 2.3 的 440s ctx 预算承载 |
| 裁剪视图规模 | 非用户内容 ≤ MaxSessionTokens（24000 token，包内常量，1 token ≈ 3 字符折算 MaxSessionChars=72000 字符执行） | 用户真实输入无条件全文进视图，超预算只截 assistant 叙述与工具摘要（短播报先、工具摘要次、长叙述最后），用户输入超 LLM 上限走底座预检失败进 failed 降级 |
| 批次吞吐 | 由 worker 并发度承载 | 组件自身不加锁，一会话一任务 |
| 内存占用 | 原文与裁剪视图会话级临时持有 | 处理完成即释放，无跨会话缓存 |

| 列表分页并发重复页 | 实测并发多页列表请求返回完全相同的首页数据（并行 4 请求 p=1/40/120/250 同返 p=1 内容，串行带间隔后正常）。本组件按 session_key 幂等落库天然免疫重复页；T6 跑批翻页须串行或按 session_key 去重，避免重复拉取详情浪费预算 |
| 中文乱码 token_name（如尾字节损坏） | 原样透传做归属键，组件内不做修复 |

### 3.3 安全要求

| 安全项 | 要求 | 实现方式 |
|--------|------|---------|
| 对话原文不落库 | 原文与裁剪视图仅内存临时持有 | Extract 返回后引用即弃；日志只输出计数与 session_key，禁止输出消息文本 |
| 档案脱敏 | 主库只存脱敏特征档案 | LLM 产出的全部文本块落库前过 Redact 正则集（指令片段、内容摘要 Summary 均脱敏，防 LLM 从视图引文中复述明文） |
| 人名不进 LLM 上下文 | prompt 组装前剥离 TokenName | 落库时按 token_name 回填归属 |
| 敏感串不进 LLM 上下文 | 进裁剪视图的全部消息行过 RedactPatterns 输入侧脱敏（用户真实输入为主通道；assistant 叙述与工具元数据行同口径，防叙述复述密钥/回显路径把敏感串带入 LLM 上下文；实测存在把集成密钥与内网地址直接写进指令的会话，密钥出域到外部 LLM 是真实风险；输入侧与能力5 输出侧共用同一正则集，PasteCharCount 按原文长度计不受脱敏影响） | 视图文本（[USER]/[AI]/[TOOL] 行）与 LLM 产出的指令片段均只见 [PATH]/[SECRET]/[ADDR] 占位符 |
| 人员标识最小化 | 档案只存 token_name 归属字段 | 无工号（系统无工号约束），无 user_id 冗余（全库 user_id 恒为 1 无区分度） |

## 6. 监控与运维

### 6.1 日志规范

| 日志级别 | 使用场景 | 示例 |
|---------|---------|------|
| DEBUG | 裁剪统计、单会话抽取成功 | trim done key=... kept=12/165 chars=7200 |
| INFO | 批次内会话跳过、档案复用 | session skipped key=... reason=empty_shell |
| WARN | schema 校验失败触发重试、截断触发 | profile schema invalid, retrying key=... |
| ERROR | LLM 调用失败、落库失败 | extract failed key=... code=ErrLLMUpstream |

日志字段只含 session_key、token_name、计数与错误码，禁止输出消息原文与裁剪视图内容（隐私架构）。

### 6.2 监控指标

| 指标名称 | 指标类型 | 说明 | 告警阈值 |
|---------|---------|------|---------|
| extract_fail_ratio | 比率 | 单周期抽取失败率。口径披露：分子取本表 status=failed 计数，ErrStoreWrite 落库失败的会话无档案行（2.3 错误码表），漏计属已知口径；持续落库故障（如磁盘满）会让分子趋零而实际失败，ERROR 日志的 extract failed code=ErrStoreWrite 计数作辅助观测线 | ≥ 10% 触发工作台待处理告警（架构文档 2.2 引擎底座约定） |
| skip_ratio | 比率 | 短会话过滤占比 | 无告警，仅观测（基线待首轮跑批回填：内容判据口径下空壳会话与辅助旁路请求会话（标题生成、next-speaker classifier、action summarizer、WorkBuddy 续接等，见 2.4 能力1）的合计占比需跑批标定，原 turn_count<2 约 55% 的口径因误杀实质会话已废弃；抽样实测约 10%；实测自动化客户端人群提示词碎片会话单侧占近期会话约 37%，零响应判定与碎片前缀收录后该人群会话整体落入 skip，skip_ratio 显著抬升属预期而非黑名单失效，基线回填时须按人群拆分观测。待标定形态清单：Perform a web search for the query: 载荷（user 侧英文祈使句无 system 侧提示配对，单例样本暂按 role 兜底保留）、Bash 打头的 user/text 转写（OMO 家族成员但存在人类真输入歧义，实测样本中 Bash 转写与人工 Bash 指令并存，暂按 role 兜底保留，跑批数据足量后按 OMO 转写家族前缀原则处置）、用户想了解 开头的模板指令（编排工具生成的截图复刻类 prompt，user 侧中文模板句式（用户想了解 XX：...请在前端代码库 D:\... 形态），实测 70 会话抽样 8 会话命中约 11%，人触发但机器生成、指令具体度失真，暂按 role 兜底保留并披露给 T5（该人群指令设计维度证据须降权）），待标定形态的再标定触发口径：单周期全量会话数 ≥ 5000 或该形态命中 ≥ 50 条，两者取先到者）） |
| inject_residual_ratio | 比率 | 保留内容中注入消息的残留占比（按消息数，剔除用户输入与 assistant 叙述后的注入特征命中数 / 保留消息数） | 连续两周期抬升提示黑名单失效（口径剔除设计上无条件保全的用户粘贴与 AI 叙述，避免业务性高保留误报） |
| extract_duration | 延迟 | 单会话抽取耗时分布 | p99 > 120s 观测 |

### 6.3 告警规则

| 告警名称 | 触发条件 | 严重程度 | 处理建议 |
|---------|---------|---------|---------|
| 抽取失败率超阈 | 单周期 extract_fail_ratio ≥ 10% | 中 | 运营经工作台决定是否补跑，补跑复用手动定向分析入口 |
| 黑名单失效嫌疑 | inject_residual_ratio 连续两周期异常抬升 | 低 | 核对上游注入形态变更，参数页 extractor.inject_prefixes 增补 |

### 6.4 故障排查

#### 常见问题

**问题1: 档案质量骤降或摘要混入 CLAUDE.md 内容**
- 现象: 裁剪视图字符数异常大，摘要出现无关项目文本
- 原因: 上游注入形态变更，新前缀未命中黑名单
- 解决: 从上游拉一条实际详情，识别新注入前缀，参数页增补黑名单（键定义见 2.2 InjectPrefixes）。反向误杀同理：运维误增前缀导致保留类消息被丢弃（inject_residual_ratio 异常走低或真实用户消息数骤降）时，参数页删除该前缀回退，删除后按 role 兜底规则处理。指纹通道的复合消息内容分流失效（SectionList 出现业务文档标题、CharCount 异常抬高）时核对 2.4 能力1 的内容语义白名单是否覆盖新形态

**问题2: 大量会话被误过滤**
- 现象: skip_ratio 显著高于首轮跑批回填的基线
- 原因: 上游空壳会话占比抬升，或黑名单误杀（新增前缀命中保留类消息致真实用户消息数被压为 0，见 6.4 问题1 回退路径）
- 解决: 抽样核对被滤会话的真实用户消息数与 SkipReason 分布（min_user_messages 与 empty_shell 分开看），确属阈值过严再代码变更发版调整常量

**问题3: schema 校验连续失败**
- 现象: ErrSchemaInvalid 集中出现
- 原因: 启用模型的 JSON 输出能力弱或 prompt schema 约束退化
- 解决: 核对当前排他启用模型，必要时在大模型配置页切换模型后补跑失败清单

### 7.1 术语表

| 术语 | 说明 |
|------|------|
| 真实用户消息 / 真实用户输入 / 用户真实输入 | 同一概念的三种表述，均指 user/text 消息经三分类后归入保留类、计入 UserMsgCount 的人类输入（判定口径见 2.4 能力4） |
| 注入（injection） | AI 编程助手框架写入消息流的非人类内容，分框架噪音（agent 清单、遥测、文件回显、事件通知、辅助请求与重放、插件续跑指令）与规约类（CLAUDE.md、AGENTS.md、技能文档）两类，处理口径见 2.4 能力1 三分类 |
| 规约指纹（spec fingerprint） | 规约类注入的轻量摘要（类型、字符数、哈希、章节标题），为 Skill 编写、知识沉淀、Harness 编排维度供证，规约全文只在内存临时持有 |
| 裁剪视图（trimmed view） | 注入清洗后喂 LLM 的中间产物，仅内存临时持有 |
| 特征档案（feature profile） | 单会话的结构化压缩产物，四块 JSON（统计块规则产出，其余三块 LLM 产出），脱敏后落主库 |
| 短会话过滤 | 裁剪后真实用户消息数与保留类消息数不足阈值的空壳会话跳过抽取，落 skipped 元数据行（turn_count 无残缺判定力，不作过滤条件） |
| 降级保留统计 | LLM 段失败时仍落 failed 档案行（仅统计块与错误码），当期评估照常推进（PRD 异常处置） |
| total_tokens 遥测 | `<total_tokens>N tokens left</total_tokens>` 行，语义为按人配额池余量倒计时而非本会话消耗，不可作 token 计量来源，裁剪时按框架噪音丢弃（口径详见能力2 注意事项） |
| 提示词碎片转储 | 自动化客户端把系统提示词拆成独立 user/text 消息逐条注入的形态，零 AI 响应零工具调用，按框架噪音丢弃；黑名单外碎片由零响应判定兜底（见能力2 零响应会话段），防幽灵档案（前缀家族全集见 2.4 能力1 形态15） |
| 标题生成辅助请求 | 上游为生成会话标题发起的旁路请求（You are a title generator 系统提示 + 历史转述输入），产出仅为标题，无工作证据，整条会话按框架噪音处理（三种形态枚举见 2.4 能力1 形态4，含 kimi 路由变体） |
| 权限裁决旁路请求 | 框架发起的 stage-1 权限裁决请求（user 侧裁决提示 + assistant 侧 `<block>` 回复，两者均按框架噪音丢弃），无工作证据（形态细节见 2.4 能力1 形态8） |
| compaction 摘要对 | 上游上下文压缩旁路：请求（user 侧 CRITICAL: Respond with TEXT ONLY 开头）与输出（assistant 侧 `<analysis>` 开头，模型生成物重放）两前缀均按框架噪音丢弃（见 2.4 能力1 形态16） |
| transcript 重放 | 框架把历史对话转储给辅助模型的 user 消息序列，载荷须按自身前缀识别，重放块另经 `<transcript>` 区段整体剥离兜底（形态细节见 2.4 能力1 形态9），非本人当次输入，按框架噪音丢弃且不计入 PasteCharCount。实测常与权限裁决旁路复合出现，复合会话整体落空壳跳过 |
| continuation 摘要 | 上下文续接时框架注入的前期会话归纳，模型生成物，本期整块丢弃 |
| OMO 工具转写 | OMO 类编排插件把工具调用转写成 user/text 消息注入的形态（工具名加空格打头），按框架噪音丢弃不计真实用户消息；Bash 打头与 mcp__ 转写的收录取舍见 2.4 能力1 形态12/13 与 6.2 待标定 |
| 成功即跳过 | 同一 session_key 已有 success 档案时复用不重抽，补跑与定向分析只重抽 failed 行与新增会话（skipped 行为终态，见 2.4 能力3） |
