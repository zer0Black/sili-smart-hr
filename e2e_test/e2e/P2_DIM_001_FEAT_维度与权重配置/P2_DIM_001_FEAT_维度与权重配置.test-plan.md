### 方法（功能与按钮映射）
- `goto()`：导航 /system/dimension，等待树加载
- `selectModule(name)` / `selectGroup(name)` / `selectLeaf(name)`：树节点点选
- `fillLeafForm(data)`：填写叶子表单（名称/提示词/锚点/权重/说明）
- `saveLeafConfig()`：点保存配置 → 确认保存（二次确认链路）

- `deleteCurrentLeaf()`：停用并保存 → 删除维度 → 确认删除
- `fillActivityRule(active, low)` + `saveActivityRule()`：活跃度规则保存链路
- `fillCreateDialog(data)` + `submitCreate()`：新增维度弹窗提交

## 测试场景

### 1. 正向流程

#### 1.1 页面加载与默认状态
**需求来源**: 3.2 流程说明 1、4.1.5 交互逻辑
**验证点**: 顶栏「系统配置 → 维度与权重」可达；四模块按固定顺序展示（使用活跃度、AI 使用能力、AI 管理能力、九型人格）；默认选中首个可配置叶子维度，右侧展示配置表单；顶部信息条显示「所有配置改动在下次评估跑批时生效」
**数据清理**: 无（只读）

#### 1.2 树搜索模糊过滤
**需求来源**: 4.1.2 A. 维度树 - 树搜索关键词「按维度名称模糊过滤」
**验证点**: 输入既有维度名片段，树中仅剩匹配节点；清空关键词恢复全树
**数据清理**: 无（只读）

#### 1.3 新增维度成功（AI 使用能力 / 对话分析）
**需求来源**: 4.2.3 提交新增维度、4.1.4 规则4（编码自动生成）
**验证点**: 弹窗填写名称（E2E_时间戳 唯一前缀）/提示词/锚点提交后弹窗关闭；树中底层能力分组下出现新节点并自动选中；维度编码只读显示且以 AI_ 开头、全大写（探索确认生成 AI_CESHIWEIDU 格式）；数据来源显示对话分析
**数据清理**: afterAll 通过 API 软删（POST /api/dimensions/delete）

#### 1.4 编辑维度并保存成功
**需求来源**: 4.1.3 保存维度配置、4.1.4 规则1
**验证点**: 选既有叶子维度改名称/权重/维度说明 → 保存配置 → 二次确认弹窗（文案含「下一次评估周期生效」）→ 确认保存 → toast 成功；刷新页面后修改持久（读 API 验证落库）
**数据清理**: beforeAll 读原值，afterAll 通过 API 恢复（POST /api/dimensions/update 回写原值）

#### 1.5 活跃度规则保存成功
**需求来源**: 4.1.3 保存活跃度规则、4.1.2 C 字段默认值 10/5
**验证点**: 选使用活跃度模块，初始 10/5；改活跃下限 20、低频下限 8 → 保存规则 → 二次确认 → 确认；判定关系文案实时更新为「≥20 判活跃、8~19 判低频、<8 判未使用」；刷新后持久
**数据清理**: afterAll 通过 API 恢复原阈值

#### 1.6 模块汇总视图与权重合计
**需求来源**: 4.1.5 交互逻辑（汇总条实时计算）、4.1.2 D 汇总表
**验证点**: 选 AI 使用能力模块展示只读汇总表（列头 6 项、行数据与树一致）；权重合计数值正确（两维度之和）；合计偏离 100% 时显示「偏离 100%（±N%）」警示；选中使用活跃度模块时不展示权重合计条，展示判定关系说明
**数据清理**: 无（只读）

#### 1.7 停用→删除全链路（状态机）
**需求来源**: 6.2 状态转换规则、4.1.3 删除维度、4.1.4 规则3
**验证点**: 新建测试维度（启用态）→ 删除按钮禁用 → 切换是否启用 → 保存配置 → 删除按钮解禁 → 点击删除 → popconfirm（文案含「历史评分保留」「不可恢复」）→ 确认删除 → 树中节点消失，右侧自动切换选中
**数据清理**: 场景内自带删除（测试数据即清理对象）；afterAll API 兜底软删

### 3. 字段长度与边界校验

#### 3.1 维度名称下边界：1 字符拒绝、2 字符通过
**需求来源**: 4.1.2 B「2~30 字符」
**验证点**: 输入 1 字符提交报错；输入 2 字符可提交成功
**数据清理**: 创建的 2 字符维度 afterAll API 软删

#### 3.2 维度名称上边界：30 字符通过、31 字符拒绝
**需求来源**: 同上
**验证点**: 30 字符提交成功；31 字符内联报错
**数据清理**: 30 字符维度 afterAll API 软删

#### 3.3 聚合权重边界：0 与 100 合法
**需求来源**: 4.1.2 B 聚合权重「0~100 整数」
**验证点**: 权重数字输入框分别填 0 和 100 可正常保存；滑块与数字框联动（改数字框后滑块位置同步）
**数据清理**: afterAll 恢复原值

#### 3.4 活跃度阈值：低频下限须小于活跃下限
**需求来源**: 4.1.2 C 低频判定下限「须小于活跃判定下限」、范围 1~999
**验证点**: 活跃 10 / 低频 10（相等）保存被拒（内联报错）；活跃 10 / 低频 11 保存被拒；活跃 1~999 范围外（0 / 1000）报错
**数据清理**: 无（未提交，表单复位即可）

## 数据策略（类型 B：可自建自清理 + 既有数据须恢复）

- **测试创建数据**：维度名称统一前缀 `E2E_` + 时间戳保证唯一，afterAll 通过 authedRequest 调 POST /api/dimensions/delete 软删（幂等，已删则忽略）
- **既有数据修改**（场景 1.4 / 1.5 / 3.3）：beforeAll 先 GET /api/dimensions/{id} 与 GET /api/dimensions/activity-rule 读原值，afterAll 回写恢复；断言依赖「刷新后重读」验证持久化
- **不触碰的字段**：AI_CESHI（名称「测试」）维度仅作只读断言对象，不修改
- **并行安全**：本套件串行运行（spec 级配置 workers=1 或单文件），维度树为全局单例配置，并行文件会互相污染树快照断言

## 质量标准
- 每个测试场景标注需求来源 ✅（见各场景）
- 测试场景相互独立 ✅（各自建数据各自清理，不依赖执行顺序）
- 必填字段（名称/锚点/提示词/活跃度阈值）、长度限制（2~30/≤500/≤2000/≤300）、唯一性（编码系统生成去重）100% 覆盖 ✅
