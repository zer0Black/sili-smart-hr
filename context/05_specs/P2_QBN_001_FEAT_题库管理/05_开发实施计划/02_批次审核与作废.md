# 批次审核与作废 实现计划

> **目标：** 落地 question_batches 表与批量标记驳回制审核闭环：待审核批次卡区、批次明细、确认入库（未标记默认通过）、作废（按批次类型分流语义）、驳回题重新提交归批，前端批量审核视图与批次卡区可用。
> **架构：** 后端沿用 SP1 的 question 域四层骨架新增 batch 面（repository/service/handler 同文件扩展或新建 question_batch.go，按文件粒度拆 QuestionBatchRepository/QuestionBatchService 独立文件）；确认入库与作废都是批次边界的单事务整批操作（repository 收口事务，assessment_config UpdateWithMembers 先例）；重新提交的归批事务同文件收口。前端在题库管理页内做页内视图切换（列表态 ↔ 审核视图，非独立路由）。
> **技术栈：** Go 1.25 + Gin + GORM（Transaction 收口）；React 19 + TanStack Query + shadcn/ui

## 代码库依据

- 相关入口与复用：
  - SP1 已落 Question/QuestionRepository（ListByIDs、MaxQuestionSeq、UpdateWithVersion）与 questions 五接口，本计划消费 ListByIDs 与批次整批更新。
  - 事务收口先例：repository.UpdateWithMembers（[repository/assessment_config.go:97](../../../../../hr-backend/internal/repository/assessment_config.go)，Transaction 内乐观锁更新+覆盖子表）；无通用 Transaction 辅助，跨表事务收敛在 repository 单方法内。
  - 批次号同日序号：参照 dimension 编码生成思路（查最大推导+唯一索引兜底），按服务器本地日 time.Local 判定同日（04 §2.2，与 scheduler Location 先例一致）。
  - 状态前置校验模式：service 层判前置状态返 1706/1708（dimension service 状态机校验同款）。
  - 前端页内视图切换先例：assessment/index.tsx 手写 tab；审核视图为同一页内条件渲染分支（viewMode state：'list' | 'review'），非路由切换。
  - 前端弹窗滚动兜底：DialogContent 自带 max-h + overflow-y-auto，144 题审核卡片流用页面主体滚动（非弹窗）。
- 验证入口：同 SP1。基线：SP1 合入后 build/test/type-check 全绿为前提。
- 规模与耦合判断：批次审核是题库管理的中枢闭环（SP3 量表引入与 SP4 生成的产物都进批次待审），先于两者落地可用「手工插库数据」独立验收（测试内直接构造 PENDING 批次与题目行）。共享 service/question.go 的重新提交方法跨文件扩展，职责边界：question.go 保持行级维护，question_batch.go 承载批次事务与重新提交归批；router.go/wire.go 顺序追加。

        ListPending(ctx context.Context) ([]domain.QuestionBatch, error)
        // FindByID 主键查。
        FindByID(ctx context.Context, id int64) (*domain.QuestionBatch, error)

        // created_at 最早一条（并入语义取最早开批的），无则返回 ErrRecordNotFound。

        // CreateBatchWithQuestions 建批事务（SP3 量表引入/SP4 生成完成复用）：
        // 批量插 questions（编号连续分配收在本方法内：按每题 source 推导前缀 Q-AG-/Q-Scale-，

        // 批内题目 status 置 PENDING + batch_id 回填。tx 传 nil 时自开事务；SP3 引入事务传入外层 tx
        // 复用（行锁+ensure+建批同事务原子提交）。
        // batch 行 ID 与题目行 ID 由雪花回调赋值；返回批次行。

        // NextBatchNo 生成批次号：前缀（G/S/R）+ MMdd（time.Local），查同日同前缀最大批次号推导序号，
        // 首批无后缀、同日第 2 批起 -2/-3 递增。UNIQUE 索引兜底并发（撞键由调用方重试或上抛）。
        NextBatchNo(ctx context.Context, prefix string, now time.Time) (string, error)
        // ConfirmBatch 确认入库事务：批次置 CLOSED+closed_at；rejectedIDs 集合外批内题目批量置 ACTIVE，
        // 集合内批量置 REJECTED 并逐题写 reject_reason；返回 admitted/rejected 计数。
        // WHERE 恒带 status=PENDING（题目）与批次 PENDING 前置，非 PENDING 返回 0,0,ErrBatchNotPending。

        // VoidBatch 作废事务：批次置 VOIDED+voided_at；GENERATE/IMPORT 批内题目批量软删（UPDATE deleted_at）；
        // RESUBMIT 批内题目回退 REJECTED（保留原 reject_reason，不覆盖）。批次非 PENDING 返回 ErrBatchNotPending。

        // ResubmitToBatch 重新提交归批事务：题目文本更新+status 置 PENDING+version+1；存在待并入 RESUBMIT 批则
        // batch_id 改挂+question_count+1，否则 NextBatchNo("R") 新建 RESUBMIT 批（question_count=1）。
        // 题目乐观锁失败（version 不符）返回 ErrVersionConflict。
        ResubmitToBatch(ctx context.Context, question *domain.Question, updates map[string]any) (*domain.QuestionBatch, error)
    }
    // 哨兵：var ErrBatchNotPending = errors.New(...)、var ErrVersionConflict = errors.New(...)（包级导出）

AND status='PENDING'`，REJECTED 子集逐题 UPDATE reject_reason（map 里带 reason）；VoidBatch 软删用 `UPDATE questions SET deleted_at=? WHERE batch_id=? AND deleted_at IS NULL`。NextBatchNo 序号推导：查 `batch_no LIKE '前缀+MMdd%'`（EscapeLike）取最大值解析尾缀数字。
