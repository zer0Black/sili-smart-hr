## 1. 概述

### 1.1 功能背景

评估引擎与个人画像已贯通：周期批量评估（P2_ASM_001）逐期落库活跃度统计（activity_stats）、维度评分（dimension_scores）与聚合结果（aggregate_scores），主动测试（P2_TST_001）叠加 AI 管理能力评分与九型判型（assessment_test_results），个人画像（P2_PRF_001）解决单人的能力呈现。团队级视角仍缺失：运营人员看不到全公司的能力分布、共性短板与未使用规模，无法回答「团队整体弱在哪、该给谁安排什么培训」这一能力盘点的核心问题。

本 feature 是 PRD 5.2.2 中 F10（团队看板）的对应交付项，建团队看板与能力逐期趋势两个只读页面，并交付一个周期性后台任务：批次终态后调 LLM 生成团队级培训方向建议落库。除该建议生成任务外，看板页面为纯只读消费，聚合数据实时计算不落库。

### 1.2 本功能业务目标

1. 团队态势一屏可见：活跃度三态分布（含环比）、AI 使用能力 8 维与管理能力 5 子能力整体均分雷达、九型人格构成快照，支撑运营人员掌握全公司当期能力全貌。
2. 共性短板可识别可行动：每模块自动判定均分最低 2 维为共性短板（带低分占比），点击短板标签或未使用人数卡携条件跳转人员画像列表定位人群，下钻个人画像详情完成逐人处置。
3. 趋势可追：能力逐期趋势页呈现模块综合分、各维度近若干期走势与本期环比变化，观察团队整体能力演进。
4. 培训方向自动产出：周期批次终态后系统自动生成两模块的团队级培训方向建议落库，看板就近呈现，指导整体培训规划（个人级培训建议在个人画像，看板只给团队级）。

### 1.3 与 PRD 拆分的对应关系

本 feature 即 PRD 5.2.2 的 F10（团队看板），承载团队看板模块的看板查询（进入团队看板、看板详情下钻）、人群识别（短板人群识别、未使用人群标识、团队级培训方向建议）、趋势下钻（能力逐期趋势）三个功能点。人群识别经需求沟通决策为跳转承载：看板不内嵌人群表格，短板标签与未使用人数卡携条件跳 F9 人员画像列表（其短板维度筛选与仅看未使用开关承接人群定位），避免两套人群列表双口径。培训方向建议经需求沟通决策为 LLM 生成落库、跑批后自动触发。工作台聚合态势归 F11。

## 4. 页面功能详细说明

### 4.1 页面 1：团队看板页

#### 4.1.1 页面概述

**页面形式：**独立页面，挂 `_authenticated` 顶栏「结果洞察」一级菜单下的「团队看板」二级菜单。

**页面职责：**全公司整体能力聚合的呈现入口。自上而下依次为评估区间工具条、活跃度概览（三态人数卡 + 环形图 + 环比）、两模块能力雷达卡（整体均分雷达 + 共性短板标签）、团队人格构成（九型分布柱图 + 构成摘要）、团队培训方向建议。运营人员在此掌握当期态势、识别共性短板与未使用规模、就近跳转人群定位或趋势下钻。

#### 4.1.2 涉及字段

##### A. 工具条字段

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 校验规则 | 默认值 | 业务含义 |
|---------|---------|---------|---------|---------|--------|--------|
| 评估区间 | 下拉单选 | 数据库（activity_stats / dimension_scores / aggregate_scores 三表落库周期并集） | 页面加载 | 选项仅列已落库区间 | 最新已落库区间（标注「本期」） | 所选评估区间，整页数据（培训建议除外）按该区间取数 |
| 数据更新时间 | 文本（只读） | 数据库（该区间聚合数据对应批次记录的终态时间，同区间多条批次时取最新终态批次） | 页面加载、切区间 | 无 | - | 所选区间看板数据对应的批次完成时间；无批次记录时显示区间周期终点 |

##### B. 活跃度概览字段

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 业务含义 |
|---------|---------|---------|---------|--------|
| 全员人数 | 数字 | 上游 userapi（全员名单计数） | 页面加载、切区间 | 统计基线人数（分母），卡片副标题呈现 |

| 低频人数 | 数字+占比 | 同上 | 页面加载、切区间 | 低频分级人数与占比 |
| 未使用人数 | 数字+占比 | 同上 | 页面加载、切区间 | 未使用分级人数与占比，人数卡可点击跳转；无 activity_stats 行的人计入未使用 |
| 三态环形图 | 图表 | 同上 | 页面加载、切区间 | 活跃/低频/未使用人数构成，中心显示全员人数 |
| 活跃度环比 | 文本（±人数） | 计算（本期减上一落库区间计数） | 页面加载、切区间 | 活跃增减与未使用增减；所选区间为最早区间时不显示 |

##### C. 能力雷达卡字段（两卡：AI 使用能力 / AI 管理能力）

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 业务含义 |
|---------|---------|---------|---------|--------|
| 整体均分雷达 | 图表 | 数据库（dimension_scores 所选区间全公司各维度行，聚合口径见 4.1.4 规则3） | 页面加载、切区间 | 模块内各维度全员均分雷达，叠加全维度均值虚线参考 |

#### 4.1.3 功能与按钮

**用户可操作功能：**

- **评估区间切换**
  - 触发方式：区间下拉选择
  - 按钮位置：页面顶部工具条
  - 权限要求：已登录平台账号
  - 功能说明：下拉列出系统全部已落库评估区间（新到旧，最新项标注「本期」），切换后活跃度与两模块雷达按所选区间整体刷新；九型区（分布、构成摘要、测评覆盖数）与培训建议保持最新快照，不随区间切换变化（口径见 4.1.4 规则5、规则6）。
  - 约束说明：区间选项集合由三表实际落库周期推导（口径同 F9 详情页区间列表），非按周期配置推算。

- **共性短板人群跳转**
  - 触发按钮：共性短板标签（卡片级可点击元素）
  - 按钮位置：两雷达卡底部短板标签区
  - 权限要求：已登录平台账号
  - 功能说明：携带短板维度作为筛选条件跳转 F9 人员画像列表页，由其短板维度筛选展示该维度为个人短板的人群。
  - 约束说明：跳转语义为「列出该维度为个人短板的人」（口径同 F9 短板集合），与公司级共性短板（维度均分低）是两个层次：公司级短板维度内必然存在个人短板人群，跳转结果即该维度的人群切面。F9 列表人群为其本期口径（各数据项最新已落库周期，F9 不设区间筛选），看板切到历史区间时跳转人群与看板所选区间可能不同期。

- **未使用人群跳转**
  - 触发按钮：未使用人数卡（卡片级可点击元素）
  - 按钮位置：活跃度概览区
  - 权限要求：已登录平台账号
  - 功能说明：跳转 F9 人员画像列表页并开启「仅看未使用」开关，展示本期未使用人群。活跃与低频人数卡置灰样式、不可点击（人群定位场景聚焦未使用与短板，活跃低频无处置动作）。

- **查看逐期趋势跳转**
  - 触发按钮：查看逐期趋势（链接按钮）
  - 按钮位置：两雷达卡右上角
  - 权限要求：已登录平台账号
  - 功能说明：携带能力类型参数（use / manage）跳转能力逐期趋势页。

- **维度雷达悬浮查看**
  - 触发方式：悬浮雷达图数据点
  - 权限要求：已登录平台账号
  - 功能说明：悬浮显示该维度全员均分值；不承载单人数据下钻（单人下钻经短板标签跳转完成）。

**前端自动流程（如有）：**

- **页面加载自动查询**
  - 触发时机：进入页面
  - 说明：按默认区间（最新已落库区间）自动发起整页数据请求，无需手动操作。

#### 4.1.4 业务规则

- **规则1：区间数据一致性**
  - 规则描述：看板页除九型区（分布、构成摘要、测评覆盖数）与培训建议外，全部数据块统一按所选区间取数；区间切换时整页刷新并显示加载态，避免新旧区间数据混渲染。
  - 约束说明：手动定向批次与周期批次的窗口可能错位，聚合按落库行实际周期归属，不跨区间拼装。

- **规则2：活跃度统计口径**
  - 规则描述：三态人数按所选区间 activity_stats 各人分级行计数，无行的人计入未使用；全员人数以 userapi 全员名单计数为分母；占比保留一位小数。环比取上一落库区间计数差，增减带方向符号，活跃增加与未使用减少为正向色。
  - 约束说明：未使用含「无统计行」与「统计行判未使用」两类，与 F9 列表口径一致。

- **规则3：整体均分聚合口径**
  - 规则描述：各维度全员均分 = 所选区间该维度全部参与聚合维度行（剔除 insufficient 与 failed）的算术平均，四舍五入取整展示；有数据人数 < 3 的维度均分置空（雷达该轴断开），避免小样本误导。全维度均值参考线 = 各维度均分的算术平均，均分以未取整原始值（单人整数分的算术平均）参与计算，展示前四舍五入取整（精度口径同 4.2.4 规则2）；任一维度置空时该参考线不显示。数据来源口径：使用能力维度取 source=conversation 行，管理能力维度取 source=active_test 行。
  - 约束说明：均分为展示期实时聚合，不落库；与 F9 详情页公司均分对照同一口径（F9 规则4）。

- **规则4：共性短板判定**
  - 规则描述：每模块在参与聚合人数 ≥ 3 的维度中取均分最低的 2 维为共性短板（并列时取满并列项，至多展示 3 项，超 3 项时按维度均分升序取前 3，仍并列按维度编码升序截断）；无满足条件的维度时该模块不展示短板标签。标签呈现「维度名 + 均分 + 低分占比%」，低分占比 = 该维度参与聚合人数中分数 < 60 的人数占比（60 分线与 F9 核心结论短板阈值一致），保留一位小数。
  - 触发条件：页面加载、切区间时按所选区间数据计算。
  - 约束说明：九型维度不参与共性短板判定（参考性维度不进硬性聚合）。

- **规则5：九型构成快照口径**
  - 规则描述：九型分布按全员各自最新判型行的集合统计当前占比（构成快照），不随评估区间切换变化；主导型与次主导型取占比最高两型，并列时按型别序号升序取先。占比分母为最新判型行总数（测评覆盖数），覆盖数与全员人数比值展示覆盖率。
  - 约束说明：与 F9 详情页「最新判型不随区间变化」口径一致；无任何判型行时九型区显示「暂无九型人格测评数据」提示，不显示空图表。

- **规则6：培训建议展示口径**
  - 规则描述：看板取 period 起止新到旧排序的第一条建议行（即最新评估区间的建议，排序键为 period 而非生成时间，补生成场景下旧区间建议生成时间晚于新区间时不影响取行）：行状态为已生成时展示其内容，生成中或生成失败时展示提示态；建议区标注其对应区间与生成时间；所选历史区间无对应建议时不切换展示（回看历史建议的需求本期不承载）。建议内容为脱敏口径，不含任何对话原文与单人评分明细。
  - 约束说明：建议生成见 5.1，展示层只读。

- **规则7：隐私红线**
  - 规则描述：看板任何位置只呈现聚合统计与脱敏建议文案；不出现对话原文、单人维度分数明细或评分理由。
  - 约束说明：定位单人必须经跳转 F9 由其鉴权页面完成，看板不做单人数据承载。

#### 4.1.5 交互逻辑

- 空状态：系统无任何落库区间时，整页显示「暂无评估数据」空态提示与评测运营中心跳转入口（跳 F6 评估运营域的评测运营中心页 /assessment，引导先完成跑批）。
- 错误态：整页数据接口失败（含全员名单上游失败，错误码 1305）时显示错误占位与「重试」按钮，重试重新发起整页请求；不用部分数据降级渲染。

- 响应式：窄屏（< 1280px）时两雷达卡纵向堆叠，九型区图左文右改上下排布。

## 5. 非页面功能详细说明

### 5.1 团队培训建议生成（周期任务）

#### 5.1.1 功能概述

**触发方式：**定时任务（Asynq scheduler，每分钟 tick）+ LLM 调用
**触发时机：**tick 扫描发现需生成建议的已终态周期批次时（拾取条件见 5.1.4 规则2）
**功能职责：**周期批次终态后自动生成该区间的团队级培训方向建议：汇总当期两模块聚合数据与共性短板，一次 LLM 调用产出两模块的培训方向建议与综合研判，脱敏后落库 team_training_suggestions 表，供团队看板页展示。

#### 5.1.2 处理流程

1. tick 扫描周期批次（batch 模式为周期批次）中状态为已终态（成功 / 部分失败 / 失败）且需生成建议的批次（拾取条件见规则2），取最早一条为待处理批次。
2. 拾取后先创建生成中建议行（幂等创建：行不存在则创建；已存在且为生成中则沿用该行续作，即任务级重试场景；重生成场景（规则2 拾取条件二）将既有终态行重置为生成中续作），生成中行即拾取锁，LLM 成功或失败终态均更新该行。
3. 汇总该批次区间的聚合素材：两模块各维度全员均分与低分占比（4.1.4 规则3、规则4 同口径）、两模块聚合分（aggregate_scores 模块行，上游加权平均口径，与趋势页「模块综合分」的维度均分算术平均口径不同）、活跃度三态计数、共性短板维度清单与维度口径快照（评分锚点摘要）。
4. 组装提示词（固定模板 + 上述结构化素材）调用当前启用大模型，要求产出：两模块各 2 至 4 条培训方向建议（每条含方向名称与说明）与一段团队综合研判。
5. 校验 LLM 返回结构（两模块建议条数、字段完整性），rationale 类文案经 Redact 脱敏后更新建议行（携带批次号、period 起止、两模块建议 JSON、综合研判、生成时间）。
6. 本批次处理完成，下个 tick 自然拾取下一条待处理批次。

#### 5.1.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 周期批次记录 | assessment_batches（P2_ASM_001 已建） | 待处理批次发现 | 仅周期批次（手动定向批次不触发建议生成） |
| 维度评分与聚合 | dimension_scores / aggregate_scores | 建议生成素材 | 按批次区间聚合，口径同看板 |
| 活跃度统计 | activity_stats | 建议生成素材 | 三态计数 |
| 维度口径 | dimensions（评分锚点） | 提示词素材 | 维度能力定义摘要 |
| LLM 能力 | integration/llm（P2_TECH_001 底座） | 建议生成 | 走当前启用模型，专用 LLM client 通道 |
| 培训建议记录 | 本 feature 新建（team_training_suggestions） | 建议落库载体 | 一区间一行，以 period 起止为唯一冲突键幂等 upsert；同周期重跑批次终态成功后重生成覆盖旧建议行（见规则2） |

#### 5.1.4 业务规则

- **规则1：触发范围**：仅周期批次触发（手动定向批次的区间与周期批次窗口错位，其聚合素材不具全公司代表性）；失败与部分失败批次同样生成（素材含已剔除的 failed 维度说明，建议按可用数据给出）。
- **规则2：幂等、重跑覆盖与补生成**：team_training_suggestions 以 period 起止为唯一约束（一区间一行，批次号为随 upsert 更新的普通字段）。tick 拾取条件（满足其一）：该 period 无对应建议行；或该 period 存在比建议行所属批次更新的同 period 重跑批次，且其终态为成功（部分失败或失败的重跑批次不覆盖既有建议）。即：周期批次重跑成功才会重生成该区间的建议并覆盖旧行，其余情况（原建议行已生成或生成中、重跑批次未终态或终态非成功）不更新。tick 幂等扫描，重生成沿既有行 upsert；漏生成（如 tick 停机窗口错过的批次）由后续 tick 自动补齐。
- **规则3：失败不阻断不重试至死**：LLM 调用失败按 Asynq 任务级重试（基准 3 次）；重试耗尽标记该行生成失败（建议行落 failed 状态与失败原因），看板展示「培训建议生成中或本期无批量批次」提示，下个周期批次自然覆盖；不回溯阻断批次链路。
- **规则4：成本口径**：每次生成一次 LLM 调用（周频一批次一次），提示词素材为结构化聚合数据（不含任何单人明细与对话原文），token 量级与单次单人综合评估相当。
- **规则5：并发与超时**：任务级超时 240s（对齐阅卷链路量级，覆盖 LLM 长响应）；tick 每分钟至多拾取一条批次，生成中行即拾取锁：行存在期间 tick 扫描条件不命中，跨 tick 重复拾取由行存在性拦下；Asynq 任务级重试沿用既有生成中行续作（见 5.1.2 步2），不产生重复拾取与并发落库冲突（period 唯一约束兜底）。

#### 5.1.5 异常处理

| 异常场景 | 处理方式 | 错误提示/日志 |
|---------|---------|--------------|
| LLM 调用失败/超时 | Asynq 任务级重试（3 次基准倍增退避） | 记 ERROR 日志含批次号 |
| 重试耗尽 | 建议行落 failed 状态与原因，看板走提示态 | 记 WARN 日志，不产告警信号 |
| LLM 返回结构校验失败 | 同 LLM 失败路径（重试后仍失败落 failed） | 记 ERROR 日志含批次号 |
| 落库失败 | err 透传交 Asynq 重试 | 记 ERROR 日志 |
| 批次数据异常（区间无聚合行） | 判定式：该 period 在 dimension_scores、aggregate_scores 与 activity_stats 三表均无任何行（任一表有行即视为有素材，activity_stats 有行的正常周期如启用首周全员未使用）。命中则该批次跳过并标记 failed 行，避免 tick 反复重扫；未命中按可用素材照常生成 | 记 WARN 日志含批次号 |

#### 5.1.6 与其他功能的关联

- **上游依赖：**P2_ASM_001 周期批次终态记录（数据依赖，只读消费）；P2_TECH_001 LLM 调用底座（能力依赖）。
- **下游影响：**团队看板页建议区消费展示（4.1.2 E）。

### 5.2 看板聚合查询接口（支撑 4.1 / 4.2）

#### 5.2.1 功能概述

**触发方式：**API 调用（前端页面触发）
**功能职责：**两个只读聚合接口：团队看板接口一次返回所选区间的看板全量数据（区间列表、活跃度三态与环比、两模块维度均分与共性短板、九型快照、培训建议、全员人数）；趋势接口按能力类型返回近 8 期逐期序列（综合分、各维度均分序列、环比变化表、本期短板标识）。聚合实时计算不落库。

#### 5.2.2 处理流程

1. 看板接口：接收评估区间参数（空时默认最新落库区间）；推导区间列表（三表落库周期并集，新到旧）；按区间批量聚合活跃度计数、两模块维度均分与低分占比（IN 查询 + 内存聚合，剔除 insufficient/failed）、共性短板判定、九型最新判型集合统计；调 userapi 取全员人数（失败即接口整体失败返回，错误码 1305）；拼装培训建议行返回。
2. 趋势接口：接收能力类型参数（use|manage，非法值按 use 兜底）；取近 8 个落库区间，逐区间按 5.2.2 步1 口径计算各维度均分与综合分；计算环比变化与本期短板标识返回。

#### 5.2.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 维度评分行 | dimension_scores | 维度均分、低分占比、走势序列 | 批量 IN 查询按区间聚合 |
| 聚合行 | aggregate_scores | 区间列表推导 | 与评分行、活跃度行并集 |
| 活跃度行 | activity_stats | 三态计数与环比 | 所选区间全行计数 |
| 九型判型行 | assessment_test_results | 构成快照 | 全员各自最新判型行 |
| 培训建议行 | team_training_suggestions | 建议区 | period 起止新到旧第一条（口径同 4.1.4 规则6） |
| 全员人数 | integration/userapi | 统计分母 | 失败即整体失败 |
| 批次记录 | assessment_batches | 数据更新时间 | 区间对应批次终态时间 |

#### 5.2.4 业务规则

- **规则1：性能口径**：四表查询按区间批量 IN 查询后内存聚合，禁止逐人逐维度查询；九型最新判型行按人取最新（SQL 窗口或自连接，三库兼容口径参照 F9 详情接口既有多库兼容子查询扩展）。
- **规则2：错误语义**：全员名单上游失败返回 StaffListUnavailable（1305）整体失败；无任何落库区间时返回空数据语义（前端走空态），不视为错误。
- **规则3：缓存口径**：聚合实时计算不落库、不加服务端缓存；周频数据变化、每次请求成本可控（百人量级 IN 聚合）。

## 6. 数据状态定义

本 feature 页面为只读消费域，不管理系统状态机。新增 team_training_suggestions 表承载建议行状态：

| 状态名称 | 状态说明 | 可转换到的状态 |
|---------|---------|--------------|
| 生成中 | 批次已终态、建议行已创建未完成生成（含任务级重试续作中） | 已生成、生成失败 |
| 已生成 | LLM 产出校验通过并脱敏落库 | 生成中（同 period 重跑周期批次终态成功后重生成） |
| 生成失败 | 重试耗尽或数据异常，含失败原因 | 生成中（同 period 重跑周期批次终态成功后重生成） |

| 当前状态 | 可转换到的状态 | 转换条件 | 转换触发方式 |
|---------|------------|---------|-------------|
| 生成中 | 已生成 | LLM 返回结构校验通过且落库成功 | 系统自动（建议生成任务） |
| 生成中 | 生成失败 | LLM 重试耗尽 / 返回校验持续失败 / 批次数据异常 | 系统自动（建议生成任务） |
| 已生成 / 生成失败 | 生成中 | 同 period 重跑周期批次终态为成功，tick 拾取后重置既有终态行续作（5.1.4 规则2） | 系统自动（建议生成任务） |

看板展示的其余数据状态均为上游落库状态的聚合映射（正常 / 已降权 / 数据缺失 / 待评估，同 F9 第 6 章口径），由聚合规则（4.1.4 规则3）吸收，无用户触发的状态转换。

## 8. 附录

### 8.1 术语表

| 术语 | 定义 | 说明 |
|------|------|------|
| 共性短板 | 模块内参与聚合人数 ≥ 3 的维度中全员均分最低 2 维（并列取满至多 3 项） | 公司级维度层面概念；与 F9 个人短板集合（个人内相对最低分维度）是两个层次 |
| 低分占比 | 该维度参与聚合人数中分数 < 60 的人数占比 | 60 分线与 F9 核心结论短板阈值一致（F9 个人短板为个人内相对最低分，无 60 分线） |
| 整体均分 | 所选区间该维度全部参与聚合维度行（剔除 insufficient 与 failed）的算术平均 | 看板口径，实时聚合不落库；与 F9 公司均分对照同口径 |
| 构成快照 | 全员各自最新判型行集合统计的九型占比 | 不随区间切换变化，反映当前覆盖人群的型别构成 |
| 团队培训方向建议 | 周期批次终态后 LLM 生成的两模块培训方向与综合研判 | 团队级概念，个人级培训建议在个人画像，看板不呈现 |
| 评估区间 | 一条聚合数据所属的周期窗口 | 口径同 F9：落库行 period_start/period_end 定义，窗口左闭右开，页面起止显示为 period_start 至 period_end 前一日 |

### 8.3 通用交互与UI规范

全系统级别的UI和交互约定详见：[01_通用需求.md](../01_通用需求.md)

**偏离记录：**
- 看板页与趋势页均为聚合图表页，无列表分页（通用规范：所有列表均分页）：两页面不承载行级列表，人群行级定位经跳转 F9 列表页完成，分页规范由 F9 承接。
