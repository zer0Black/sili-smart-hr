# 03 场景列表

> 采用两层架构。第一层模块能力场景回答每个模块能干什么，聚合其 CRUD、配置、查询操作；第二层端到端业务流程场景回答用户如何跨模块完成业务目标，只描述衔接逻辑并引用第一层编号。场景按用户目标划分，CRUD 强制聚合，不拆分为独立场景。

## 一、场景总览

### 1. 模块能力场景

| 场景编号 | 场景名称 | 场景类型 | 主要参与者 | 关键节点 |

## 二、模块能力场景详细说明

### S01 对话分析评估管理

| 属性 | 说明 |
|-----|------|
| 场景描述 | 系统按周期自动跑批或由 HR 定向触发，对员工对话行为做会话级特征抽取与跨会话综合评估，覆盖 AI 使用能力底层 4 维与上层 4 维，产出个人画像与团队看板 |
| 前置条件 | 维度权重已配置（S03），跑批周期已配置（S05），大模型已配置并启用，集成密钥可用，sili-smart-api 会话日志可访问 |
| 关键节点 | 批量跑批触发, 定向分析触发, 拉取会话, 抽取特征, 综合评估, 汇聚活跃度, 生成画像, 更新看板, 查看定向报告 |
| 后置状态 | 当期个人画像与团队看板已更新，能力维度不足处已降权标注 |
| 技能调用 | 通用评估引擎底座（会话级抽取、跨会话综合评估） |

### S02 主动测试管理

| 属性 | 说明 |
|-----|------|
| 场景描述 | HR 发起 AI 管理能力或九型人格测评，按需对特定人员单次定向发起；每次生成一次性作答链接推送，员工作答后系统 AI 阅卷，结果汇入画像 |
| 前置条件 | 题库已就绪（S04），维度已配置（S03），推送通道可用 |
| 关键节点 | 发起测试, 选对象维度, 单次定向发起, 生成作答链接, 推送链接, 追踪完成情况, AI阅卷评分, 更新画像, 查看测试结果 |
| 后置状态 | 测试结果已落库并汇入个人画像，作答链接已失效 |
| 技能调用 | AI 管理能力题 LLM 出题（情境简述加作答要求，选项写在作答要求中）、员工作答通过与 AI 逐题对话、AI 阅卷结合对话过程；九型用标准量表，AI 只做型别判定 |

### S03 维度与权重配置管理

| 属性 | 说明 |
|-----|------|
| 场景描述 | HR 维护能力模型的维度构成、评分基准锚点与聚合权重，作为对话分析与主动测试评估的统一口径 |
| 前置条件 | HR 已登录 |
| 关键节点 | 新增, 查询, 编辑, 删除 |
| 后置状态 | 维度与权重配置已更新，下次跑批按新配置执行 |
| 技能调用 | 无 |

### S04 题库管理

| 属性 | 说明 |
|-----|------|
| 场景描述 | 题库分两路来源：AI 管理能力题由 LLM 动态生成（选项写在作答要求文本中），九型人格引入标准量表作固定题库；两路共用同一审核界面与标记操作，按来源分批审核、不混批，HR 标记不合适的题驳回弃用，未标记的默认入库启用 |
| 前置条件 | 大模型已配置并启用（AI 管理能力题生成），九型量表已引入，HR 已登录 |
| 关键节点 | 生成AI管理题, 引入九型量表, 分批审核, 入库, 驳回弃用, 维护题库 |
| 后置状态 | 题库内容已更新，审核通过的题目可供主动测试调用 |
| 技能调用 | LLM 出题（仅 AI 管理能力题） |

### S05 评估周期与系统配置管理

| 属性 | 说明 |
|-----|------|
| 场景描述 | HR 维护评估周期、触发时点与大模型配置（模型清单、排他启用、密钥轮换）等系统参数 |
| 前置条件 | HR 已登录 |
| 关键节点 | 新增, 查询, 编辑, 删除 |
| 后置状态 | 系统配置已更新，下次跑批按新参数执行 |
| 技能调用 | 无 |

### S06 评估结果查看

| 属性 | 说明 |
|-----|------|
| 场景描述 | 运营人员作为消费方查看团队看板与个人画像，识别短板人群与未使用人群，查看短板结论与培训方向 |
| 前置条件 | 当期画像与看板数据已生成（S01、S02） |
| 关键节点 | 查看团队看板, 展示团队看板, 展示个人画像, 识别短板人群, 识别未使用人群, 查看短板结论与培训方向 |
| 后置状态 | 消费方已获取所需能力分布与培训信息 |
| 技能调用 | 无（只读查询与可视化） |

### S07 员工作答

| 属性 | 说明 |
|-----|------|
| 场景描述 | 员工经系统生成的一次性作答链接进入轻量作答页，完成当期 AI 管理能力或九型人格作答后提交，链接即失效。作答本身周期性进行，每轮用新链接；作答页仅承载作答提交，不提供画像、看板、评分理由浏览 |
| 前置条件 | HR 已发起测试并推送作答链接（S02），链接未失效 |
| 关键节点 | 进入作答页, 提交作答 |
| 后置状态 | 作答数据已提交至系统待阅卷，作答链接已失效 |
| 技能调用 | 无（仅提交） |

### S08 异常处置

| 属性 | 说明 |
|-----|------|
| 场景描述 | 系统对跑批失败的会话自动标记重试，重试耗尽降级为仅保留统计上下文，失败比例超阈告警；HR 在告警后决定是否触发补跑 |
| 前置条件 | 跑批已执行（S01），存在失败会话 |
| 关键节点 | 标记待重试, 自动重试, 降级保留统计, 超阈告警, 触发补跑 |
| 后置状态 | 失败会话已处置或降级，当期评估完成或已补跑 |
| 技能调用 | 无 |

### S09 工作台总览

| 属性 | 说明 |
|-----|------|
| 场景描述 | 运营人员登录后进入工作台首页，总览本期评估态势（跑批状态、下次跑批计划）、需要关注的人（短板与未使用人群入口）、待处理项（跑批失败比例超阈告警、主动测试逾期），并就近跳转团队看板或个人画像处置 |
| 前置条件 | HR 已登录，当期画像与看板数据已生成或跑批已执行（S01、S02） |
| 关键节点 | 进入工作台, 查看本期评估态势, 识别需关注的人, 查看失败超阈告警与逾期待处理项, 跳转看板或画像 |
| 后置状态 | 运营人员已掌握本期评估态势与待办，进入对应业务页处置或深入消费 |
| 技能调用 | 无（只读总览与跳转） |

### S10 用户管理

| 属性 | 说明 |
|-----|------|
| 场景描述 | HR 在用户管理页维护可登录平台的账号台账（账号、姓名、密码、启停、最近登录），支持新增、查询、编辑、启停、重置密码、删除；不设角色 |
| 前置条件 | HR 已登录 |
| 关键节点 | 新增, 查询, 编辑, 启停, 重置密码, 删除 |
| 后置状态 | 账号台账已更新，启停与登录校验即时生效 |
| 技能调用 | 无 |

## 三、端到端业务流程场景详细说明

### E01 员工能力盘点全周期

| 属性 | 说明 |
|-----|------|
| 场景描述 | 从员工在 sili-smart-api 的对话行为沉淀，到系统周期性能力评估，再到个人画像与团队看板更新的完整盘点闭环 |
| 涉及模块 | S01, S06 |
| 业务目标 | 周期性产出全员能力画像与团队看板，支撑能力分布识别与短板定位 |
| 前置条件 | 维度权重与跑批周期已配置，集成密钥与会话日志可访问 |
| 关键节点 | S01.批量跑批→拉取会话→抽取特征→综合评估, S01.汇聚活跃度→生成画像→更新看板, S06.查看团队看板→识别短板 |
| 数据流 | 会话日志 → 会话特征档案 → 能力评分（底层4维+上层4维）→ 个人画像 → 团队看板 |
| 触发链 | 周期到达触发 S01 自动跑批 → 画像与看板更新 → S06 数据可供消费 |
| 异常分支 | 抽取失败会话降级为仅保留统计 → 跨会话评估时该会话特征缺失 → 当期评估照常推进 → 失败超阈转 E03 |
| 补偿机制 | HR 调整维度权重或阈值后，下一周期跑批自动按新配置重算 |
| 后置状态 | 全员当期画像与团队看板已更新 |

### E02 主动测试发起到结果落库

| 属性 | 说明 |
|-----|------|
| 场景描述 | 对对话分析无法覆盖的能力项（AI 管理能力、九型人格）完成从 HR 发起、员工作答、AI 阅卷到画像更新的闭环 |
| 涉及模块 | S02, S07, S06 |
| 业务目标 | 补齐对话数据的盲区，使冷启动与高阶能力评估有据可依 |
| 前置条件 | 题库已就绪，维度已配置，推送通道可用 |
| 关键节点 | S02.发起测试→生成作答链接→推送链接, S07.进入作答页→提交作答, S02.AI阅卷评分→更新画像, S06.查看个人画像 |
| 数据流 | 测评对象与维度 → 作答链接 → 作答数据 → AI 评分 → 画像更新 |
| 触发链 | S02 发起并推送 → S07 作答 → S02 阅卷 → 画像更新 → S06 可消费 |
| 异常分支 | 员工逾期未作答 → S02 追踪提醒 → 仍未作答标记未完成；阅卷失败 → 并入失败兜底重试或降级 |
| 补偿机制 | 题库或评分标准调整后，S02 可对历史作答重阅卷并刷新画像 |
| 后置状态 | 测试结果已落库并汇入个人画像，作答链接已失效 |

### E03 评分失败兜底与补跑

| 属性 | 说明 |
|-----|------|
| 场景描述 | 批量跑批中个别会话抽取失败时，通过自动重试、降级、告警与人工补跑保证当期评估完成 |
| 涉及模块 | S01, S08, S05 |
| 业务目标 | 失败可控，当期评估不被局部失败阻塞 |
| 前置条件 | 跑批已执行且存在失败会话 |
| 关键节点 | S01.抽取特征（失败）, S08.标记待重试→自动重试→降级保留统计, S08.超阈告警→HR决定补跑, S01.定向补跑 |
| 数据流 | 失败会话标识 → 重试队列 → 重试结果 → 告警阈值 → 补跑任务 |
| 触发链 | S01 抽取失败 → S08 标记待重试并自动重试 → 仍失败降级 → 失败比例超阈告警 → HR 决定补跑 → S01 定向补跑 |
| 异常分支 | 重试次数耗尽 → 降级为仅保留统计上下文 → 该会话特征缺失当期评估照常推进 |
| 补偿机制 | 大模型恢复后，HR 触发定向补跑补齐缺失会话评估 |
| 后置状态 | 失败会话已处置或降级，当期评估完成或已补跑 |

### E04 冷启动新员工画像构建

| 属性 | 说明 |
|-----|------|
| 场景描述 | 新员工无对话数据时靠主动测试撑起画像，待对话数据积累后逐步补齐能力维度 |
| 涉及模块 | S07, S02, S01, S06 |
| 业务目标 | 新员工入职即有可用画像，随数据积累自动趋于完整 |
| 前置条件 | 新员工已纳入被测评对象，主动测试已就绪 |
| 关键节点 | S02.发起主动测试, S07.提交作答, S02.阅卷出结果, S01.对话积累后能力评分, S06.查看画像 |
| 数据流 | 主动测试作答 → 测试评分 → 初始画像 → 对话特征 → 能力评分 → 画像补齐 |
| 触发链 | 新员工无对话数据 → S02 发起主动测试 → S07 作答 → 画像以测试为主 → 对话数据达阈值 → S01 能力维度开始评分并补齐 |
| 异常分支 | 长期未使用无对话 → 画像持续以主动测试与活跃度为主，能力维度长期降权 |
| 补偿机制 | 对话数据从无到有后，S01 自动把能力维度从降权恢复为正常评分 |
| 后置状态 | 新员工画像随数据积累逐步完整 |

**矩阵说明**
