# 会话日志集成 实现计划

> **目标：** 在 hr-backend/internal/integration/conversationlog 补齐会话列表拉取与详情拉取两个 HTTP 客户端能力，收编既有 Ping 并固化错误分类与重试退避契约，成为 AI 使用能力评估全部对话数据的唯一入口。
> **架构：** 纯标准库 HTTP 客户端（net/http + encoding/json），一个包内三层：errors.go 收敛错误分类（sentinel + UpstreamError.IsNotFound 白名单）、retry.go 承载指数退避重试（fake clock 可注入）、client.go 承载三个公开方法与超时分档（每次尝试独立派生 ctx）。上游 `{success, message, data}` 解包逻辑收敛在本组件，禁止扩散到 service 层。Wire 装配零改动（NewConversationlogClient 与 wire.Bind 到 ConversationlogPinger 已随 P2_SYS_001 就位）。
> **技术栈：** Go 1.25 标准库（net/http、encoding/json、log/slog），httptest 单测，CGO_ENABLED=0 兼容。

  ```go
  package conversationlog

  import (
      "context"
      "errors"
      "fmt"
      "net/http"
      "time"
  )

  // doWithRetry 包装单次 HTTP 执行（specs §2.4 能力4）：
  // retryable := 传输错误（err != nil，含 ctx 派生超时但父 ctx 未取消） || HTTP 5xx
  // backoff := initialBackoff << attempt（10s → 20s → 40s），经 c.sleepFn 可中断等待
  // attempt 从 0 起，最多 4 次执行（1 + 3 重试）。
  // 确定性失败（非 5xx 的 HTTP 响应）首轮直通返回，不消耗退避。
  // 注：reqFn 形参为 func(context.Context) 而非 specs 的 func()，因每次尝试须用
  // 新派生的子 ctx 重建请求（WithTimeout 派生的 ctx 不可跨尝试复用），specs §2.2
  // 超时机制是此偏差的权威依据，实现以本签名为准。
  func (c *Client) doWithRetry(ctx context.Context, timeout time.Duration, reqFn func(context.Context) (*http.Request, error)) (*http.Response, error)

  // sleepContext 可中断等待，ctx 先结束返回 ctx.Err()（与 llm 底座 retry.go 同构，参照
  // hr-backend/internal/integration/llm/retry.go 的 sleepContext）。
  func sleepContext(ctx context.Context, d time.Duration) error
  ```

  关键逻辑：每次尝试独立经 `context.WithTimeout(ctx, timeout)` 派生子 ctx 后由 reqFn 构造请求并 `c.httpClient.Do` 执行，`resp.Body` 的关闭责任在调用方（doWithRetry 只负责拿到响应；重试场景下上一次尝试的 resp.Body 必须先 Close 再退避，防连接泄漏）；父 ctx 取消（`ctx.Err() != nil` 检查或 sleep 返回非 nil）立即返回 `ctx.Err()` 包装，剩余重试不再发起；传输错误需区分父 ctx 取消（`errors.Is(err, context.Canceled)` 直通）与单次超时（可重试）。成功（任意 HTTP 状态码的响应到手，含 401/400 等）即返回由调用方分类，重试判定只看传输错误与 5xx。日志接线（specs §6.1）：每次退避等待前输出 WARN 级 retrying 日志（method/path/attempt/backoff 字段）；重试耗尽返回 ErrNetwork 前输出 ERROR 级 failed 日志（method/path/status/session_key/attempt/retries/code 字段），日志禁止携带密钥明文与对话原文。

  **验收锚点：**

  - 核心断言：`TestDoWithRetryNetworkErrorRecovered`：注入 RoundTripper（替换 `c.httpClient.Transport`）前两次返 `errors.New("conn refused")`、第三次返 200 响应，断言最终 resp.StatusCode == 200 且请求计数 == 3
  - 核心断言：`TestDoWithRetryExhausted`：RoundTripper 恒返连接错误，sleepFn 记录调用序列，断言 `errors.Is(err, ErrNetwork)`、请求计数 == 4、退避序列 == `[10s, 20s, 40s]`
  - 核心断言：`TestDoWithRetry5xxRetried`：RoundTripper 返 500、500、200，断言成功且请求计数 == 3
  - 核心断言：`TestDoWithRetryDeterministicNoRetry`：RoundTripper 首次即返 401 响应，断言请求计数 == 1 且 sleepFn 零调用
  - 核心断言：`TestDoWithRetryCtxCancel`：RoundTripper 返网络错误、sleepFn 返回 context.Canceled，断言返回错误 `errors.Is(err, context.Canceled)` 且请求计数 == 1

  - 章节范围：§2.4 能力4（网络层重试退避）、§2.2（重试相关常量）、§3.1（重试次数与退避性能表）
