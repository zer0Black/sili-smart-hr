# 技术组件规格说明书

## 1. 概述

### 1.1 组件名称

会话日志集成（ConversationLog Integration）

### 1.2 组件描述

封装对兄弟系统 sili-smart-api 会话日志通道的只读消费：会话列表拉取、会话详情拼回两个 HTTP 客户端能力，统一承载 Bearer 集成密钥鉴权、网络层重试退避与错误分类，是 AI 使用能力评估全部对话数据的唯一入口。用户信息客户端（userapi）已随 P2_SYS_001 交付，不在本组件范围（见 1.3 边界说明）。

### 1.3 创建背景

sili-smart-hr 处于 sili-smart-api（LLM 网关）的数据下游，AI 使用能力底层 4 维与上层 4 维评分的唯一信号来源是 sili-smart-api 沉淀在 ClickHouse 的员工对话日志。本系统经集成密钥只读消费该数据源，对话原文不落本系统主数据库。

上游通道有几处必须屏蔽的复杂度：conversation_turns 采用增量存储（首轮存全量、后续轮存增量），消费方必须经详情接口把完整 messages 拼回；ClickHouse 中 id 恒为 0，业务标识以 request_id 为准，会话以 session_key 组织；对外接口的响应结构与本系统统一响应结构不同（{success, message, data} 而非 {code, message, data}）。评估引擎（T4 特征抽取、T5 活跃度统计）与配置域（F3 连通验证）都消费这份数据，若各自直连上游会重复实现鉴权、重试、解包与拼回逻辑，且密钥暴露面扩散。

为此把通道访问收敛为 integration 层的独立技术组件：一个会话日志客户端（列表 + 详情 + 探活），统一密钥注入、统一错误分类、统一重试退避，调用方只见 Go 接口。工程落点 integration/conversationlog，当前包内已有连通探活（Ping）的先行实现，本组件在其上补齐会话列表与详情拉取并固化完整契约。

**范围边界**：同通道的用户信息客户端（integration/userapi 的 ListStaffs，对接 /api/conversation-log/users）已随 P2_SYS_001 交付并被 staff service 消费，其契约以既有实现与 P2_SYS_001 规格为准，本组件不重复定义、不改动其代码。后续若 userapi 需要重试退避等增强，另立 RFC 变更。

### 1.4 技术栈

| 技术 | 版本 | 用途 |
|------|------|------|
| Go | 1.25 | 实现语言 |
| net/http（标准库） | — | HTTP 客户端，不引第三方 SDK |
| encoding/json（标准库） | — | 上游响应解包 |
| Wire | 编译时 DI | 客户端装配进依赖图 |
| slog | 标准库 | 结构化调用日志 |

## 2. 组件接口

### 2.1 能力清单

| 序号 | 能力名称 | 能力类型 | 说明 |
|------|---------|---------|------|
| 1 | 会话列表拉取 | 基础 | 按时间窗口与用户过滤分页拉取会话聚合元数据，跑批与活跃度统计的数据入口 |
| 2 | 会话详情拉取 | 基础 | 按 session_key 取单会话完整 messages 与逐轮元数据，全量不分页 |
| 3 | 连通探活 | 基础 | 用集成密钥探活会话日志通道，供大模型配置页连通验证复用 |
| 4 | 网络层重试退避 | 高级 | 网络错误与 5xx 自动重试，指数退避，确定性错误直通 |

> **能力类型说明**：基础=核心必需能力 | 高级=增强型能力 | 扩展=可选能力

### 2.2 输入定义

#### Props / 参数列表

客户端构造参数（NewClient）：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| baseURL | string | 是 | — | sili-smart-api 根地址（如 https://gw.example.com），来自 config.Integration.SmartAPIBaseURL，末尾斜杠容忍 |

方法级参数：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| ctx | context.Context | 是 | — | 超时与取消控制：列表/详情/探活分档超时（listTimeout / detailTimeout / pingTimeout），http.Client 不设全局 Timeout，重试的每次尝试独立派生超时子 ctx（见下方超时机制），父 ctx 取消立即中止请求与剩余重试 |
| secret | string | 是 | — | 集成密钥明文，由 service 层从 IntegrationSecret 解密后注入，本组件不涉解密、不持久化密钥 |
| listReq | ListSessionsRequest | 是 | — | 会话列表查询条件 |
| sessionKey | string | 是 | — | 会话详情的目标会话标识，取自列表接口返回值 |

ListSessionsRequest 字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| Username | string | 否 | 用户名过滤，对应上游 username 查询参数（精确匹配，见 3.2 既定事实表） |
| UserID | int | 否 | 上游列表接口按 username 过滤，UserID 供调用方按上游 user_id 二次筛选（内存过滤）。total 为上游口径，内存过滤后 len(items) 可能小于 total，翻页仍以 total 为准。注意：内存过滤后 len(items) 可能小于上游实返数（当页全为目标用户时相等），禁止用过滤后数量判断末页 |
| StartTime / EndTime | int64 | 否 | 时间窗口（Unix 秒），对应 start_timestamp / end_timestamp；时间过滤作用于轮次时间，窗口口径见 3.2 既定事实表 |
| Page / PageSize | int | 否 | 分页参数：Page 对应上游 p 查询参数，PageSize 对应 page_size，上游硬上限 100，组件层钳制到 100 |

> 上游列表接口另支持 token_name / model_name 过滤，按本系统「按人按时段拉取」的场景裁剪不暴露；需要时扩展 ListSessionsRequest 并透传对应查询参数。

#### 配置项说明

```go
// Client 结构定义（进程内 Go 组件，无 TypeScript 定义）
type Client struct {
    baseURL    string       // sili-smart-api 根地址，来自 config.Integration.SmartAPIBaseURL
    httpClient *http.Client // 承载超时与传输配置，由 NewClient 装配默认值
}

// 重试相关常量（包级，初版经验值，随跑批数据积累迭代）
const (
    maxRetries     = 3              // 网络层失败重试次数
    initialBackoff = 10 * time.Second // 指数退避初始值（架构文档 3.1.1）
    pingTimeout    = 5 * time.Second  // 单次探活请求超时（轻量值，与列表/详情区分）
    listTimeout    = 30 * time.Second // 单次列表请求超时（架构文档 3.1.1）
    detailTimeout  = 30 * time.Second // 单次详情请求超时（架构文档 3.1.1）
    maxBodySize    = 10 << 20        // 响应体上限 10MB，LimitReader 防上游超大响应 OOM
)
```

超时机制：httpClient 不设全局 Timeout（避免与探活 5s / 列表详情 30s 分档冲突），重试的每次 HTTP 尝试独立经 `context.WithTimeout(parentCtx, xxxTimeout)` 派生子 ctx 注入该次尝试的超时预算，下一次尝试重新获得完整预算（与 3.1 性能表的 30s × 4 次尝试口径一致），父 ctx 取消立即中止当前请求与剩余重试。

### 2.3 输出定义

#### Events / 返回值

| 方法名 | 参数 | 返回值 | 说明 |
|--------------|------|--------|------|
| ListSessions | ctx, secret, listReq | ([]SessionSummary, int64, error) | 会话聚合元数据列表与 total；空结果返回空切片非 nil |
| GetSessionDetail | ctx, secret, sessionKey | (*SessionDetail, error) | 单会话完整数据：聚合元数据 + 逐轮元数据 + 完整 messages |
| Ping | ctx, secret | error | 探活成功返 nil，失败带可读原因 |

领域模型（组件对外 DTO，全部为值类型，无雪花 ID 精度问题）：

```go
// SessionSummary 会话聚合元数据（列表接口 items 元素）
type SessionSummary struct {
    SessionKey    string // 会话标识，调详情的唯一凭据
    FirstTurnTime int64  // 窗口内首轮时间（Unix 秒）
    LastTurnTime  int64  // 窗口内末轮时间（Unix 秒）
    TurnCount     int    // 窗口内轮次数
    TokenName     string // 调用令牌名
    Username      string // 用户名（人员标识）
    UserID        int    // 上游用户 ID
    ModelName     string // 模型名
}

// SessionDetail 会话详情（详情接口 data）
type SessionDetail struct {
    Session  SessionSummary  // 会话聚合元数据，字段同列表
    Turns    []TurnMeta      // 逐轮元数据，全量不分页
    Messages []Message       // 完整对话序列，按时间升序，全量不分页
}

// TurnMeta 逐轮元数据：id（查询侧回填的会话内连续序号）、created_at、request_id（业务标识）、turn_kind
type TurnMeta struct {
    ID        int    // 会话内连续序号，从 1 起（上游查询侧按序回填；ClickHouse 存储层 id DEFAULT 0），非全局唯一，业务标识用 RequestID
    CreatedAt int64  // 轮次时间（Unix 秒）
    RequestID string // 请求级业务标识
    TurnKind  string // first / normal / tool_round
}

// Message 完整对话消息
type Message struct {
    Role string // user / assistant / tool / system
    Kind string // text / tool_use / tool_result
    Text string // text 存原文；tool_use 存「工具名 args=字节数」；tool_result 存「工具名 result=字节数」元信息
}
```

> 人员标识到人名映射（Staff）由 integration/userapi 承载，已随 P2_SYS_001 交付，本组件不重复定义。

#### 错误码定义

组件层错误（Go sentinel error，供 errors.Is 分类，非 HTTP 错误码）：

| 错误码 | 说明 | 处理建议 |
|--------|------|---------|
| ErrNotConfigured | baseURL 未配置（空串） | 检查 config.Integration.SmartAPIBaseURL，属部署配置缺失。注意：config 对空值注入默认 http://localhost:8081（见 4.3），标准 Wire 装配下本错误不可达，仅测试路径或绕过 config 的直接构造可触发；生产漏配地址的实际表现是请求发往默认地址后 ErrNetwork 重试耗尽 |
| ErrUnauthorized | 401/403 | 确定性错误，不重试；按状态码分流（见 6.4 问题1）：401 为本侧密钥错误，到大模型配置页检查集成密钥；403 为上游未配置 CONVERSATION_LOG_INTEGRATION_KEY 的服务端问题，联系上游部署方 |
| ErrUpstreamBusiness | HTTP 200 但 success=false（记录不存在、上游内部错误等） | 读 UpstreamError.Msg 字段定位；记录不存在经 IsNotFound() 白名单识别后按业务空处理，见下方「记录不存在识别」 |
| ErrBadRequest | 400 参数非法（分页越界、时间范围倒置等） | 确定性错误，不重试；检查调用参数构造 |
| ErrNetwork | 网络不可达、超时、5xx（重试耗尽后） | 已重试 3 次仍失败，交由调用方降级；会话级失败按降级保留统计处理 |
| ErrRateLimited | 429 限流（重试耗尽后） | 瞬时错误，语义同 ErrNetwork 走指数退避重试（至多 3 次），耗尽后返回交调用方 error 通道；上游或中间网关限流时批量请求集中命中，与确定性错误的整批终态化分流（评审修订：原归 ErrUnexpectedStatus 兜底桶会让限流期间的批量会话误落终态） |
| ErrDecode | JSON 解析失败或响应体超 10MB | 带上游原始信息记日志排查，视为该次拉取失败 |
| ErrUnexpectedStatus | 其余非 2xx（404 等未明确分类状态码） | 兜底桶，确定性错误不重试；带状态码记日志排查 |

错误分类与重试的关系：ErrUnauthorized、ErrBadRequest、ErrUpstreamBusiness、ErrUnexpectedStatus 为确定性错误，首次出现即直通返回，不消耗重试；ErrNetwork（网络错误、5xx）与 ErrRateLimited（429 限流）为瞬时错误，按指数退避重试至多 3 次，耗尽后返回。所有错误经 fmt.Errorf 包装保留原始原因链，调用方可 errors.Is 精确分类。

ErrUpstreamBusiness 的载体是 `*UpstreamError`（实现 `Unwrap() error` 返回哨兵 `ErrUpstreamBusiness`，携带 `Msg string` 字段为上游 message 与 `IsNotFound() bool` 白名单判定方法），调用方经类型断言 `errors.As(err, &ue)` 读 Msg 或判定记录不存在：

```go
var ue *conversationlog.UpstreamError
if errors.As(err, &ue) {
    // ue.Msg 携带上游 message（i18n 文案，语言随请求 Accept-Language 而定）
}
```

**记录不存在识别**：上游对不存在的 session_key 返回 HTTP 200 + success=false，message 为 i18n 文案（zh-CN「会话不存在」、en「conversation not found」，无 Accept-Language 头时上游回退英文），无机器可读错误码。识别收敛在 `UpstreamError.IsNotFound()`：Msg 命中白名单（「会话不存在」「conversation not found」及其大小写变体，覆盖中英两语言）即判定记录不存在，调用方按业务空处理；未命中按会话级失败处理。此方案与上游文案耦合，上游文案变更会让记录不存在被多计为会话失败（兜底方向安全：不漏数据、只污染失败率统计），根治路径是上游为业务错误增加机器可读 code 字段，届时替换白名单实现、契约不变。

### 2.4 能力详细说明

#### 能力1: 会话列表拉取

**描述**: 调用 GET {baseURL}/api/conversation-log/，按时间窗口与用户名过滤分页拉取会话聚合元数据。周期批量评估跑批启动时按本周期区间拉全员列表；活跃度统计只消费此接口的元数据（user_id、last_turn_time、session_key、turn_count，时间口径以末轮时间为准），不取详情正文；手动定向分析按选定人员与时段拉取。结果按末轮时间倒序（上游行为）。

**接口定义**:
```go
// ListSessions 拉取会话聚合列表。
// 时间过滤的窗口口径、username 精确匹配语义见 3.2 既定事实表。
// PageSize 钳制到上游上限 100；UserID 非 0 时在内存中按 user_id 二次过滤，翻页终止警示见 2.2 参数表 UserID 行。
func (c *Client) ListSessions(ctx context.Context, secret string, req ListSessionsRequest) (items []SessionSummary, total int64, err error)
```

**调用示例**:
```go
// 周期跑批：拉取本周窗口内全员会话列表
items, total, err := cl.ListSessions(ctx, secret, conversationlog.ListSessionsRequest{
    StartTime: weekStart.Unix(),
    EndTime:   weekEnd.Unix(),
    Page:      1,
    PageSize:  100,
})
if err != nil {
    if errors.Is(err, conversationlog.ErrNetwork) {
        // 重试耗尽，交由 T6 fallback 降级标记，当期评估照常推进
    }
    return err
}
for p := 2; int64((p-1)*100) < total; p++ {
    // 翻页直至覆盖 total
}
```

**注意事项**:
- total 是上游按过滤条件统计的会话总数，翻页循环以 total 为准；UserID 内存过滤生效时实返数判断不可用，完整警示见 2.2 参数表 UserID 行
- 首末轮时间与轮数是窗口内统计值，跨窗口聚合活跃度时须按窗口边界对齐（同一会话横跨窗口边界时会被两个窗口各计一次）。对齐规则（如按 last_turn_time 归属单一窗口或按 session_key 去重合并）由 T5 活跃度统计规格定义，本组件只保证窗口口径可追溯
- 上游按末轮时间倒序返回，依赖顺序的调用方需自行确认

#### 能力2: 会话详情拉取

**描述**: 调用 GET {baseURL}/api/conversation-log/{session_key}，返回单会话完整数据：聚合元数据、逐轮元数据（turns）、完整对话序列（messages）。conversation_turns 在上游是增量存储，本接口返回的是上游已拼回的全量 messages，消费方直接按序消费即可。全量返回不分页，超长会话受 10MB 响应体上限保护。

**接口定义**:
```go
// GetSessionDetail 拉取单会话完整详情。
// sessionKey 必须来自列表接口返回值，不得凭空构造。
// messages 按时间升序，role/kind/text 三字段；工具调用只有元信息（工具名与字节数），原始载荷不落上游库。
func (c *Client) GetSessionDetail(ctx context.Context, secret string, sessionKey string) (*SessionDetail, error)
```

**调用示例**:
```go
// T4 特征抽取：逐会话取详情喂给 LLM
detail, err := cl.GetSessionDetail(ctx, secret, item.SessionKey)
if err != nil {
    // 会话级失败：返回带 session_key 的错误，由 T6 fallback 落待重试，重试耗尽降级保留统计
    return fmt.Errorf("session %s: %w", item.SessionKey, err)
}
for _, msg := range detail.Messages {
    // 原文仅在内存临时持有，抽取完成后丢弃，不持久化（隐私架构）
}
```

**注意事项**:
- 对话原文只在 T4 特征抽取阶段临时读入内存，抽取产出脱敏特征档案后即丢弃，本组件与调用方都不得把原文写入主数据库或日志
- 工具消息（tool_use / tool_result）的 text 是「工具名 args=字节数」元信息，无原始参数与结果内容；args 字节数在流式与非流式路径可能有口径偏差，属上游已知行为，不做归一化
- 单会话失败只影响该会话，调用方须逐会话隔离错误，禁止让单个会话失败中断整批。整批终止的例外仅限三类确定性配置/参数错误：ErrUnauthorized（密钥无效）、ErrNotConfigured（地址缺失）、ErrBadRequest（参数构造缺陷，整批同源），其余错误（含 ErrNetwork 重试耗尽、ErrUnexpectedStatus）一律会话级隔离（见能力5）

#### 能力3: 连通探活

**描述**: 调用 GET {baseURL}/api/conversation-log/?p=1&page_size=1，以最小请求量探活会话日志通道并校验集成密钥有效性。大模型配置页集成密钥卡片的「连通验证」按钮经 service 层调用本能力，2xx 即连通成功。当前 Ping 实现已交付，本组件契约将其纳入并保持行为不变（现行代码探活请求为 /api/conversation-log?page=1&page_size=1，与契约存在两处偏差：参数名 page 应为 p、路径缺尾斜杠，属待修正项，本契约以 /api/conversation-log/?p=1&page_size=1 为准）。

**接口定义**:
```go
// Ping 探活会话日志通道：2xx 成功；401/403 密钥无效；超时/网络错误不可达；其余非 2xx 接口异常。
func (c *Client) Ping(ctx context.Context, secret string) error
```

**调用示例**:
```go
if err := cl.Ping(ctx, secret); err != nil {
    // service 层映射 errcode.IntegrationSecretTestFailed(1304)，message 透传可读原因
}
```

**注意事项**:
- 只覆盖集成密钥对会话日志通道的探活，不对 LLM 模型做连通验证（LLM 连通性在评估引擎实际调用时校验）
- 探活请求 timeout 用轻量值 pingTimeout = 5 秒，与列表/详情的 30 秒区分

#### 能力4: 网络层重试退避

**描述**: 列表与详情请求的传输层韧性。网络错误（连接拒绝、DNS 失败、超时）与 5xx 按指数退避自动重试：初始 10 秒、倍增、至多 3 次；401/403、400、success=false 等确定性错误直通返回不重试。重试在组件内部完成，调用方感知的是最终结果。

**接口定义**:
```go
// 内部机制，无独立公开方法。doWithRetry 包装单次 HTTP 执行：
// retryable := 网络错误 || HTTP 5xx
// backoff := initialBackoff << attempt（10s → 20s → 40s）
// reqFn 形参携带 context.Context：每次尝试须用新派生的超时子 ctx 重建请求
//（§2.2 超时机制，WithTimeout 派生的 ctx 不可跨尝试复用），timeout 为该次尝试的超时预算。
func (c *Client) doWithRetry(ctx context.Context, timeout time.Duration, reqFn func(context.Context) (*http.Request, error)) (*http.Response, error)
```

**调用示例**:
```go
// 调用方无感知，重试日志自动输出：
// WARN conversationlog request retrying method=GET path=/api/conversation-log/ attempt=1 backoff=10s
```

**注意事项**:
- 可重试与确定性错误的完整分类矩阵见 2.3「错误分类与重试的关系」，此处不重复定义；本能力只承载重试机制特有信息（退避序列、ctx 中止、重试日志）
- ctx 取消时立即中止，不继续剩余重试
- 退避等待期间不占外部资源，仅 sleep；跑批并发下多个 worker 同时退避属预期行为，上游容量由 Asynq worker 并发度约束

#### 能力5: 错误分类

**描述**: 把上游三类失败形态（HTTP 401/403、HTTP 200 + success=false、网络/5xx）与参数错误、解码错误统一收敛为 2.3 节定义的 sentinel error。分类结果是降级决策的输入：确定性错误（密钥无效、参数非法）重试无益，直接上报配置问题；可重试错误耗尽后由调用方按会话级降级处理。与现有 integration_secret service 的 errcode 映射（1304）衔接。

**接口定义**:
```go
// 调用方分类示例：
if errors.Is(err, conversationlog.ErrUnauthorized) {
    // 密钥问题：提示配置页，整批停止（密钥无效重试无意义）
}
if errors.Is(err, conversationlog.ErrNetwork) {
    // 网络/上游过载：该会话降级保留统计，当期照常推进
}
```

**调用示例**:
```go
items, _, err := cl.ListSessions(ctx, secret, req)
switch {
case err == nil:
case errors.Is(err, conversationlog.ErrUnauthorized):
    return fmt.Errorf("集成密钥无效，请到大模型配置页检查: %w", err)
case errors.Is(err, conversationlog.ErrNetwork):
    // 会话级降级路径
}
```

**注意事项**:
- 错误消息禁止携带集成密钥明文与对话原文，只携带状态码、路径、session_key 等定位信息
- ErrUpstreamBusiness 的记录不存在场景由 UpstreamError.IsNotFound() 白名单识别，调用方按业务空处理，与通道故障区分（识别机制与脆弱性说明见 2.3）

### 2.5 使用示例

> 本节示例是组件契约的消费演示：证明接口设计与错误分类可用、供 T4/T5/T6 消费方参考调用方式。示例中的跑批循环、FailedSession 结构、service 层封装均非本组件交付物，生产实现分别归 pipeline（T6 规格）与消费方 feature，届时以各自规格为 SSOT。

#### 基础用法

```go
// 构造客户端（Wire 装配，baseURL 来自 config.Integration.SmartAPIBaseURL）
cl := conversationlog.NewClient(cfg.Integration.SmartAPIBaseURL)

// 拉取某用户某时段会话列表
items, total, err := cl.ListSessions(ctx, secret, conversationlog.ListSessionsRequest{
    Username:  "user1",
    StartTime: start.Unix(),
    EndTime:   end.Unix(),

    PageSize:  100,
})
```

#### 高级用法

```go
// 周期跑批主循环：列表翻页 + 逐会话详情 + 错误分类（整批终止 / 业务空跳过 / 会话级隔离）
func pullWeekSessions(ctx context.Context, cl conversationlog.Client, secret string, start, end time.Time) ([]conversationlog.SessionDetail, []FailedSession) {
    var details []conversationlog.SessionDetail
    var failures []FailedSession
    // 整批终止：三类确定性配置/参数错误，重试无意义（见 2.4 能力2 注意事项）
    batchAbort := func(err error) ([]conversationlog.SessionDetail, []FailedSession) {
        return details, append(failures, FailedSession{Scope: "batch", Err: err})
    }
    page := 1
    for {
        items, total, err := cl.ListSessions(ctx, secret, conversationlog.ListSessionsRequest{
            StartTime: start.Unix(), EndTime: end.Unix(),
            Page: page, PageSize: 100,
        })
        if err != nil {
            if errors.Is(err, conversationlog.ErrUnauthorized) ||
                errors.Is(err, conversationlog.ErrNotConfigured) ||
                errors.Is(err, conversationlog.ErrBadRequest) {
                return batchAbort(err) // 密钥无效等：停止整批，不继续翻页与详情
            }
            // 其余错误（网络重试耗尽等）：整页降级记录（页码与窗口）后终止翻页，已拉取页照常进入详情
            failures = append(failures, FailedSession{Scope: fmt.Sprintf("page:%d", page), Err: err})
            break
        }
        for _, it := range items {
            d, err := cl.GetSessionDetail(ctx, secret, it.SessionKey)
            if err != nil {
                if errors.Is(err, conversationlog.ErrUnauthorized) ||
                    errors.Is(err, conversationlog.ErrNotConfigured) ||
                    errors.Is(err, conversationlog.ErrBadRequest) {
                    return batchAbort(err) // 同源参数缺陷或密钥失效，继续只会整批失败
                }
                var ue *conversationlog.UpstreamError
                if errors.As(err, &ue) && ue.IsNotFound() {
                    continue // 记录不存在按业务空处理，不落降级标记（见 2.3 记录不存在识别）
                }
                failures = append(failures, FailedSession{SessionKey: it.SessionKey, Err: err})
                continue // 其余错误（含 ErrNetwork 重试耗尽）会话级隔离，继续下一会话
            }
            details = append(details, *d)
        }
        // 翻页终止以 total 与实返数双重判断（见 2.4 能力1 注意事项）。
        // UserID 内存过滤生效时实返数判断不可用，警示见 2.2 参数表 UserID 行
        if int64(page*100) >= total || len(items) < 100 {
            break
        }
        page++
    }
    return details, failures
}
```

#### 完整示例

```go

    secret, err := s.secretRepo.GetDecryptedSecret(ctx) // IntegrationSecret AES-256-GCM 解密

        return nil, s.newError(errcode.IntegrationSecretNotConfigured) // 1303

        s.markFailedSessions(ctx, failures) // 交 T6 fallback 落降级标记
    }
    return details, nil
}
```

## 3. 技术约束

### 3.1 性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 单次列表请求超时 | 30 秒 | 架构文档 3.1.1 约定，经 context.WithTimeout 注入，ctx 取消立即中止 |
| 单次详情请求超时 | 30 秒 | 同上；详情全量返回，超长会话受 10MB 响应体上限保护 |
| 单次探活超时 | 5 秒（pingTimeout 常量） | 轻量请求，配置页交互即时反馈 |
| 重试次数 | 至多 3 次 | 仅网络错误与 5xx；指数退避 10s → 20s → 40s |
| 响应体上限 | 10MB | io.LimitReader 防上游异常超大响应 OOM |
| 单会话拉取总时长上界 | 约 3.2 分钟 | 120s 请求预算（30s × 4 次尝试）+ 70s 退避等待（10s+20s+40s）最坏情形；跑批以会话为粒度并行，单会话慢不阻塞他人 |
| 并发度 | 组件自身不限流 | 拉取并发由 Asynq worker 并发度约束（架构 3.1.2：worker 只控任务并行度），组件保持无状态可并发调用 |

### 3.2 兼容性要求

#### 版本兼容性

| 依赖 | 版本要求 |
|------|---------|
| sili-smart-api 会话日志接口 | 对话内容记录查询 API（P1_TECH_001_TECH_对话内容记录）现行契约：列表 /api/conversation-log/、详情 /api/conversation-log/:session_key、用户字典 /api/conversation-log/users |
| Go | 1.25（与 hr-backend 一致） |
| CGO | 无依赖，net/http 纯标准库，兼容 CGO_ENABLED=0 静态编译 |

#### 上游契约既定事实（消费方必须知晓）

| 事实 | 影响 |
|------|------|
| conversation_turns 增量存储（首轮全量、后续增量），详情接口已拼回 | 消费方拿到的 messages 即完整对话，无需自行拼接 |
| 详情 turns 的 id 为查询侧回填的会话内连续序号（从 1 起，存储层 DEFAULT 0），业务标识以 request_id 为准 | Turns.ID 可作展示序号，禁止用作全局业务键 |
| 会话以 session_key 组织 | 详情拉取唯一凭据，必须来自列表返回值 |
| 列表时间过滤作用于轮次时间，首末轮与轮数为窗口内统计 | 跨窗口活跃度聚合须按窗口对齐（见 2.4 能力1 注意事项） |
| 工具消息仅存元信息（工具名 + 字节数），原始载荷不落库 | 特征抽取对工具使用的分析只能基于元信息，PRD 已知边界 |
| 上游响应结构 {success, message, data}，与本系统 {code, message, data} 不同 | 解包逻辑收敛在本组件，禁止扩散到 service 层 |
| username 过滤为精确匹配（上游实现 username = ?，非模糊匹配），p 为页码参数名 | Username 过滤传全量用户名才能命中；分页参数名禁用 page |

### 3.3 安全要求

| 安全项 | 要求 | 实现方式 |
|--------|------|---------|
| 密钥不落组件 | 客户端不持久化、不缓存集成密钥 | secret 由 service 层逐次注入（解密后明文仅存于调用栈），组件内只经 Authorization 头透传 |
| 密钥不出日志 | 任何日志与错误消息禁止携带密钥明文 | slog 只记 method、path、status、session_key、耗时、重试次数 |
| 对话原文不落库 | 原文仅在调用栈内存中临时持有 | 组件返回的 SessionDetail 由调用方（T4）抽取特征后丢弃，禁止写入主数据库、日志、缓存 |
| 传输安全 | 生产环境 baseURL 须为 https | 部署配置约束，组件不强校验但文档约定 |
| 只读消费 | 组件只发起 GET 请求 | 不提供任何写操作方法，上游通道单向只读 |

## 6. 监控与运维

### 6.1 日志规范

| 日志级别 | 使用场景 | 示例 |
|---------|---------|------|
| DEBUG | 单次请求成功明细 | conversationlog request completed method=GET path=/api/conversation-log/ status=200 duration=1.2s |
| INFO | 跑批量级汇总 | conversationlog pull summary window=2026-08-10~2026-08-16 sessions=320 failed=3 retries_total=12 |
| WARN | 重试进行中 | conversationlog request retrying method=GET path=/api/conversation-log/conv_x attempt=1 backoff=10s |
| ERROR | 重试耗尽、确定性失败 | conversationlog request failed method=GET path=/api/conversation-log/conv_x code=network status=503 retries=3 |

日志字段约束：只记 method、path、status、session_key、duration、attempt、backoff、retries、code；禁止记集成密钥明文与对话原文（Message.Text 任何形式不得进日志）。

### 6.2 监控指标

| 指标名称 | 指标类型 | 说明 | 告警阈值 |
|---------|---------|------|---------|
| 会话拉取成功率 | 比率 | 成功会话数 / 拉取会话总数（按周期） | < 90%（对齐架构文档失败比例告警阈值 10%） |
| 重试发生次数 | 计数 | 周期内网络层重试总次数，反映上游稳定性 | 周期内 > 会话数 × 1.5 时关注 |
| 单会话拉取耗时 | 分布 | ListSessions / GetSessionDetail 的 P95 耗时 | P95 > 25s（逼近 30s 超时） |
| ErrUnauthorized 次数 | 计数 | 密钥失效信号，出现即说明配置有问题 | > 0 即处理 |

### 6.3 告警规则

| 告警名称 | 触发条件 | 严重程度 | 处理建议 |
|---------|---------|---------|---------|
| 拉取失败率超阈 | 单周期会话拉取失败率 ≥ 10% | 高 | 经工作台待处理项呈现（T6 fallback 信号链），运营决定是否触发定向补跑 |
| 集成密钥失效 | 任一请求返回 ErrUnauthorized | 高 | 到大模型配置页核对集成密钥并更新，必要时上游侧确认 CONVERSATION_LOG_INTEGRATION_KEY 配置 |
| 上游持续不可达 | 连续 2 个周期 ErrNetwork 占比 > 50% | 中 | 检查 sili-smart-api 服务状态与网络链路，跑批自动降级保留统计。周期数为初版经验值，权威定义归 T6 规格 |

### 6.4 故障排查

#### 常见问题

**问题1: 连通验证失败但密钥确认无误**
- 现象: 配置页连通验证报密钥无效或不可达
- 原因: 403 是上游未配置 CONVERSATION_LOG_INTEGRATION_KEY（服务端问题），401 才是本侧密钥错误；不可达则查 baseURL 与网络
- 解决: 按 401/403/超时三分支定位：401 换密钥，403 联系 sili-smart-api 部署方，超时查 config.Integration.SmartAPIBaseURL 与链路

**问题2: 跑批期大量会话拉取失败**
- 现象: 周期汇总 failed 占比高，触发工作台告警
- 原因: 上游过载（5xx/超时重试耗尽）或网络抖动
- 解决: 看 WARN 重试日志的 status 分布确认上游侧；本侧等降级机制兜底（当期照常推进），运营经手动定向分析入口补跑

**问题3: 会话数与预期不符**
- 现象: 列表 total 少于预期
- 原因: 列表时间过滤的窗口口径见 3.2 既定事实表；翻页期间新会话写入导致 total 漂移
- 解决: 核对窗口边界与轮次时间口径；翻页以 total 与实返数双重收敛（2.4 能力1）

**问题4: 响应体超限报 ErrDecode**
- 现象: 个别会话详情拉取失败，日志提示 body too large
- 原因: 单会话 messages 超 10MB 上限（极端长会话）
- 解决: 属预期保护；若高频出现，评估上调 maxBodySize 或与上游协商分片，单会话降级保留统计不阻塞跑批
