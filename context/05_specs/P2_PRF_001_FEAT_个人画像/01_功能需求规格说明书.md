# 个人画像 功能需求规格说明书

## 文档信息

- 基线 Feature：无
- 变更组：无
- 变更根节点：无
- 历史基线链：无

## 1. 概述

### 1.1 功能背景

sili-smart-hr 的评估引擎已全线贯通：F6 周期批量评估跑批（P2_ASM_001）把对话日志周期性转化为使用活跃度统计（activity_stats）、维度评分（dimension_scores）与聚合结果（aggregate_scores），F7 主动测试评估运营（P2_TST_001）叠加 AI 管理能力 5 子能力评分（source=active_test 落 dimension_scores）与九型判型（assessment_test_results）。这些数据已在库里，但没有任何消费界面：运营人员看不到每个人的能力结构、短板结论与历史趋势，能力盘点与培训提升的业务闭环停在数据层。

本 feature 是 PRD 5.2.2 中 F9（个人画像）的对应交付项，建人员画像列表与个人画像详情两个只读页面，把上游产出汇聚为个人能力全景。定位是纯只读消费域：本 feature 不产生任何新评分、不调 LLM、不改上游数据，全部数据来自已落库的四张表与上游人员名单。

### 1.2 本功能业务目标

1. 画像可查：运营人员通过姓名、活跃度、短板维度筛选定位人员，一屏掌握全员活跃度基线与两模块总分态势。
2. 全景可见：个人画像详情呈现多维能力雷达（使用 8 维 + 管理 5 子能力）、评分卡与较上期变化、九型判型参考、维度明细逐层下钻到解读与脱敏证据来源，服务评分可解释诉求。
3. 趋势可追：评估区间切换与维度近若干期走势支撑运营人员对比历史分数追踪个人进步。
4. 名单可导：按当前筛选条件导出人员名单 xlsx，支撑能力盘点汇报场景。

### 1.3 与 PRD 拆分的对应关系

本 feature 即 PRD 5.2.2 的 F9（个人画像），承载个人画像模块的画像查询与画像详情两个功能点，外加对外接口模块的画像数据接口（预留）功能点。画像数据接口按需求沟通决策为规格预留：本规格第 5.3 节定义接口契约，首期不实现、不占用开发任务，后续外部系统对接时按契约直接开发。团队看板下钻个人时跳转本模块详情页，看板本身归 F10；工作台聚合态势归 F11。

## 3. 页面与功能总览

### 3.1 页面清单

| 序号 | 页面名称 | 页面形式 | 职责说明 | 包含功能 |
|-----|---------|---------|---------|---------|
| 1 | 人员画像列表页 | 独立页面（挂顶栏「结果洞察」二级菜单「人员画像」） | 全员画像检索与定位：按筛选条件查人，展示活跃度与两模块总分态势，点击进入详情 | 人员筛选查询、查看画像跳转、导出名单 |
| 2 | 个人画像详情页 | 独立页面（路由携带人员标识参数） | 单人能力全景：概览、核心结论、评分卡、能力雷达与维度明细、九型参考 | 评估区间切换、能力 tab 切换、维度明细展开（解读/走势/证据来源）、返回列表 |

**页面形式说明：**
- 两页面均为独立路由页面，挂 `_authenticated` 布局。
- 团队看板（F10）下钻个人时跳转本详情页，跳转入口归 F10 定义。

### 3.2 页面跳转流程

```
[入口：顶栏「结果洞察 → 人员画像」] → [人员画像列表页]
    ├── 点击行或行内「查看画像」→ [个人画像详情页]
    └── 点击「导出名单」→ 留在本页，浏览器下载 xlsx
[个人画像详情页]
    ├── 点击「返回列表」→ [人员画像列表页]（浏览器历史返回）
    └── 切换评估区间下拉 → 留在本页，整页数据按所选区间刷新
```

**流程说明：**
1. 运营人员从顶栏进入人员画像列表页，页面加载全员名单与画像概要。
2. 通过姓名、活跃度、短板维度筛选与仅看未使用开关定位目标人员。
3. 点击行或「查看画像」进入个人画像详情页，查看该人能力全景。
4. 详情页通过评估区间下拉切换历史期次，通过维度行展开查看解读、走势与证据来源。
5. 「返回列表」经浏览器历史返回列表页；无历史（如从团队看板直入）时回列表页兜底。

## 4. 页面功能详细说明

### 4.1 页面 1：人员画像列表页

#### 4.1.1 页面概述

**页面形式：**独立页面，挂 `_authenticated` 顶栏「结果洞察」一级菜单下的「人员画像」二级菜单。

**页面职责：**全员画像的检索与定位入口。运营人员在此按条件筛人、纵览活跃度与两模块总分态势、点击进入单人详情。人群口径为全员：名单实时拉取 sili-smart-api 用户体系（上游 userapi 客户端），画像数据按人左联补齐，未参与任何评估的人也入列表（显示待评估态），支撑「谁还没被盘到」的盘点场景。

#### 4.1.2 涉及字段

##### A. 查询字段（列表页专用）

| 字段名称 | 字段类型 | 数据来源 | 默认值 | 业务含义 |
|---------|---------|---------|--------|--------|
| 姓名 | 文本 | 用户输入 | 空 | 按姓名包含匹配（子串），前端去首尾空格后提交 |
| 活跃度 | 下拉单选 | 系统预设 | 全部 | 活跃/低频/未使用 三态筛选，空为全部；取本期（最新已落库周期）活跃分级 |
| 短板维度 | 下拉单选 | 数据库（维度配置启用维度） | 全部 | 按选定维度筛「该维度为本期相对短板」的人；选项为使用 8 维与管理 5 子能力并集，动态读维度配置 |
| 仅看未使用 | 开关 | 用户输入 | 关 | 开启时列表仅显示本期活跃分级为未使用的人，与活跃度筛选叠加时以未使用为准 |

##### B. 显示字段

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 业务含义 |
|---------|---------|---------|---------|--------|
| 姓名 | 文本 | 上游 userapi（人名） | 页面加载、查询 | 人员标识到人名的映射，列表主列 |
| 活跃度 | 标签 | 数据库（activity_stats 最新周期行） | 页面加载、查询 | 活跃/低频/未使用 三态标签，无数据行显示未使用（依据见 4.1.4 规则2） |
| AI 使用能力 | 分数 | 数据库（aggregate_scores 最新周期 AI_USAGE 模块行） | 页面加载、查询 | 本期 AI 使用能力模块分，降权时分数旁带警示图标与悬浮说明 |
| AI 管理能力 | 分数 | 数据库（aggregate_scores 最新周期 AI_MGMT 模块行） | 页面加载、查询 | 本期 AI 管理能力模块分；无主动测试评分行显示「待评估」 |
| 九型主型 | 标签 | 数据库（assessment_test_results 最新判型行） | 页面加载、查询 | 九型主型名称标签，无判型行显示 - |
| 操作 | 按钮 | - | - | 行内「查看画像」入口，见 4.1.3 |

#### 4.1.3 功能与按钮

**用户可操作功能：**

- **人员筛选查询**
  - 触发按钮：查询（页面级）、重置（页面级）
  - 按钮位置：筛选区右侧
  - 权限要求：已登录平台账号
  - 功能说明：按查询字段组合查询，查询后分页回到第 1 页；重置清空全部条件后重新查询。姓名回车即触发查询；活跃度、短板维度下拉切换与仅看未使用开关切换后即时触发查询。

- **查看画像**
  - 触发按钮：行内「查看画像」链接按钮、整行点击
  - 按钮级别：行级
  - 权限要求：已登录平台账号
  - 功能说明：携带人员标识跳转个人画像详情页。

- **导出名单**
  - 触发按钮：导出名单（页面级）
  - 按钮位置：列表区右上工具栏
  - 权限要求：已登录平台账号
  - 加载状态：点击后至文件开始下载前显示 loading
  - 功能说明：按当前筛选条件导出 xlsx，字段与列表显示字段一致（姓名、活跃度、AI 使用能力、AI 管理能力、九型主型），导出全部命中行（分页不截断）；文件命名 `人员画像名单_YYYYMMDD.xlsx`；未设置筛选条件时导全员。数值缺失时导出空串，不含降权标记与警示图标等展示态。列表处于错误态时导出按钮禁用；导出请求失败提示通用错误文案，不产出文件。

**前端自动流程（如有）：**

- **页面加载自动查询**
  - 触发时机：进入页面
  - 说明：按当前筛选条件（初始为空）自动发起一次列表查询，无需手动点查询。

#### 4.1.4 业务规则

- **规则1：人群口径与数据联接**
  - 规则描述：列表人群为全员，名单实时拉取上游用户体系，画像数据按人员标识左联补齐。
  - 约束说明：上游名单不可用时页面显示错误态与重试入口，不展示任何缓存或降级名单；不允许降级为仅本系统有数据者，防止运营误读为全员规模。

- **规则2：缺失值口径**
  - 规则描述：活跃度无 activity_stats 行时按未使用显示；AI 使用能力 / AI 管理能力无聚合行时显示「待评估」；九型无判型行时显示 -。
  - 约束说明：待评估与 - 按 8.3 通用空值口径延伸，不把缺失渲染为 0 分。

- **规则3：降权标注口径**
  - 规则描述：模块内任一维度评分行 insufficient=true 或 status=failed 时，该模块总分旁展示降权警示图标，悬浮说明「对话数据不足，该总分已降权处理」；管理能力模块降权说明为「部分子能力因作答数据不足降权」。failed 行视为该维度数据无效，聚合侧已剔除，列表沿用聚合结果口径。
  - 触发条件：模块内存在 insufficient 或 failed 维度行。
  - 约束说明：警示只作标注，不改分数值。

- **规则4：短板维度筛选口径**
  - 规则描述：某人的短板维度集合为本期参与聚合的维度中分数最低的维度（并列时全部入选）；筛选选定维度 D 时，仅 D ∈ 该人短板集合的人命中。
  - 约束说明：无任何维度评分行的人不属于任何短板集合，全维度待评估者在任何短板维度筛选下都不命中；九型维度不参与短板筛选。

- **规则5：列表数据时点**
  - 规则描述：列表的总分与活跃度取各数据项各自最新已落库周期的数据，不按评估区间切换；定向批次与周期批次窗口可能错位（见 4.2.4 规则1），AI 使用能力与 AI 管理能力两模块的聚合行最新周期可能不同，各列分别取各自最新周期行；周期切换能力在详情页提供。
  - 约束说明：列表页查询字段不设区间条件。

#### 4.1.5 交互逻辑

- 空状态区分：无任何筛选时提示「暂无人员数据」（上游名单为空或不可用）；有筛选条件时提示「未找到匹配人员，请尝试调整筛选条件」。
- 分页：沿用 8.3 通用分页，默认 10 条/页，可选 10/20/30。
- 行可点击：整行 cursor 为 pointer，点击整行等价于点「查看画像」。
- 上游不可用错误态：名单拉取失败时列表区显示错误占位与「重试」按钮，重试重新发起整页查询。

### 4.2 页面 2：个人画像详情页

#### 4.2.1 页面概述

**页面形式：**独立页面，路由携带人员标识参数，挂 `_authenticated` 布局；入口为列表页点击与团队看板（F10）下钻。

**页面职责：**单人能力全景的呈现。自上而下依次为人物概览条、核心结论、能力分析（评分卡 + 双 tab 雷达 + 维度明细）、九型人格参考区。运营人员在此从总分到维度逐层下钻，理解一个人的能力结构、短板结论与培训方向，并通过评估区间切换追踪历史趋势。

#### 4.2.2 涉及字段

##### A. 人物概览条（页面加载时按人员与区间获取）

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 业务含义 |
|---------|---------|---------|---------|--------|
| 姓名 | 文本 | 上游 userapi | 页面加载 | 人员人名 |
| 活跃度 | 标签 | 数据库（activity_stats 所选区间行） | 页面加载、切区间 | 活跃/低频/未使用 |
| 九型主型 | 标签 | 数据库（assessment_test_results） | 页面加载 | 参考展示，最新判型不随区间变化 |
| 当前区间 | 文本 | 数据库（该人已落库周期列表） | 页面加载 | 所选评估区间与起止日期，本期标注「本期」 |

##### B. 能力评分卡（两块，按所选区间获取）

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 业务含义 |
|---------|---------|---------|---------|--------|
| AI 使用能力总分 | 数字+等级标签 | 数据库（aggregate_scores AI_USAGE 行） | 页面加载、切区间 | 0-100 分与优秀/良好/中等/待提升等级 |
| AI 管理能力总分 | 数字+等级标签 | 数据库（aggregate_scores AI_MGMT 行） | 页面加载、切区间 | 同上，无行显示待评估 |
| 较上期变化 | 数字（±分值） | 计算（本期减上一期聚合行） | 页面加载、切区间 | 上升/下降/持平箭头，任一期缺失不显示 |
| 评估时间 | 日期 | 数据库（聚合行周期终点） | 页面加载、切区间 | 该区间评估落库对应的周期终点日期（显示为 period_end 前一日） |
| 数据状态 | 文本 | 数据库（模块内维度行 insufficient/failed 计数） | 页面加载、切区间 | 数据完整 / 部分维度已降权 / 部分维度缺失 / 待评估（判定规则见 4.2.4 规则8） |

##### C. 核心结论区（按所选区间获取）

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 业务含义 |
|---------|---------|---------|---------|--------|
| 结论主文 | 文本 | 计算（前端规则拼装） | 页面加载、切区间 | 模块等级与突出项的一句话概括；数据严重不足时替换为谨慎参考提示 |
| 发现列表 | 列表（四类） | 计算（前端规则拼装） | 页面加载、切区间 | 优势/短板/风险/趋势四类发现条目，规则见 4.2.4 规则2 |

##### D. 能力雷达与维度明细（双 tab，按所选区间获取）

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 业务含义 |
|---------|---------|---------|---------|--------|
| 使用能力雷达 | 图表 | 数据库（dimension_scores 所选区间 AI_USAGE 各维度行） | 页面加载、切 tab、切区间 | 8 维雷达，叠加公司均分对照（口径见 4.2.4 规则4） |
| 管理能力雷达 | 图表 | 数据库（dimension_scores 所选区间 AI_MGMT 各维度行） | 切到管理 tab | 5 子能力雷达，叠加公司均分对照 |
| 维度名称 | 文本 | 数据库（维度配置） | 页面加载 | 维度显示名，分组呈现：使用 tab 分基础对话能力 4 维与高级生成能力 4 维，管理 tab 为 5 子能力一组；维度集合与数量随维度配置动态，8 维 / 5 子能力为当前配置快照 |
| 维度分数 | 数字 | 数据库（dimension_scores） | 页面加载、切区间 | 该维度所选区间分，insufficient 行照常显示分数并带降权标记；failed 行与无行维度按数据缺失口径显示 -，不渲染落库的 0 分占位 |
| 维度状态标记 | 标签 | 数据库（dimension_scores status/insufficient） | 页面加载、切区间 | 降权（insufficient）/ 数据缺失（无行或 failed） |
| 维度解读 | 文本 | 数据库（dimension_scores rationale） | 展开时 | 该维度评分理由（上游已脱敏） |
| 证据来源 | 列表 | 数据库（dimension_scores evidence_json） | 展开时 | 来源类型（对话分析/主动测试）、时间、置信度（口径见 4.2.4 规则5）、摘要与脱敏样本 |
| 近期走势 | 折线图 | 数据库（同人各期维度评分行） | 页面加载、切区间（走势序列随明细响应返回，展开时才渲染） | 近若干期该维度分数走势与较上期变化，期数取近 4 期 |

##### E. 九型人格参考区（页面加载时获取）

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 业务含义 |
|---------|---------|---------|---------|--------|
| 主型 | 文本 | 数据库（assessment_test_results） | 页面加载 | 判型主型名称，无判型行整区显示未参与提示 |
| 翼型 | 文本 | 数据库（assessment_test_results） | 页面加载 | 判型翼型描述 |
| 9 型倾向分布 | 柱状图 | 数据库（assessment_test_results 分布字段） | 页面加载 | 9 型倾向值柱状图，主型柱高亮 |
| 型别解读 | 文本 | 数据库（assessment_test_results rationale） | 页面加载 | 判型理由摘要 |

#### 4.2.3 功能与按钮

**用户可操作功能：**

- **返回列表**
  - 触发按钮：返回列表（页面级）
  - 按钮位置：页面顶部条左侧
  - 权限要求：已登录平台账号
  - 功能说明：浏览器历史返回上一页；无历史记录时跳人员画像列表页兜底。

- **评估区间切换**
  - 触发方式：区间下拉选择
  - 按钮位置：页面顶部条右侧
  - 权限要求：已登录平台账号
  - 功能说明：下拉列出该人全部已落库评估区间（新到旧，本期标注「本期」），切换后概览、结论、评分卡、雷达、维度明细按所选区间整体刷新；九型区不随区间变化。
  - 约束说明：区间列表由该人实际落库周期行推导，非按当前周期配置推算，避免配置变更后出现无数据区间。

- **维度明细展开/收起**
  - 触发方式：点击维度行
  - 权限要求：已登录平台账号
  - 功能说明：展开显示维度解读、近 4 期走势图与证据来源列表；再次点击收起。数据缺失维度不可展开。
  - 约束说明：走势图展开时才渲染，收起即销毁，避免整页常驻图表；多行展开状态互相独立、跨区间切换保留。

- **能力 tab 切换**
  - 触发方式：tab 点击（AI 使用能力 / AI 管理能力，显示名后缀的维度计数动态取自维度配置）
  - 权限要求：已登录平台账号
  - 功能说明：切换雷达图与维度明细分组；管理 tab 首次切入时才渲染雷达（按需加载）。

#### 4.2.4 业务规则

- **规则1：数据区间一致性**
  - 规则描述：详情页除九型区外的全部数据块统一按所选区间取数；区间下拉的选项集合为该人 activity_stats / dimension_scores / aggregate_scores 三表落库周期的并集（新到旧）。
  - 约束说明：手动定向批次与周期批次的窗口可能错位，以落库行实际周期为准展示，不跨区间拼装数据。

- **规则2：核心结论规则化生成**
  - 规则描述：结论主文与发现列表由前端基于接口数据按固定规则拼装，不调 LLM：主文概括两模块等级与最高分维度；发现按四类生成：优势（维度分 ≥ 75 的最高两项）、短板（短板集合内分数 < 60 的维度全部列出，短板集合口径同 4.1.4 规则4，含两模块参与聚合维度、排除九型）、风险（按模块汇总一条：使用与管理模块各拼一条「N 个维度降权、M 个维度缺失」计数摘要；管理能力模块整体待评估时拼「AI 管理能力待评估」）、趋势（较上期升降）。某类发现为空时不渲染该类条目。数据严重不足（使用能力无聚合行，或使用能力模块内降权与缺失维度计数之和 ≥ 4）时主文替换为「当前可用数据有限，结论仅供参考」提示。
  - 约束说明：规则拼装保证只读消费域零 LLM 成本与结果确定性，文案阈值（75/60/4）为前端常量，调整无需后端发版。

- **规则3：等级映射**
  - 规则描述：分数到等级的映射为 ≥ 85 优秀、70-84 良好、60-69 中等、< 60 待提升，待评估单列；模块总分与维度分共用该映射。模块总分为上游聚合浮点值，展示与等级判定前四舍五入取整；较上期变化按取整后分差计算，上一期取该人落库区间列表（新到旧排序）中所选区间的下一项的聚合行，与区间下拉同口径按落库行推导、不按周期配置推算；维度分为整数无需处理。
  - 约束说明：映射为前端展示常量，与上游聚合权重口径解耦。

- **规则4：公司均分对照口径**
  - 规则描述：雷达图叠加公司均分对照：对所选区间全公司该维度全部参与聚合维度行求算术平均（剔除 insufficient 与 failed）；公司侧不足 3 人有数据时该维度对照线隐藏，避免小样本误导。
  - 约束说明：均分为展示期实时聚合，不落库。

- **规则5：证据来源置信度口径**
  - 规则描述：对话分析来源的置信度按该维度证据中会话信号次数映射：信号 ≥ 10 次高、2-9 次中、不足 2 次低（样本不足）；主动测试来源按任务阅卷状态映射：success 高、degraded 低（阅卷降级）。信号次数来自 evidence_json 统计摘要。
  - 约束说明：置信度为规则映射的展示标签，非 LLM 输出字段。

- **规则6：九型参考性口径**
  - 规则描述：九型区标注「辅助维度，不进入硬性评分聚合」；无判型行时整区显示「未参与九型人格测评」提示，不显示空图表。
  - 约束说明：九型判型结果不参与任何模块分、总览分与短板筛选。

- **规则7：隐私红线**
  - 规则描述：详情页任何位置不得出现对话原文；维度解读与证据样本均取自已脱敏落库的 rationale 与 evidence_json，展示层不再二次加工还原。
  - 约束说明：评分可解释诉求由脱敏证据支撑，原文仅存在于抽取阶段内存。

- **规则8：数据状态判定**
  - 规则描述：评分卡数据状态按模块内维度行计数映射，判定优先级从高到低：模块无聚合行为「待评估」；存在 failed 行或无行维度（即有数据缺失维度）为「部分维度缺失」；存在 insufficient=true 行为「部分维度已降权」；其余为「数据完整」。降权与缺失并存时按缺失显示（缺失代表评分链路失败，比样本不足更严重）。
  - 约束说明：全部维度降权或缺失时仍沿用上述映射结果，展示层不引入额外档位。

#### 4.2.5 交互逻辑

- 评估区间切换时页面数据整体刷新，期间显示加载态，避免新旧区间数据混渲染。
- 维度行数据缺失态置灰且不可点击；可展开行带展开指示箭头，展开时箭头旋转 180 度。
- 雷达图悬浮显示维度名与分值；走势图悬浮显示区间与分值。
- 人员不存在或无任何画像数据时，页面显示空态提示与返回列表入口。
- 错误态：详情接口失败（含姓名上游解析失败，错误码 1305）时整页显示错误占位与「重试」按钮，重试重新发起整页数据请求；不用画像数据降级渲染，也不以占位姓名渲染概览。

## 5. 非页面功能详细说明

### 5.1 列表查询聚合接口（支撑 4.1）

#### 5.1.1 功能概述

**触发方式：**API 调用（前端页面触发）
**功能职责：**一次请求返回分页后的人员画像概要行：上游全员名单 + 最新周期画像数据左联 + 筛选与分页在服务端完成。名单拉取上游失败时接口返回明确错误码，前端进入错误态。

#### 5.1.2 处理流程

1. 接收筛选条件（姓名、活跃度、短板维度、仅看未使用）与分页参数。
2. 经 userapi 客户端拉取全员名单（翻页聚合，复用既有 WalkStaffPages 口径）。
3. 名单按姓名筛选（如上游支持服务端过滤则透传，否则内存过滤）。
4. 按名单人员标识批量查最新周期 activity_stats、aggregate_scores、dimension_scores（降权判定与短板集合计算）、assessment_test_results 判型。
5. 组装行数据（缺失按 4.1.4 规则2 口径）、应用活跃度/短板/仅看未使用筛选、排序分页返回。

#### 5.1.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 全员名单 | integration/userapi | 列表人群基表 | 实时拉取，人群口径为全员 |
| 活跃度分级 | activity_stats | 活跃度列与筛选 | 每人最新周期行 |
| 模块总分与降权 | aggregate_scores + dimension_scores | 两模块分数列、降权标记 | 每人最新周期行 |
| 短板集合 | dimension_scores | 短板维度筛选 | 每人最新周期参与聚合维度最低分 |
| 九型主型 | assessment_test_results | 九型列 | 每人最新判型行 |

#### 5.1.4 业务规则

- **规则1：上游失败的错误语义**：上游名单拉取失败时接口整体失败返回（不返回半截数据），错误码映射配置域 StaffListUnavailable（1305），前端显示错误态；不使用本系统落库数据兜底替代名单。
- **规则2：性能口径**：画像四表查询按人员标识批量 IN 查询，避免逐人查询；上游名单翻页在接口内完成；导出复用同一查询链路（透传筛选条件、跳过分页）。

### 5.2 画像详情聚合接口（支撑 4.2）

#### 5.2.1 功能概述

**触发方式：**API 调用（前端页面触发）
**功能职责：**一次请求返回单人指定评估区间的完整画像数据：区间列表、概览（活跃度、九型）、两模块评分卡（含较上期聚合行）、维度明细（分数、状态、解读、证据、近 4 期走势）、公司均分对照。人员姓名的归属与失败语义见 5.2.4 规则2。

#### 5.2.2 处理流程

1. 接收人员标识与评估区间参数（区间为空时默认该人最新已落库区间）。
2. 查该人 activity_stats / dimension_scores / aggregate_scores 三表落库周期并集，生成区间列表（新到旧），校验所选区间在列表内。
3. 按人员标识与所选区间查三表数据行与 assessment_test_results 最新判型行。
4. 取区间列表下一项的聚合行计算较上期变化；按同人各期维度评分行组装各维度近 4 期走势序列。
5. 公司均分对照：对所选区间全公司该维度参与聚合维度行（剔除 insufficient 与 failed）求算术平均，公司侧有数据人数 < 3 的维度对照值置空。
6. 组装响应返回；维度行缺失按第 4 章口径映射（分数 -、状态数据缺失）。

#### 5.2.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 区间列表 | activity_stats / dimension_scores / aggregate_scores 三表落库周期并集 | 区间下拉选项 | 新到旧，本期标注 |
| 概览与评分卡 | 三表所选区间行 + assessment_test_results | 概览条与评分卡 | 较上期取区间列表下一项 |
| 维度明细与走势 | dimension_scores 同人各期行 | 维度行与展开区 | 近 4 期走势随明细一并返回 |
| 公司均分 | dimension_scores 所选区间全公司行 | 雷达对照 | 实时聚合不落库，< 3 人置空 |

#### 5.2.4 业务规则

- **规则1：人员与区间的错误语义**：人员标识查无任何落库周期行时返回空画像语义（前端进空态），不视为错误；所选区间不在区间列表内时按业务错误返回，前端提示并回落最新区间。
- **规则2：姓名归属**：详情页姓名经本接口由服务端调 userapi 按人员标识解析（单人查询，非全员名单）；上游失败时接口整体失败返回 StaffListUnavailable（1305），前端整页错误态加重试入口，不用画像数据降级渲染。

### 5.3 画像数据接口（预留，首期不实现）

#### 5.3.1 功能概述

**触发方式：**API 调用（外部系统在授权时调用）
**触发时机：**外部消费系统获取画像数据时（预留通道，首期不实现）
**功能职责：**为外部系统提供单人画像数据查询能力，作为平台画像数据的对外输出通道。

#### 5.3.2 契约要点（首期约定，实现期细化）

1. 提供按人员标识查询单人画像的能力，覆盖活跃度、两模块总分与各维度分、维度解读与证据摘要、九型判型；输出为脱敏口径，不含对话原文。
2. 鉴权经平台对外签发的集成凭据（凭据形态实现期确定，方向与对上游的集成密钥相反）；无凭据或凭据失效拒绝访问。
3. 本接口为只读查询，不提供写入、订阅与批量拉取能力；数据范围止于已落库画像，不含上游会话原文。
4. 首期不实现、不注册路由、不占用开发任务；外部系统对接需求明确后按本契约立项实现，届时补充接口字段级定义与限流策略。

#### 5.3.3 与其他功能的关联

- **上游依赖：**5.1 / 5.2 同源的画像数据（activity_stats / dimension_scores / aggregate_scores / assessment_test_results）。
- **下游影响：**外部消费系统（预留，未定）。

## 6. 数据状态定义

本 feature 为只读消费域，不管理系统状态机。呈现的数据状态均为上游落库状态的映射：

| 状态名称 | 状态说明 | 可转换到的状态 |
|---------|---------|--------------|
| 正常 | 维度评分行 status=success 且 insufficient=false | 随上游周期评估重跑更新 |
| 已降权 | 维度评分行 insufficient=true（对话样本不足） | 随上游重跑可能恢复正常 |
| 数据缺失 | 无评分行或 status=failed | 随上游补数生成评分行 |
| 待评估 | 模块整体无聚合行（如未参与主动测试） | 随上游首次评估生成 |

状态演进由 F6/F7 的评估与阅卷链路驱动，本 feature 仅按第 4 章口径映射展示，无用户触发的状态转换。
