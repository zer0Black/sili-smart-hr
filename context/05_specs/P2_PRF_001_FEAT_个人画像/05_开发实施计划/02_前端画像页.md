# 前端画像页 实现计划

> **目标：** 打通个人画像前端两页面：人员画像列表页（筛选/分页/导出/跳详情）与个人画像详情页（区间切换/评分卡/核心结论/双雷达与维度明细/九型参考），接入顶栏「结果洞察」导航。
> **架构：** 仿 assessment feature 样板：contracts.ts 定义契约类型，features/profile 承载 api/hooks/规则拼装/组件，TanStack Router 文件路由挂 _authenticated，TanStack Query 取数（无轮询），Recharts 雷达/折线/柱状图，i18n 新增 profile 命名空间中英双语。
> **技术栈：** React 19 + TypeScript、TanStack Router/Query、axios（httpClient 解包契约 + blob 旁路）、Recharts（已在 package.json）、Tailwind 4 token、i18next、sonner toast。

---

## 代码库依据

- 相关入口与复用：
  - `src/features/assessment/` 是列表页样板：api.ts（httpClient.get 解包）、hooks.ts（useQuery + queryKey 命名空间 + token/visible 门控）、components/（表格 + 筛选 + 分页自治）、`src/routes/_authenticated/assessment/index.tsx`（tab 常驻与页面状态机）。
  - `src/lib/http-client.ts`：统一解包拦截器会把 body.data 替换 resp.data；**xlsx 二进制响应无 code 字段，拦截器 `typeof body.code !== 'number'` 直接放行原始 resp**，导出用 `httpClient.get(url, { responseType: 'blob' })` 消费 `resp.data`（Blob），失败时后端返 JSON（axios 对 blob 请求会把错误体当 Blob，需在 api 层 catch 后按 blob.type 判别再 text() 解析 code，03 §1.6 前端按 Content-Type 判别）。
  - `src/features/dimension/api.ts` 的 `fetchDimensionTree` 与 `src/lib/contracts.ts` 的 `DimensionBrief/DimensionModuleNode/DimensionGroupNode`（含 include_overview/group_code 字段）：短板下拉选项与详情维度分组直接复用，不新建维度请求。

  - `src/lib/use-table-state.ts` 的 `useResetSignal`/`usePageClamp`：列表页分页信号复用。
  - `src/features/assessment/components/staff-multi-select.tsx`：人员选择器仅参考样式，本域人员为列表数据非选择器。
  - i18n 命名空间现状 14 个（common/auth/account/.../answer），profile 为第 15 个；zh.json 与 en.json 同步维护。
  - Recharts ^3.10.1 已在 package.json（根 CLAUDE.md 确认当前未用，本计划首次启用）。
- 验证入口：`pnpm type-check`（tsc --noEmit）、`pnpm test`（vitest run）；基线实测 type-check 通过（2026-10-02）。组件测试样板见 `src/features/assessment/components/__tests__/`。
