# 评估周期配置 实现计划

> **目标：** 实现系统参数页全链路，包括评估周期配置的查询（A1）、保存（A2）、人员列表查询（A3）三个后端接口，以及前端系统参数页（周期与触发、评估对象、成本说明三区段 + 保存/恢复默认）。
> **架构：** 后端按 account 四层样板新增 assessment config 的 repository → service → handler，userapi 集成客户端从零建（doc.go 占位），service 层用乐观锁与事务保证配置并发安全与指定人员全量覆盖；前端新增 system/params 路由页，feature 三件套，RHF + Zod 表单，周期联动与评估对象互斥在前端纯函数实现。
> **技术栈：** Go 1.25（GORM 链式 API、net/http 调外部用户体系）、React 19 + TanStack Router/Query + RHF + Zod。

  **文件：**

  **契约：**

  ```go
  type AssessmentConfigRepository interface {
      Get(ctx context.Context) (*domain.AssessmentConfig, error)   // 单例，恒有数据（首启 seed）
      UpdateWithVersion(ctx context.Context, cfg *domain.AssessmentConfig) (int64, error)  // UPDATE WHERE id=? AND version=?，返回 RowsAffected
      ListMembers(ctx context.Context, configID int64) ([]domain.AssessmentConfigMember, error)
      ReplaceMembers(ctx context.Context, configID int64, members []domain.AssessmentConfigMember) error  // 事务内先删后插
      UpdateWithMembers(ctx context.Context, cfg *domain.AssessmentConfig, members []domain.AssessmentConfigMember) (int64, error)  // 单事务内乐观锁更新 + 人员全量覆盖（repo 收口事务），返回 RowsAffected
  }

  type assessmentConfigRepository struct { db *gorm.DB }
  func NewAssessmentConfigRepository(db *gorm.DB) AssessmentConfigRepository
  ```

  关键逻辑：
  - Get：`r.db.WithContext(ctx).First(&cfg)` 或 `.Take(&cfg)`，单例表恒有数据，ErrRecordNotFound 理论不触发（seed 保证），仍 wrap 为内部 error。
  - UpdateWithVersion：`r.db.Model(&domain.AssessmentConfig{}).Where("id = ? AND version = ?", cfg.ID, cfg.Version).Updates(map[string]any{"period": cfg.Period, "trigger_time": cfg.TriggerTime, "target_mode": cfg.TargetMode, "version": cfg.Version + 1})`，返回 RowsAffected。affected==0 表示 version 不匹配（并发冲突），由 service 层映射 1306。用 map 而非 struct Updates 避免 zero-value 被忽略。
  - ListMembers：`r.db.Where("assessment_config_id = ?", configID).Find(&members)`，按 configID 查关联人员。
  - ReplaceMembers：在调用方传入的 tx 事务内执行（或本方法内 `r.db.Transaction`），先 `r.db.Where("assessment_config_id = ?", configID).Delete(&domain.AssessmentConfigMember{})`，再 `r.db.CreateInBatches(members, 100)` 批量插入。members 为空时仅执行 Delete（target_mode=all 场景）。

  **验收锚点：**
  - 核心断言（repository_test.go，用 :memory: SQLite 或临时文件库）：seed 后 Get 返回 Period=="weekly"；UpdateWithVersion 传正确 version 返回 affected==1 且再次 Get 得 Version 自增、字段更新；传错误 version（如旧 version）返回 affected==0；ReplaceMembers(configID, [2 个 member]) 后 ListMembers 长度==2，再次 ReplaceMembers(configID, []) 后长度==0（全量覆盖）。
  - 验证命令：`cd hr-backend && go test ./internal/repository -run TestAssessmentConfig -v`
  - 预期输出：`ok sili-smart-hr/backend/internal/repository`，乐观锁 affected 与全量覆盖两类断言通过。

  type AssessmentConfigService interface {
      Get(ctx context.Context) (*AssessmentConfigDTO, error)
      Save(ctx context.Context, period, triggerTime, targetMode string, members []StaffDTO, version int) (*SaveAssessmentResult, error)

  userapiClient 为 service 包内定义的接口（鸭子类型由 integration/userapi.Client 实现），便于测试注入 fake：
  ```go
  type userapiClient interface {
      ListStaffs(ctx context.Context, keyword string, page, pageSize int) ([]userapi.Staff, int64, error)
  }
  ```

  关键逻辑：
  - Get：repo.Get → 转 DTO（members 从 repo.ListMembers 填充，target_mode=all 时为空切片）。
  - Save 校验（任一失败返 NewError(BadRequest)=1400，message 带字段名）：period 必须 ∈ {daily,weekly,monthly}；target_mode 必须 ∈ {all,specified}；trigger_time 正则 `^\d{2}:\d{2}$` 且小时 00-23、分钟 00-59；target_mode=specified 时 members 非空。校验通过后组装 domain.AssessmentConfig（含原 version）与 members 切片，调 repo.UpdateWithMembers（单事务收口），affected==0 返 NewError(ConfigVersionConflict)=1306。UpdateWithMembers 内部按 target_mode 处理 members：specified 时全量覆盖、all 时清空。成功返新 version。
  - Save 的事务边界：UpdateWithMembers 在 repo 层单事务内完成乐观锁更新与人员全量覆盖，避免并发下 version 已更新但 members 未覆盖。UpdateWithVersion 与 ReplaceMembers 作为细粒度方法保留，供 T2 单测分别验证乐观锁与全量覆盖。
  - ListStaffs：调 userapiClient.ListStaffs，成功转 []StaffDTO；失败（err != nil）返 NewError(StaffListUnavailable)=1305。
  - 错误模型复用 service.Error 与 NewError（account 样板），不新建错误类型。

    - Save 参数非法：period="yearly" 返 Code==1400；target_mode=specified 但 members 空返 Code==1400；trigger_time="25:00" 返 Code==1400

- [x] **T5: 前端周期联动纯函数 + 测试**

  **文件：**
  - 创建：`hr-frontend/src/features/system-params/period.ts`
  - 创建：`hr-frontend/src/features/system-params/components/__tests__/period.test.ts`

  **契约：**

  ```ts
  export type Period = 'daily' | 'weekly' | 'monthly';

  // 触发日只读联动：日→每日、周→每周日、月→每月最后一天
  export function triggerDayOf(period: Period): string;

  // 评估区间只读说明：日→抽取当日、周→周一至周日、月→1日至月末
  export function intervalDescOf(period: Period): string;

  // 成本节流估算：据当前评估对象人数返回调用量提示文案（人数为 0 或全员时人数由调用方传入）
  export function estimateCount(memberCount: number | 'all'): string;
  ```

  关键逻辑：
