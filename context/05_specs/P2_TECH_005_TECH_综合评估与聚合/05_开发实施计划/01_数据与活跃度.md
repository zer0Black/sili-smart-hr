# 数据与活跃度 实现计划

> **目标：** 落地 dimension_scores / aggregate_scores / activity_stats 三张表与三个新 repository、DimensionRepository 评分口径扩展，实现人群签名识别纯函数与 Activity 活跃度统计组件（能力3/4），交付可独立验收的活跃度全链路。
> **架构：** domain 纯数据结构 + repository 双重接口范式（account/session_feature 样板），迁移走 migrateDB B 段 AutoMigrate 登记（三表全新建；实现期另补 aggregate_scores 存量列 float→double precision 幂等修正钩子，见 T1 说明）。IdentifyPopulation 是纯函数落 activity 包（消费主体），Activity 持 conversationlog 客户端 + 档案仓储 + 阈值读取 + 活跃度仓储四依赖，档案取数统一走 7 天缓冲加末轮归属内存过滤（与评分侧同口径，单点收敛在 activity 包导出函数 FetchWindowDigests）。
> **技术栈：** Go 1.25、GORM v2（多库兼容 tag：通用类型、无 default tag、TEXT 存序列化 JSON、time.Time）、glebarez/sqlite 内存库测试。
