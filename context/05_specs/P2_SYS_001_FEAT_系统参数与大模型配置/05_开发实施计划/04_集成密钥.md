# 集成密钥 实现计划

> **目标：** 实现大模型配置页下区集成密钥卡片全链路，包括集成密钥查询（C1）、详情临时查看（C2）、更新（C3）、连通验证（C4）四个后端接口，以及前端集成密钥卡片的掩码展示、临时查看、更新弹窗、连通验证就地反馈，并填充子计划 03 预留的卡片容器。
> **架构：** 后端按 account 四层样板新增 integration secret 的 repository → service → handler，conversationlog 集成客户端从零建（连通验证探活），service 复用 crypto 加解密；前端新增集成密钥 feature（与 llm-config 同页但独立 feature 三件套），填充 03 预留的 IntegrationSecretCard 容器。
> **技术栈：** Go 1.25（GORM、net/http 探活）、React 19 + RHF + Zod + RSA-OAEP。

  DTO：

  接口：
  ```go
  type IntegrationSecretService interface {
      Get(ctx context.Context) (*IntegrationSecretDTO, error)
      Detail(ctx context.Context) (*IntegrationSecretDetailDTO, error)
      Update(ctx context.Context, secretCipher, keyID string) (*UpdateSecretResult, error)
      Test(ctx context.Context) (*SecretTestResult, error)
  }
  func NewIntegrationSecretService(repo repository.IntegrationSecretRepository, dec service.PasswordDecryptor, encKey []byte, convLog service.ConversationlogPinger) IntegrationSecretService
  ```
  ConversationlogPinger 为 service 包内导出接口（`Ping(ctx, secret string) error`），由 conversationlog.Client 实现，wire.Bind 绑定。dec 复用 account 域既有 `service.PasswordDecryptor`（与 03 llm_config 共用，wire.Bind 已存在）。encKey 复用 03 T3 新增的 NewLLMEncKey provider（wire 类型 `[]byte` 单例，两个 service 共用同一 AES 对称密钥加密两类密钥，与 04 §1.6"同一 LLM_SECRET_KEY"一致）。

  关键逻辑：
  - Get：repo.Get → 转 DTO，Configured = (secret.SecretCipher != "")（04 §3.3.1 配置状态推导），SecretMasked 直接取列。
  - Detail：repo.Get，若 SecretCipher=="" 返 NewError(IntegrationSecretNotConfigured)=1303（未配置不可临时查看）；否则 crypto.Decrypt(encKey, cipher) 解密返明文。
  - Update 校验：secretCipher 非空（绑定层保证 required，service 复校验），dec.Decrypt(ctx, keyID, secretCipher) 解密（失败 1400），明文 ≤200 字符校验。组装 domain.IntegrationSecret：SecretCipher=crypto.Encrypt(encKey, 明文)、SecretMasked=crypto.Mask(明文)。repo.Update 覆盖。返 UpdateSecretResult{Configured: true}。
  - Test：repo.Get，若 SecretCipher=="" 返 1303（未配置不可验证）；解密明文，调 convLog.Ping(ctx, 明文)。Ping 返 nil → SecretTestResult{Connected: true}；Ping 返 error → NewError(IntegrationSecretTestFailed)=1304，Msg 携带失败原因（自定义 message 覆盖 errcode.Message：构造 `*service.Error{Code: 1304, Msg: err.Error() 或友好文案}`）。
  - 错误模型复用 service.Error。1304 的 message 须动态携带失败原因（03 §C4 错误码表 1304 message 携带失败原因），用 `&service.Error{Code: IntegrationSecretTestFailed, Msg: reason}` 而非 NewError（NewError 取固定文案）。

  **验收锚点：**
  - 核心断言（service_test.go，fakeRepo + fakeDecryptor + fakeConvLog + 固定 encKey）：

    - Update：合法密文解密后 repo.Update 收到的 SecretCipher==crypto.Encrypt(明文)、SecretMasked==crypto.Mask(明文)，返 Configured==true；解密失败返 1400
    - Test：空 cipher 返 1303；非空 + fakeConvLog.Ping 返 nil → Connected==true；fakeConvLog.Ping 返 error → Code==1304 且 Msg 含失败原因
  - 验证命令：`cd hr-backend && go test ./internal/service -run TestIntegrationSecret -v`
  - 预期输出：`ok sili-smart-hr/backend/internal/service`，Get/Detail/Update/Test 与配置状态推导、1303/1304 映射断言通过。
