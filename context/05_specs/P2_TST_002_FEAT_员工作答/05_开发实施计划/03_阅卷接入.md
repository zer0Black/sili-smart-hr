# 阅卷接入 实现计划

> **目标：** F7 grading 引擎的作答对话段从空占位切换为真实作答记录拼接：Grader 增加答案读取窄接口、prompt 组装注入逐题作答行、Wire 装配随构造签名调整。
> **架构：** grading.Grader 新增 `AnswerRepo` 窄接口（answer 域仓储满足），`buildAIMgmtPrompt`/`buildEnneagramPrompt` 增加 answers 形参，作答段空记录保留占位兜底。作答原文进 prompt 前不脱敏（03 §4.3：prompt 是进程内一次性消费，脱敏约束落库字段 rationale）。
> **技术栈：** Go 1.25 + 既有 grading 引擎（无 LLM 侧变更，模板版本常量随变更 +1）。

---

## 代码库依据

- 相关入口与复用：

  - 数据源：子计划 01 T2 的 `repository.AssessmentTestAnswerRepository.ListByTask`（question_seq 升序）满足窄面签名（结构化匹配，无需适配器）。
  - 既有测试锚点：TestBuildAIMgmtPromptEmptyAnswerSection（prompt_test.go:67，空占位断言需随接入改造保留空态分支）。

- 规模与耦合判断：providers.go/wire_gen.go 与子计划 01 顺序修改（01 先改装配加 answer 域，本计划再改 Grader 装配签名），各阶段可编译可测试；Grader 构造签名变更属 grading 包内收口，worker/task 侧 handler 形参是窄接口不受影响。

    // AnswerRepo 作答对话记录读取窄面（03 §4.3，specs §5.2.3 全过程对话）。
    type AnswerRepo interface {
        ListByTask(ctx context.Context, taskID int64) ([]domain.AssessmentTestAnswer, error)
    }
    // New 构造签名：十参 → 十一参（answers AnswerRepo 插在 questionRepo 之后）：

    // PromptVersion 常量 "v1" → "v2"（模板变更同步，prompt.go:15）

  - 关键逻辑：

    - buildGradingPrompt 作答段：answers 非空时逐行 `第 X 题作答：{content}`（X 取行内 QuestionSeq，行序已按 seq 升序），空时保留 emptyAnswerSectionPlaceholder 兜底（理论不可达，提交门槛已保证全答，03 §4.3）。
    - 作答原文进 prompt 不脱敏（03 §4.3 分工：Redact 约束落库 rationale，prompt 一次性消费保留阅卷证据）。
    - PromptVersion 升 v2：模板变更落库标记（后续幂等重评按版本比对触发，evaluator 同款语义）。
  - 依赖：`domain.AssessmentTestAnswer`（子计划 01 T1 模型）；repository.AssessmentTestAnswerRepository 结构化满足 AnswerRepo（ListByTask 签名一致）。

  **验收锚点：**
  - 核心断言：

    - TestBuildEnneagramPromptWithAnswers：同口径，量表题作答（"4"）入段。
    - TestBuildPromptEmptyAnswersFallback（改造自 TestBuildAIMgmtPromptEmptyAnswerSection）：answers=nil → 保留占位文案 "（暂无作答对话记录）" 且不含 "题作答："。
