# 系统初始化 功能需求规格说明书

## 文档信息

- 基线 Feature：无
- 变更组：无

---

## 1. 概述

### 1.1 功能背景

sili-smart-hr 在 SQLite 开发模式下原本通过启动播种 admin / hzwlsoft.com 提供首个可登录账号，PostgreSQL / MySQL 模式不播种，导致生产空库部署后无人可登录、登录后状态不明。需要一个统一的首访就绪机制，替代硬编码播种，让平台从空白状态进入可登录、可运营的就绪状态，并锁定初始化状态避免重复执行。

机制参考兄弟思路 New-api 的系统初始化模块：以一个公开的初始化状态接口承载首访探针判定，以一个仅在未初始化时可用的提交接口创建首个管理员账号并锁定状态，完成后入口关闭、接口拒绝重复提交。New-api 的使用模式选择（自用 / 演示）在本平台无对应概念，不引入。运行状态摘要与组件健康测试这两类运维能力沿用 New-api 的模块归属，与本向导同属系统初始化域。

PRD 4.13 已为本模块定调：向导聚焦首个账号创建与初始化状态锁定，大模型配置、sili-smart-ap日志集成密钥、维度权重、评估周期等运行时配置不在向导内强制，由各自配置页维护，向导完成后工作台就近提示未完成的配置项。本说明书据此细化。

### 1.2 本功能业务目标

1. 提供首访就绪判定，前端首访探针据此放行登录页或进入初始化向导，消除空库部署后无人可登录的状态。
2. 提供初始化向导，首访者在单页内确认环境就绪项、创建第一个可登录平台账号，提交后写初始化记录锁定状态并跳转登录页。
3. 锁定初始化状态为单向终态，此后向导入口关闭、初始化提交接口拒绝重复执行。
4. 提供运行状态摘要与组件健康测试能力，供运维排查底座与外部依赖连通性，状态摘要同时供工作台消费以提示未完成配置。

## 2. 角色与权限矩阵

> 本章节是权限控制的单一真实来源。第 4 章各页面不再重复定义权限，仅在第 2 章未覆盖时补充。

### 2.1 数据权限（行级访问控制）

平台不设角色权限模型，所有平台账号统一全权。初始化记录为系统级单行数据，无行级隔离概念。向导处于系统未初始化阶段，此时不存在任何平台账号，向导操作由首访者在公开通道完成。

| 角色 | 数据范围 | 说明 |
|------|---------|------|
| 首访者（未登录） | 仅初始化向导可见 | 系统未初始化时，任何打开系统者可进入向导完成首个账号创建，完成后该入口关闭 |
| 平台账号（统一全权） | 全部数据 | 初始化完成后，任何登录账号可查看系统状态页并触发组件健康测试 |

### 2.2 页面访问权限

| 页面名称 | 可访问角色 | 可操作角色 | 字段级权限 |
|---------|----------|----------|------------------|
| 初始化向导页 | 任何人（系统未初始化时） | 任何首访者（系统未初始化时） | 无 |
| 系统状态页 | 平台账号 | 平台账号 | 无 |

向导页与登录页同属公开通道，仅在系统未初始化时可访问；已初始化后访问向导路由自动重定向至登录页。

### 2.3 接口鉴权矩阵

第 5 章各后端服务的鉴权要求集中声明如下，与 2.2 页面访问权限互补：页面访问权限约束前端路由可达性，接口鉴权约束后端 API 调用。

| 服务 | 鉴权要求 | 说明 |
|------|---------|------|
| 初始化状态检测（5.1） | 无需鉴权（公开） | 首访探针与向导页加载调用，此时可能不存在任何账号 |
| 首次初始化提交（5.2） | 无需鉴权，前置校验系统未初始化 | 一次性可用，已初始化后拒绝 |
| 系统状态摘要（5.3） | 无需鉴权（公开，供外部监控探针） | 仅暴露非敏感摘要，不含密钥与账号信息 |
| 组件健康测试（5.4） | 需平台账号鉴权（JWT） | 初始化完成后运维观测，触发外部依赖探测 |

## 3. 页面与功能总览

### 3.1 页面清单

| 序号 | 页面名称 | 页面形式 | 职责说明 | 包含功能 |
|-----|---------|---------|---------|---------|
| 1 | 初始化向导页 | 独立页面（不挂主框架，路由 /setup，与 /login 同级公开） | 首访者完成环境就绪确认与首个账号创建，提交后锁定初始化状态 | 初始化状态检测、环境就绪自检、创建首个账号、完成初始化 |
| 2 | 系统状态页 | 独立页面（_authenticated 顶栏内，路由 /system/status，挂载于系统配置下） | 展示系统运行状态摘要与组件健康，供运维排查连通性 | 运行状态摘要、组件健康测试 |

### 3.2 页面跳转流程

```
系统未初始化时任意访问 → [初始化向导页]
                                ├─ 环境就绪自检通过 → 填写首个账号 → 完成初始化 → [登录页]
                                └─ 环境就绪自检未通过 → 提交置灰 → 解决环境问题后继续

系统已初始化：
任意访问 → [登录页] → 登录成功 → [工作台]
                          ↓
            顶部导航「系统配置 > 系统状态」
                          ↓
                  [系统状态页] → 点击「立即测试」→ 组件健康结果刷新
```

**流程说明：**

1. 前端首访探针调用初始化状态接口：未初始化时强制跳转向导页，已初始化时放行登录页；接口调用失败（网络超时、后端未启动、5xx）时按访问态分流：无 token 视同未初始化跳转向导页，由向导页环境就绪自检复测数据库与缓存连通性以暴露真实环境问题，避免空库且后端未就绪时用户被放行到登录页锁死；有 token 保持放行，避免后端瞬态故障把已登录用户甩到公开向导页，真实异常态由 _authenticated 的 token 校验、401 拦截器各自兜住。
2. 向导页展示环境就绪自检结果，阻断项通过后首访者填写首个账号并提交，系统写初始化记录、跳转登录页。
3. 初始化完成后向导入口关闭，访问 /setup 重定向至 /login。
4. 登录后经顶部导航进入系统状态页，查看运行摘要并按需触发组件健康测试。

## 4. 页面功能详细说明

### 4.1 页面 1：初始化向导页

#### 4.1.1 页面概述

**页面形式：**独立页面，不挂主框架，路由 /setup，与 /login 同级公开。

**页面职责：**系统首次部署且无可用账号时的唯一就绪入口。首访者在单页内确认环境底座就绪、创建第一个可登录平台账号，提交后系统写初始化记录锁定状态。该页仅在系统未初始化时可访问，初始化完成后自动重定向至登录页。参考 New-api 的单页安装表单做法，一次提交同时完成账号创建与状态锁定。

#### 4.1.2 涉及字段

**首个账号表单字段（非列表页）：**

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 校验规则 | 默认值 | 业务含义 |
|---------|---------|---------|---------|---------|--------|--------|
| 账号 | 文本 | 用户输入 | 实时输入 | 必填；3-30 字符（列宽 varchar(64)）；全平台唯一（首个账号，库空必唯一）；对齐 account 账号台账新增规则 | 无 | 首个平台账号的登录账号，写入 accounts.username |
| 姓名 | 文本 | 用户输入 | 实时输入 | 必填；1-20 字符（列宽 varchar(64)）；对齐 account 账号台账新增规则 | 无 | 账号显示名，写入 accounts.name |
| 密码 | 密码 | 用户输入 | 实时输入 | 必填；≥8 字符 | 无 | 登录密码，bcrypt 哈希后写入 accounts.password_hash |
| 确认密码 | 密码 | 用户输入 | 实时输入 | 必填；与密码一致 | 无 | 二次确认，不一致时字段下方实时提示 |

> 字段约束对齐 P1_ACC_001 账号台账新增规则与 account 模型（username / name 均为 varchar(64)），完整校验以 P1_ACC_001 为准，避免与账号台账口径漂移。

**环境就绪自检项（只读展示，非表单输入）：**

| 自检项 | 展示形式 | 数据来源 | 业务含义 | 是否阻断提交 |
|--------|---------|---------|---------|------------|
| 数据库类型 | 标签 | 系统探测 | sqlite / mysql / postgres，反映当前 SQL_DSN 选库结果 | 否（信息展示） |
| 数据库连通 | 状态（对勾 / 叉） | 系统实时 ping | 库可读写，初始化记录与账号写入的前提 | 是 |
| 缓存（Redis）连通 | 状态（对勾 / 叉） | 系统实时 ping | Asynq 底层可达，平台跑批与任务调度的前提 | 是 |
| JWT 密钥状态 | 状态（对勾 / 叉） | 系统探测 | 生产由 JWT_SECRET 覆盖为安全态；SQLite 开发态用默认公开密钥，提示风险 | 否（仅提示） |

#### 4.1.3 功能与按钮

**用户可操作功能：**

- **完成初始化**
  - 触发按钮：完成初始化（页面级，表单提交按钮，位于表单底部）
  - 按钮级别：页面级
  - 按钮位置：向导页账号表单底部
  - 触发方式：点击按钮
  - 权限要求：系统未初始化时任何首访者可点击
  - 加载状态：点击后至接口响应前显示 loading，防止重复提交
  - 功能说明：校验表单通过后，调用初始化提交接口创建首个账号并写初始化记录，成功后整页过渡到「初始化完成」提示页

- **立即去登录**
  - 触发按钮：立即去登录（页面级，提示页内）
  - 按钮级别：页面级
  - 按钮位置：初始化完成提示页
  - 触发方式：点击按钮
  - 权限要求：完成初始化后停留在提示页的首访者可点击
  - 加载状态：无
  - 功能说明：点击后立即跳转登录页，供首访者主动跳转，无需等待提示页 2 秒自动跳转

**后台自动流程：**

- **环境就绪自检加载**
  - 触发时机：向导页加载时
  - 说明：前端在向导页挂载时调用初始化状态接口，获取并渲染四项自检结果，据阻断项决定提交按钮是否置灰

#### 4.1.4 业务规则

- **规则1：初始化记录判据**
  - 规则描述：系统就绪状态以初始化记录是否存在为准，与账号表是否有账号解耦
  - 触发条件：首访探针、向导提交、运行状态摘要查询
  - 约束说明：初始化记录为系统级单行数据，存在即判定已初始化

- **规则2：单向状态锁定**
  - 规则描述：初始化记录一旦写入，状态锁定为已初始化，不可逆、不可重置
  - 触发条件：向导提交成功后
  - 约束说明：无反向流程、无回收站、无重新初始化入口；如需重置只能重建库

- **规则3：自检阻断**
  - 规则描述：数据库连通或缓存连通任一未通过时，完成初始化按钮置灰禁用
  - 触发条件：自检结果返回阻断项未通过
  - 约束说明：JWT 密钥状态仅提示不阻断；首访者需先解决环境问题再提交

- **规则4：首个账号属性**
  - 规则描述：向导创建的账号为首个平台账号，启用状态由业务层显式置 true，登录后统一全权
  - 触发条件：向导提交成功
  - 约束说明：遵循平台无角色模型约束与 account 布尔字段不加 default tag 的约定

- **规则5：接口一次性可用**
  - 规则描述：初始化提交接口仅在系统未初始化时可用，已初始化后拒绝重复提交
  - 触发条件：已存在初始化记录时再次调用提交接口
  - 约束说明：返回已初始化错误码，前端不会进入此路径（向导入口已重定向）

#### 4.1.5 交互逻辑

- 自检项以状态图标呈现，绿色对勾表示通过、红色叉表示未通过（阻断项）；非阻断风险项（如 SQLite 开发态 JWT 默认密钥）用黄色警示图标区分，每项附一行说明文案。
- 阻断项未通过时，完成初始化按钮置灰，按钮下方提示"请先解决标红的环境项"。
- 密码与确认密码不一致时，确认密码字段下方实时红字提示，不阻塞焦点离开前的输入。
- 提交成功后整页过渡到“初始化完成”提示页，2 秒后自动跳转登录页；提示页同时提供“立即去登录”按钮，首访者可主动跳转，避免重复点击。

#### 4.1.6 权限要求

参见第 2.2 节"页面访问权限"。本页面为公开通道，无字段级特殊权限。

### 4.2 页面 2：系统状态页

#### 4.2.1 页面概述

**页面形式：**独立页面，_authenticated 顶栏内，路由 /system/status，挂载于顶部导航"系统配置"下。

**页面职责：**初始化完成后的运维观测入口。展示系统运行状态摘要（初始化状态、数据库类型、系统版本、启动时间）与组件健康（数据库、Redis、当前启用大模型、sili-smart-ap日志集成密钥的连通性），供平台账号排查底座与外部依赖是否就绪。运行状态摘要同时供工作台消费以提示未完成的运行时配置。

#### 4.2.2 涉及字段

**运行状态摘要（只读展示）：**

| 展示项 | 展示形式 | 数据来源 | 获取时机 | 业务含义 |
|--------|---------|---------|---------|---------|
| 初始化状态 | 标签 | 初始化记录 | 页面加载 | 已初始化 / 未初始化 |
| 数据库类型 | 标签 | 系统探测 | 页面加载 | sqlite / mysql / postgres |
| 系统版本 | 标签 | 系统构建信息 | 页面加载 | 当前二进制版本号 |
| 启动时间 | 时间 | 进程启动记录 | 页面加载 | 进程本次启动时间戳，格式 yyyy-MM-dd HH:mm:ss |

**组件健康（可测试刷新）：**

| 组件 | 展示形式 | 数据来源 | 获取时机 | 业务含义 |
|--------|---------|---------|---------|---------|
| 数据库 | 状态 | 探测 | 点击立即测试 | connected / disconnected |
| 缓存（Redis） | 状态 | 探测 | 点击立即测试 | connected / disconnected |
| 大模型（当前启用） | 状态 | 探测 | 点击立即测试 | reachable / unreachable / 未启用模型 |
| 会话日志集成 | 状态 | 探测 | 点击立即测试 | reachable / unreachable / 未配置密钥 |

> 大模型与会话日志集成两项依赖 config 模块落地（当前为 doc.go 占位）。组件健康状态值的完整口径集中定义如下，4.2.4 规则2 与 5.4.4 业务规则均引用本表：

**组件健康状态值枚举（大模型 / 会话日志集成）：**

| 状态值 | 触发条件 | 适用阶段 |
|--------|---------|---------|
| 未配置 | config 模块未落地，对应配置项不存在 | config 落地前，两项统一显示 |
| 未启用模型 / 未配置密钥 | config 已落地，但未启用模型 / 未配置集成密钥 | config 落地后 |
| reachable | config 已配置，连通探测成功 | config 落地后 |
| unreachable | config 已配置，连通探测失败 | config 落地后 |

> 数据库与缓存两项不受 config 阶段影响，固定为 connected / disconnected。config 落地后，「未配置」文案不再出现。

#### 4.2.3 功能与按钮

**用户可操作功能：**

- **立即测试**
  - 触发按钮：立即测试（页面级，位于组件健康区顶部工具栏）
  - 按钮级别：页面级
  - 按钮位置：组件健康区右上角
  - 触发方式：点击按钮
  - 权限要求：平台账号（统一全权）
  - 加载状态：点击后至探测完成前显示 loading，期间禁用按钮
  - 功能说明：触发组件健康测试接口，逐项探测数据库、Redis、大模型、会话日志集成的连通性并刷新结果

- **刷新**
  - 触发按钮：刷新（页面级）
  - 按钮级别：页面级
  - 按钮位置：运行状态摘要区右上角
  - 触发方式：点击按钮
  - 权限要求：平台账号
  - 加载状态：点击后显示 loading
  - 功能说明：重新拉取运行状态摘要，更新初始化状态、数据库类型、版本、启动时间

#### 4.2.4 业务规则

- **规则1：组件探测只读**
  - 规则描述：组件健康测试仅做连通性探测，不修改任何配置与数据
  - 触发条件：点击立即测试
  - 约束说明：探测过程对大模型发起一次最小请求、对集成密钥发起一次鉴权探测，均为只读

- **规则2：依赖项降级展示**
  - 规则描述：被探测的外部依赖按 4.2.2「组件健康状态值枚举」呈现对应档位，未配置时返回降级文案而非异常
  - 触发条件：config 未落地或未维护对应配置
  - 约束说明：区分”降级文案（未配置 / 未启用模型 / 未配置密钥）”与”已配置但不通（unreachable）”，前者是配置待补、后者是连通故障

- **规则3：状态摘要下游消费**
  - 规则描述：运行状态摘要供工作台消费，工作台据此提示未完成的运行时配置项（大模型、集成密钥等）
  - 触发条件：工作台加载
  - 约束说明：提示逻辑归属工作台模块，本页仅提供状态数据

#### 4.2.5 交互逻辑

- 组件健康结果以状态图标加文案呈现，探测进行中显示加载态，单项探测完成即更新该项状态。
- 首次进入页面时组件健康区显示"点击立即测试"空状态引导，不自动触发探测，避免页面加载即发起外部请求。

#### 4.2.6 权限要求

参见第 2.2 节"页面访问权限"。本页面仅平台账号可访问，无字段级特殊权限。

## 5. 非页面功能详细说明

本章描述承载页面与首访探针的后端接口服务。完整字段契约（请求 / 响应结构、错误码）由下游"接口数据设计"技能在 03_api_interface 中定义，本节仅固化职责、处理流程与异常策略。

### 5.1 初始化状态检测服务

#### 5.1.1 功能概述

**触发方式：**API 调用（前端首访探针、向导页加载）
**触发时机：**前端首访时、向导页加载时、已初始化后访问 /setup 时
**功能职责：**返回系统初始化状态与数据库类型，供前端判定走向导还是放行登录，并向导页渲染环境就绪自检结果。

#### 5.1.2 处理流程

1. 接收 GET 请求，无需鉴权。
2. 查询初始化记录表是否存在记录，得出 initialized 标志。
3. 探测数据库连通、缓存连通、JWT 密钥状态，组装环境就绪自检结果。
4. 读取当前数据库类型（SQL_DSN 选库结果）。
5. 返回初始化状态、数据库类型、环境就绪自检项及阻断判定。

#### 5.1.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 初始化记录 | 初始化记录表 | 判定就绪状态 | 单行记录存在即已初始化 |
| 数据库连通 | 实时 ping | 自检阻断判定 | 阻断项 |
| 缓存连通 | 实时 ping | 自检阻断判定 | 阻断项，Asynq 底层 |
| JWT 密钥状态 | 配置探测 | 自检提示 | 是否由 JWT_SECRET 覆盖 |
| 数据库类型 | SQL_DSN 选库结果 | 信息展示 | sqlite / mysql / postgres |

#### 5.1.4 业务规则

- 已初始化时仍正常返回状态与自检结果，但前端据此重定向登录页而非渲染向导。
- 探测失败不影响接口返回，仅反映为对应自检项未通过。

#### 5.1.5 异常处理

| 异常场景 | 处理方式 | 错误提示 / 日志 |
|---------|---------|--------------|
| 初始化记录表查询失败 | initialized 置 false 且数据库连通项强制未通过（联动阻断提交），其余自检项仍真实探测 | 记录 slog 错误日志 |
| 缓存探测超时 | 该项判未通过，阻断提交 | 记录 slog 警告日志 |

#### 5.1.6 与其他功能的关联

- **上游依赖：**初始化记录表（本 feature 新增）、account 模型（间接，状态判定参考）、Redis、DB。
- **下游影响：**前端首访探针、向导页、登录页判定逻辑。

### 5.2 首次初始化提交服务

#### 5.2.1 功能概述

**触发方式：**API 调用（向导页提交）
**触发时机：**首访者在向导页填写首个账号并点击完成初始化
**功能职责：**创建第一个可登录平台账号并写入初始化记录锁定状态，一次性可用。

#### 5.2.2 处理流程

1. 接收 POST 请求，无需鉴权，但前置校验系统未初始化。
2. 复核环境就绪自检阻断项（数据库、缓存），未通过则拒绝。
3. 校验账号、姓名、密码、确认密码字段规则，确认密码一致。
4. 复用 account 账号创建能力写入 accounts 表，密码 bcrypt 哈希，启用状态业务层置 true。
5. 写入初始化记录（关联首个账号 ID），状态锁定为已初始化。
6. 返回成功，前端跳转登录页。

#### 5.2.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 首个账号字段 | 用户提交 | 写入 accounts | username / name / password_hash / enabled |
| 初始化记录 | 本次创建 | 锁定就绪状态 | 单行，关联 creator_account_id |

#### 5.2.4 业务规则

- 已初始化时调用直接拒绝，返回已初始化错误码。
- 账号唯一性以 accounts.username 唯一索引保证，首个账号库空必唯一。
- 账号创建与初始化记录写入在同一事务内，任一失败整体回滚，避免半状态。

#### 5.2.5 异常处理

| 异常场景 | 处理方式 | 错误提示 / 日志 |
|---------|---------|--------------|
| 系统已初始化 | 拒绝提交，返回已初始化错误码 | 前端不应进入此路径 |
| 自检阻断项未通过 | 拒绝提交，提示对应环境项未就绪 | 记录 slog 警告日志 |
| 字段校验失败 | 拒绝提交，返回字段级错误 | 按统一响应带错误码 |
| 事务失败 | 整体回滚，提示初始化失败 | 记录 slog 错误日志 |

#### 5.2.6 与其他功能的关联

- **上游依赖：**account 账号创建能力（P1_ACC_001）、初始化状态检测服务。
- **下游影响：**登录认证（首个账号可登录）、工作台（消费就绪状态）。

### 5.3 系统状态摘要服务

#### 5.3.1 功能概述

**触发方式：**API 调用（系统状态页加载、工作台消费、外部监控探针）
**触发时机：**进入系统状态页、工作台加载、外部探针轮询
**功能职责：**返回系统运行摘要（初始化状态、数据库类型、系统版本、启动时间），面向运维观测与下游消费。

#### 5.3.2 处理流程

1. 接收 GET 请求，无需鉴权（公开，供外部监控探针）。
2. 查询初始化记录得出初始化状态。
3. 读取数据库类型、系统构建版本、进程启动时间。
4. 返回运行状态摘要。

#### 5.3.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 初始化状态 | 初始化记录表 | 摘要展示与下游消费 | 已初始化 / 未初始化 |
| 数据库类型 | SQL_DSN 选库结果 | 摘要展示 | sqlite / mysql / postgres |
| 系统版本 | 构建信息 | 摘要展示 | 二进制版本号 |
| 启动时间 | 进程启动记录 | 摘要展示 | 本次启动时间戳 |

#### 5.3.4 业务规则

- 公开接口仅暴露非敏感摘要，不含密钥、不含账号信息。
- 工作台据此判断哪些运行时配置未完成并就近提示，提示逻辑归工作台。

#### 5.3.5 异常处理

| 异常场景 | 处理方式 | 错误提示 / 日志 |
|---------|---------|--------------|
| 初始化记录查询失败 | 初始化状态返回未初始化，其余摘要正常 | 记录 slog 错误日志 |

#### 5.3.6 与其他功能的关联

- **上游依赖：**初始化记录表、进程启动记录。
- **下游影响：**系统状态页、工作台未完成配置提示、外部监控探针。

### 5.4 组件健康测试服务

#### 5.4.1 功能概述

**触发方式：**API 调用（系统状态页立即测试）
**触发时机：**平台账号在系统状态页点击立即测试
**功能职责：**逐项探测数据库、Redis、当前启用大模型、sili-smart-ap日志集成密钥的连通性，返回各项健康状态。参考 New-api 的组件健康测试接口。

#### 5.4.2 处理流程

1. 接收 POST 请求，需平台账号鉴权（JWT）。
2. 探测数据库连通（一次轻量查询）。
3. 探测 Redis 连通（一次 ping）。
4. 读取 config 当前启用模型，发起一次最小大模型请求探测可达性；未启用模型标记"未启用模型"。
5. 读取 config sili-smart-ap日志集成密钥，发起一次鉴权探测；未配置密钥标记"未配置密钥"。
6. 汇总返回各组件状态。

#### 5.4.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 数据库连通 | 实时探测 | 健康展示 | connected / disconnected |
| 缓存连通 | 实时探测 | 健康展示 | Asynq 底层 |
| 大模型可达 | 探测当前启用模型 | 健康展示 | 依赖 config 模型清单 |
| 集成密钥可达 | 探测sili-smart-ap日志集成密钥 | 健康展示 | 依赖 config 集成密钥 |

#### 5.4.4 业务规则

- 探测只读，不修改配置与数据。
- 大模型探测受 Asynq 节流之外的独立限流约束，避免健康测试触发模型侧 429，单次探测超时上限 10 秒。
- 各项状态值按 4.2.2「组件健康状态值枚举」返回，config 未落地前大模型与集成密钥两项统一返回"未配置"，不报错。

#### 5.4.5 异常处理

| 异常场景 | 处理方式 | 错误提示 / 日志 |
|---------|---------|--------------|
| 大模型探测超时或失败 | 该项标记 unreachable，不影响其他项 | 记录 slog 警告日志 |
| 集成密钥探测失败 | 该项标记 unreachable，不影响其他项 | 记录 slog 警告日志 |
| 数据库或缓存探测失败 | 对应项 disconnected，其余项继续 | 记录 slog 错误日志 |

#### 5.4.6 与其他功能的关联

- **上游依赖：**config 模块（当前启用模型、sili-smart-ap日志集成密钥）、Redis、DB。
- **下游影响：**系统状态页组件健康展示。

## 6. 数据状态定义

### 6.1 数据状态

本功能核心状态为系统初始化状态，单向流转、终态锁定。

| 状态名称 | 状态说明 | 可转换到的状态 |
|---------|---------|--------------|
| 未初始化 | 系统首访前，无初始化记录，向导入口开放、提交接口可用 | 已初始化 |
| 已初始化 | 向导提交成功后写入初始化记录，状态锁定，向导入口关闭、提交接口拒绝 | 无（终态） |

### 6.2 状态转换规则

| 当前状态 | 可转换到的状态 | 转换条件 | 转换触发方式 |
|---------|------------|---------|-------------|
| 未初始化 | 已初始化 | 环境就绪自检阻断项通过、首个账号字段校验通过、事务提交成功 | 首访者点击完成初始化 |
| 已初始化 | 无 | 无 | 无（终态不可逆） |

> 状态不可逆：已初始化后无回退入口、无重新初始化路径，重置只能重建库。这一点与 New-api 初始化后接口拒绝重复提交的机制一致。

## 7. 集成和依赖

### 7.1 外部系统集成

本功能无直接外部系统依赖，向导聚焦账号创建与状态锁定，不强制配置大模型与集成密钥。组件健康测试会反向探测外部依赖的连通性，但这些依赖的配置归属 config 模块，本功能仅消费。

| 系统名称 | 集成方式 | 集成内容 | 调用时机 | 依赖功能 |
|---------|---------|---------|---------|---------|
| 平台自配大模型 | 同步 HTTP（OpenAI 兼容 /v1） | 探测当前启用模型可达性 | 系统状态页点击立即测试 | config 模块维护模型清单 |
| sili-smart-api 会话日志 | 同步 HTTP（Bearer 集成密钥） | 探测集成密钥鉴权连通性 | 系统状态页点击立即测试 | config 模块维护集成密钥 |

### 7.2 内部功能依赖

| 当前功能 | 依赖的功能 | 依赖说明 | 依赖类型 |
|---------|-----------|---------|---------|
| 创建首个账号 | P1_ACC_001 账号台账 | 复用 account 账号模型与创建能力，首个账号写入 accounts 表 | 数据依赖 + 流程依赖 |
| 环境就绪自检 | Redis、DB | 探测底座连通性作为提交阻断判据 | 数据依赖 |
| 组件健康测试 | config 模块（大模型、集成密钥） | 读取当前启用模型与集成密钥做连通探测 | 数据依赖 |
| 运行状态摘要 | 初始化记录表 | 判定初始化状态供下游消费 | 数据依赖 |

**前置变更项（对 P1_ACC_001 的影响）：**

本 feature 上线需移除 account 的 SQLite 自动播种逻辑（admin / hzwlsoft.com），由初始化向导统一承接首个账号创建。该改动构成对 P1_ACC_001 已交付代码的变更，建议二选一处理：由「需求变更」技能对 P1_ACC_001 发起 RFC 单独记录，或在本 feature 开发实施计划内作为前置任务一并落地。开发态影响：SQLite 每次重建库后首访需走向导创建账号，不再有默认凭据。

**偏离记录：**

- 账号、姓名列宽 varchar(64)（通用规范：文本框上限 50 字符）。原因：对齐 account 模型 username / name 的 varchar(64) 定义，本 feature 创建首个账号复用同一模型，列宽跟随 account。格式校验上限（账号 30、姓名 20 字符）均小于通用规范 50，不构成偏离。
