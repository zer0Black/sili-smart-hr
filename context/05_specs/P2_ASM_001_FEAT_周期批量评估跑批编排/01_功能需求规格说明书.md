# 功能需求规格说明书

## 1. 概述

### 1.1 功能背景

sili-smart-hr 的能力评估主通道是对话分析：把员工在 sili-smart-api 沉淀的 AI 对话日志周期性转化为能力评分。技术底座已就位：T4 会话特征抽取（P2_TECH_003/004）与 T5 综合评估与聚合（P2_TECH_005）的引擎与 Asynq 任务均已交付，评估周期参数（P2_SYS_001）与维度权重口径（P2_DIM_001）已可配置。缺口在两端：引擎之上没有跑批编排（周期触发、全员展开、批次状态跟踪、失败兜底与超阈告警均未建，engine/pipeline 与 engine/fallback 仍为占位，scheduler 只注册了健康任务）；引擎之下没有运营消费界面（评测运营中心页前后端均未开工，运营人员无从查看跑批态势、无从发起手动定向分析、无从追溯批次历史）。

本 feature 是 PRD 5.2.2 中 F6（周期批量评估跑批编排）的对应交付项，把评测运营中心 · AI 使用能力 tab 的运营界面与随其交付的跑批调度、编排、失败兜底非页面功能合为一个业务 feature：非页面侧建跑批编排链路，页面侧建评测运营中心首期形态。合并的理由是两者互为表里：批次列表的每一条记录就是一次跑批编排的执行快照，拆开交付则页面无数据可显或引擎无出口可看，合在一起才能形成「配置周期 → 自动跑批 → 看态势 → 按需补跑」的完整闭环。

### 1.2 本功能业务目标

1. 周期跑批自动化：按系统参数页配置的周期与触发时点（默认每周日 23:00）自动对配置的评估对象发起全员对话分析评估，全程无人值守，批内单人失败不阻塞整体推进。
2. 跑批过程可观测：每个批次（定时或手动）落一条批次记录，进行中可看进度，完成后可看覆盖会话数与结果入口，运营人员一屏掌握本期评估态势。
3. 手动定向分析可达：运营人员按需选定对象与时段发起定向评估，复用同一套评分引擎与批次记录，也用作失败超阈后的补跑入口。
4. 失败兜底可控：抽取失败自动重试、重试耗尽降级保留统计、失败人数占比超阈产出告警信号，保证本评估周期评估不被局部失败阻塞且异常可被发现。

### 1.3 与 PRD 拆分的对应关系

本 feature 即 PRD 5.2.2 的 F6（周期批量评估跑批编排），承载对话分析评估的运营界面与随页面一并交付的跑批调度、编排、失败兜底非页面功能。跑批调度与失败兜底在 PRD 5.3 拆分说明中原为独立技术 Feature T6，已于 PRD v1.5 并入 F6（技术泳道现为 T1 至 T5，5.2.1 无 T6 条目），本 feature 是其落点。同页面的 AI 管理能力 tab、九型人格 tab 与主动测试发起追踪归后续 F7 主动测试评估运营 feature，在同一页面叠加。工作台告警卡的呈现归 F11 工作台 feature，本 feature 只产出告警信号与统计。个人画像与团队看板页面归 F9/F10，本页「查看结果」仅跳转。

3. 计划卡提供向系统参数页与维度配置页的就近跳转，支撑周期与口径的快速调整。
4. 批次完成后，行内「查看结果」跳转个人画像列表页消费评估产出（F9 建成前该按钮置灰，见 4.1.3）。

## 4. 页面功能详细说明

### 4.1 页面 1：评测运营中心页

#### 4.1.1 页面概述

**页面形式：**独立页面，挂 `_authenticated` 顶栏「评估运营」一级菜单下的「评测运营中心」，页面主体为 tab 容器（首期仅「AI 使用能力」一个 tab）。

**页面职责：**对话分析评估的运营总览与操作入口。运营人员在此查看本期跑批态势与下次跑批计划、追溯历史批次、发起手动定向分析、跳转消费评估结果。周期批量评估的自动执行不在此页触发，此页是其执行状态的呈现面。

#### 4.1.2 涉及字段

##### A. 态势统计卡（页面加载时获取）

| 字段名称 | 字段类型 | 数据来源 | 获取时机 | 业务含义 |
|---------|---------|---------|---------|--------|
| 本期评测次数 | 数字 | 数据库（触发时间落于本期跑批间隔内的批次计数） | 页面加载、轮询 | 本期跑批间隔内已发起的对话分析批次数（定时加手动）；本期跑批间隔指上一次定时批次触发时点至下一次触发时点之间，与 5.1.4 规则1 的周期窗口（评估数据区间）是两个口径，划界见 8.1。归属按批次触发时间判定，补跑历史时段的手动批次计入发起当期 |
| 已完成评估人次 | 数字 | 数据库（触发时间落于本期跑批间隔内的全部批次中到达成功侧终态（成功、复用、降级、跳过）的单人评估计数，不去重，含部分失败批次中的成功者） | 页面加载、轮询 | 本期跑批间隔内被成功评估过的人次规模 |

#### 4.1.4 业务规则

- **规则1：批次评估对象范围**
  - 规则描述：定时批次的评估对象取评估周期配置的评估对象（全员或指定人员），手动批次的评估对象取发起时选定的人员集合，均按人展开为一组单人评估，一人一次。
  - 触发条件：批次创建。
  - 约束说明：手动发起选「全员」时展开为发起时点的全员名单快照，批次执行中途入职或离职的人员变动不影响已展开的批次。

- **规则2：进度口径**
  - 规则描述：批次进度 = 已到达终态（成功、复用、降级、跳过、失败）的单人评估数 / 批次总人数；覆盖会话数按单人评估终态回写累计，计入该人窗口内的会话数（口径见 5.2.4 规则3）。
  - 触发条件：单人评估终态落库。
  - 约束说明：进行中批次的进度条与覆盖会话数依赖轮询刷新，存在最长一个轮询周期的延迟，不承诺实时。

- **规则3：同周期批次并存**
  - 规则描述：同一评估时段允许多个批次并存（先自动后手动补跑、或不同对象的手动批次），各批次独立推进、独立落状态，评估引擎侧的幂等机制保证同人同区间重复评估收敛到同一份评分结果，不产生重复计分。
  - 触发条件：手动发起时段与既有批次重叠。
  - 约束说明：不弹重叠警告，批次列表按触发时间倒序自然呈现。

- **规则4：周期配置变更生效边界**
  - 规则描述：评估周期、触发时点、评估对象的修改自下一次跑批触发生效，进行中批次不受影响；维度与权重变更同样在下次评估生效，已产出的历史批次不重算。
  - 触发条件：系统参数页或维度配置页保存。
  - 约束说明：生效边界由配置域的保存语义与本功能的触发时读取语义共同保证，本页不做额外提示。

#### 4.1.5 交互逻辑

- 列表空状态显示引导文案「暂无评测记录，点击右上角发起评测或等待周期自动跑批」。

## 5. 非页面功能详细说明

### 5.1 周期跑批调度

#### 5.1.1 功能概述

**触发方式：**定时任务（Asynq scheduler）
**触发时机：**按评估周期配置的周期长度与触发时点（默认每周日 23:00，随配置变更在下次注册生效）
**功能职责：**周期到达时自动创建定时批次并对配置的评估对象发起全员对话分析评估，是能力评估主通道的无人值守驱动源。

#### 5.1.2 处理流程

1. scheduler 按评估周期配置注册周期任务（配置变更时重注册；进程重启后按持久化的当前配置重新注册，不依赖内存态）。
2. 触发时读取评估周期配置快照：周期窗口、评估对象（全员或指定人员名单）。
3. 触发时将批次创建请求（触发方式=定时、周期窗口、评估对象名单快照）交 5.2 跑批编排处理，之后不再介入。

#### 5.1.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 评估周期配置 | assessment_configs | 决定触发节奏、周期窗口与评估对象 | P2_SYS_001 已建 |
| 指定人员名单 | assessment_config_members | specified 模式下的评估对象展开 | P2_SYS_001 已建 |

#### 5.1.4 业务规则

- **规则1：**周期窗口按评估周期配置推算，区间之间不重叠不遗漏（日→当日、周→本周一至本周日、月→本月 1 日至月末），保证同人跨区间评分可比。推算口径的单一真实来源为 P2_SYS_001「周期与触发联动」规则，本功能只读取不改写。
- **规则2：**触发时点到达但上一同源批次仍在进行中时，跳过本次触发并记 ERROR 日志，不排队叠加（防止慢批次滚雪球）。同源批次指上一轮定时触发创建的批次。任何批次（含手动批次）距创建已超过一个周期长度仍停留进行中的视为停滞，不再阻塞新触发。
- **规则3：**触发时读取的配置为触发时刻快照，批次创建后配置再变更不影响本批次。

#### 5.1.5 异常处理

| 异常场景 | 处理方式 | 错误提示/日志 |
|---------|---------|--------------|
| 触发时配置读取失败 | 交 Asynq 任务级重试（30s 基准倍增退避），重试耗尽跳过至下个周期 | ERROR 日志记失败原因 |
| 触发时点到达但上一同源批次仍在进行中 | 跳过本次触发（判定见 5.1.4 规则2），不重试 | ERROR 日志记同源批次号与跳过原因 |
| 批次创建请求投递失败 | 交 Asynq 任务级重试，重试耗尽跳过至下个周期 | ERROR 日志记队列错误与配置快照 |

#### 5.1.6 与其他功能的关联

- **上游依赖：**评估周期配置（P2_SYS_001）、维度权重（P2_DIM_001，经 T5 引擎间接消费）
- **下游影响：**批次执行驱动页面呈现；评估产出（评分、聚合、活跃度）由 T5 引擎落库，供画像与看板消费。

### 5.2 跑批编排（pipeline）

#### 5.2.1 功能概述

**触发方式：**事件驱动（随周期跑批调度与手动定向分析的批次创建请求启动）
**触发时机：**批次创建请求到达后立即展开
**功能职责：**把一个批次展开为可执行的编排：拉取窗口内会话列表、逐会话投递抽取任务、按人展开单人评估、汇聚单人终态推进批次状态、统计失败人数占比并产出告警信号。是批次从创建到终态的唯一状态机持有者。

#### 5.2.2 处理流程

1. 批次创建（定时或手动），落批次记录（进行中，总人数 N），生成批次号。
2. 编排器按评估时段全量分页拉取会话列表（ListSessions），翻页串行执行并按 session_key 去重（上游并发多页会返回相同的首页数据，见 T4 §3.2），再按 token_name 内存分组得到各人会话集。上游按人过滤参数不可用（中文 token_name 过滤触发上游 Database error，且全员 user_id 恒 1 使该过滤无区分度），禁止依赖，口径见 T4 §3.2 既定事实表。
3. 逐会话投递抽取任务（engine:session-extract，一会话一任务），交 T4 抽取链路产出特征档案，档案幂等规则见 T4 能力3。
4. 逐人执行单人评估：编排器以步骤2 分组结果中该人窗口内的会话列表作为 sessions 入参，进程内直调 T5 的 EvaluatePerson（已分组路径，T5 接口设计 §3.3），完成「活跃度统计→特征档案消费→综合评估→聚合」全链并三表落库。该路径即 T5 §3.2 对跑批编排（原 T6）的既定要求（一次拉全量列表内存分组后经 EvaluatePerson 的 sessions 入参注入），避免逐人重复全量拉取会话列表；分组结果在编排器侧同时供覆盖会话数与会话级失败比例口径消费（见 5.2.4 规则3 与 5.2.2 步骤7）。单人评估的 ctx 预算按 T5 §3.3 声明的 1050s 量级施加（该值原为 worker 侧 personEvaluateTimeout，已分组路径不经 worker，由编排器按同量级施加上限），满足 T5 对该入口 ctx 预算 ≥ 900s 的下限要求（重试时的 ctx 派生口径见 5.3.4 规则1）；编排器侧单人评估的并发上限不超过 T5 评估专用 client 的 LLM 在飞 gate（T5 接口设计 §3.3，4 路），避免超出 gate 形成排队。
5. 单人评估返回即由批次推进器回写该人终态（编排器同步持有调用结果）：到达任一种单人终态（成功、复用、降级、跳过、失败）均推进进度，其中成功侧四态额外累计该人会话数入覆盖会话数，失败另累计失败计数。
6. N 人全部终态后批次落终态：失败人数占比 ≤ 阈值为成功（含零失败），> 阈值且 < 全员为部分失败，= 全员为失败。
7. 批次终态时计算失败人数占比与会话级失败比例（分子为批次内 status=failed 会话计数，承接 T4 §6.2 extract_fail_ratio 的分子口径；分母为批次展开拉取会话列表时确定的全部会话总数，口径为本功能定义）；两个比例均按百分比计算并保留两位小数，与告警阈值的比较按该精度判定。失败人数占比超阈写一条告警信号记录（含批次号、失败人数占比、失败人数、时间），会话级失败比例随批次记录一并暴露，两者供工作台消费。

#### 5.2.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 窗口内会话列表 | sili-smart-api 会话日志接口 | 确定各人待评会话集与覆盖会话数 | T3 已实现 ListSessions，须全量拉取后按 token_name 内存分组 |
| 会话抽取任务 | Asynq 队列 | 逐会话产出特征档案，评估链路的输入 | T4 已实现 engine:session-extract，一会话一任务 |
| 单人评估 | 进程内直调（编排器持有分组结果） | 一人一次的评估执行载体 | 复用 T5 已实现的 EvaluatePerson 已分组路径（sessions 入参注入） |
| 会话级失败比例 | session_features（T4 已建） | 抽取健康度观测，供 F11 工作台呈现 | 批次终态时聚合：分子为 status=failed 计数（承接 T4 §6.2 extract_fail_ratio 的分子口径），分母为批次展开拉取会话列表时确定的全部会话总数（本功能定义） |
| 批次记录 | 本 feature 新建 | 编排状态机载体 | 进度、覆盖会话、失败计数、终态 |
| 告警信号记录 | 本 feature 新建 | 失败超阈的告警载体 | 消费方为 F11 工作台 |

#### 5.2.4 业务规则

- **规则1：**单人失败不阻塞同批其他人：单人评估的发起、排队、执行互相独立，任何人失败只影响自己的终态与批次的失败计数。
- **规则2：**批次推进以单人评估终态回写为准，进度只增不减（终态不回退）。
- **规则3：**覆盖会话数口径为批次内到达成功侧终态的各人窗口内会话数之和，在该人单人评估到达终态时一次性计入（含降级、跳过的会话，降级保留统计语义），失败人员的会话不计入，列表展示值随成功侧终态逐人递增。批次展开拉取会话列表时确定的全部会话总数（含失败人员会话）不作列表展示口径，仅作会话级失败比例的分母，见 5.2.2 步骤7。
- **规则4：**告警信号每批次至多一条（批次进入终态时判定产出），重复判定幂等覆盖。

#### 5.2.5 异常处理

| 异常场景 | 处理方式 | 错误提示/日志 |
|---------|---------|--------------|
| 会话列表拉取失败（上游接口不可用） | 整批落失败终态，批次内全部人员计入失败计数（列表显示 N/N），失败原因记为上游不可用 | ERROR 日志记批次号与上游错误摘要 |
| 抽取任务投递失败 | 该会话未进队列、无 session_features 行，不计入会话级失败比例分子（漏计口径与 T4 §6.2 披露的 ErrStoreWrite 同类，属已知披露） | ERROR 日志记会话标识 |
| 编排器侧单人评估未发起（编排器异常中断） | 批次停留进行中，按停滞批次处置（见 5.1.4 规则2 与本表末行）。补跑按 4.1.3 入口分流：该批次失败人数为零时经行内「重新发起」带入完整名单一次收敛；失败人数非零时行内仅「失败明细」可见、带入对象为失败人员，未发起人员由下个周期定时批次照常覆盖（见 5.1.4 规则2）经同人同区间幂等收敛 | ERROR 日志记中断点与未发起人员清单 |
| 单人评估执行出错 | 编排器侧按 30s 基准倍增退避重试（次数见 5.3.4 规则1），重试耗尽落该人失败终态 | ERROR 日志记错误与人员标识 |
| 会话列表翻页返回重复页 | 按 session_key 去重后并入各人会话集，不重复投递抽取任务 | WARN 日志记重复页页码与去重条数 |
| 批次记录创建落库失败 | 按 Asynq 任务级重试退避重试，重试耗尽则本次触发结束、不产出批次 | ERROR 日志记配置快照与落库错误 |
| 批次推进器回写失败 | ERROR 日志留痕，批次停留进行中；停滞批次不阻塞下个周期触发（见 5.1.4 规则2），下个周期照常覆盖同一批人，运营人员亦可经行内补跑入口对该批次重新发起定向评估（同人同区间幂等收敛见 4.1.4 规则3，入口分流见 4.1.5） | ERROR 日志记批次号与回写错误 |

#### 5.2.6 与其他功能的关联

- **上游依赖：**周期跑批调度（5.1）、手动定向分析（4.2）、会话日志集成（T3）、会话特征抽取（T4，抽取任务执行；投递见 5.2.2 步骤3）、综合评估与聚合（T5）
- **下游影响：**批次记录与告警信号驱动页面与工作台呈现。

### 5.3 失败兜底（fallback）

#### 5.3.1 功能概述

**触发方式：**事件驱动（会话抽取任务与单人评估失败时生效）
**触发时机：**任务或调用返回错误
**功能职责：**为跑批提供韧性内核：固定次数自动重试、重试耗尽降级保留统计、失败人数占比超阈告警，保证本评估周期评估照常推进且异常可被发现、可补跑。

#### 5.3.2 处理流程

1. 会话特征抽取失败（网络/LLM 调用错误）：按 Asynq 任务级重试（30s 基准倍增退避，worker 已实现的 RetryDelayFunc 口径），重试次数内恢复则正常产出档案。
2. 重试耗尽仍失败：该会话标记终态 failed，仅保留统计上下文（该人到达成功侧终态时，该会话计入覆盖会话数与活跃度统计，口径见 5.2.4 规则3；特征缺失由 T5 评估侧按数据不足降权承接），本评估周期评估照常推进。
3. 单人综合评估失败重试耗尽：该人落失败终态，计入批次失败计数（重试由编排器侧施加，见 5.2.5）。
4. 批次终态时失败人数占比超阈：写告警信号（见 5.2.4 规则4）。
5. 运营人员在批次列表经行内「失败明细」查看失败人员与原因后，用发起评测弹窗对该批失败对象与原时段重新发起，即定向补跑（复用手动定向分析入口，无独立补跑页面）。

#### 5.3.3 涉及数据

| 数据项 | 数据来源 | 数据用途 | 说明 |
|-------|---------|---------|------|
| 会话特征档案状态 | session_features（T4 已建） | 失败/降级会话的状态载体 | failed 终态行保留统计上下文 |
| 批次失败计数 | 本 feature 新建 | 失败人数占比计算输入 | 5.2 回写 |
| 告警信号记录 | 本 feature 新建 | 超阈告警载体 | F11 工作台消费 |

#### 5.3.4 业务规则

- **规则1：**会话抽取任务的重试次数按 Asynq 任务级默认口径（30s 基准倍增退避）；单人评估由编排器侧按同一退避曲线施加重试，次数为本功能常量（初值 3 次），每次尝试派生子 ctx 并各自拥有 5.2.2 步骤4 声明的完整预算额度，退避等待不计入预算；单次评估最坏耗时 840s 远高于单会话抽取，故次数显著少于会话级默认值。失败人数占比告警阈值为本功能常量（初值 10%）。两者的在线配置不在本期范围，如后续开放归系统参数域扩展，本功能改为消费。
- **规则2：**降级保留统计的会话，在该人到达成功侧终态时于批次覆盖会话数与活跃度统计中照常计入（口径见 5.2.4 规则3），评估侧按 T5 的 insufficient 口径降权，不产生硬失败。
- **规则3：**补跑不自动触发，由运营人员决策后经发起评测手动执行。

#### 5.3.5 异常处理

兜底自身为异常处理的最后一层：重试耗尽即终态化，不再向上抛出阻断批次；告警信号写入失败仅记日志不重试（下个批次的信号自然覆盖）。

#### 5.3.6 与其他功能的关联

- **上游依赖：**会话特征抽取（T4，抽取任务与失败状态来源，投递见 5.2.2 步骤3）、综合评估与聚合（T5，降权口径）
- **下游影响：**告警信号供 F11 工作台呈现；补跑入口复用 4.2 发起评测。

## 6. 数据状态定义

### 6.1 批次状态

| 状态名称 | 状态说明 | 可转换到的状态 |
|---------|---------|--------------|
| 进行中 | 批次已创建，单人评估未全部到达终态 | 成功、部分失败、失败 |
| 成功 | 全员终态且失败人数占比未超阈（含零失败） | 无（终态） |
| 部分失败 | 失败人数占比超阈但未达全员 | 无（终态） |
| 失败 | 全员失败或整批无法执行（上游会话列表不可用） | 无（终态） |

### 6.2 状态转换规则

| 当前状态 | 可转换到的状态 | 转换条件 | 转换触发方式 |
|---------|------------|---------|-------------|
| 进行中 | 成功 | 全员终态且失败人数占比 ≤ 告警阈值 | 系统自动（批次推进器） |
| 进行中 | 部分失败 | 全员终态且告警阈值 < 失败人数占比 < 100% | 系统自动（批次推进器） |
| 进行中 | 失败 | 失败人数占比 = 100%，或批次级异常（上游会话列表不可用） | 系统自动（批次推进器/编排器） |

**说明：**状态一经终态不可逆，重新评估通过新批次表达（同人同区间幂等收敛语义见 4.1.4 规则3）。批次不提供取消或作废操作：批次记录是评估执行的审计留痕，一经创建即执行到底，异常批次通过新批次补跑收敛（停滞批次的处置见 5.1.4 规则2 与 5.2.5，其停留进行中不改写本表转换规则，前端轮询与态势统计按 4.1.3 与 4.1.2 排除停滞批次）。单人评估内部的降级/跳过/复用等细粒度终态由 T5 引擎定义，本功能只在批次层聚合为成功与失败两类计数口径（降级、跳过、复用计入成功侧）。

### 8.3 通用交互与UI规范

全系统级别的UI和交互约定详见：[01_通用需求.md](../01_通用需求.md)

**偏离记录：**
- 批次列表每页条数可选 10/20/50（通用规范第1条：10/20/30）。跑批周期间隔长、单批数据行少，放宽大页容量便于整期回看。
- 批次列表按触发时间倒序（通用规范第1条：按更新时间倒序）。列展示的是发起时刻，按触发时间排序在轮询刷新时不跳行，列表顺序稳定。
- 时间显示为 yyyy-MM-dd HH:mm（通用规范第9条：yyyy-MM-dd HH:mm:ss）。跑批时间粒度到分钟，秒位无信息量。
- 失败明细弹窗内清单以滚动列表展示，不引入分页与筛选（通用规范第1条：所有列表均分页）。清单为单批次失败人员的只读快照，条数有限且无筛选维度，分页无收益。

说明：批次号为系统生成标识，无字符长度校验语义；进度百分比为整数显示，不适用通用「数字精确到小数点后两位」（该规范针对金额类数值）；行内进度条与 10 秒轮询为通用规范未定义的功能特有交互。
