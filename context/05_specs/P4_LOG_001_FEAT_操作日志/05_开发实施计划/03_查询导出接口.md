# 查询导出接口 实现计划

> **目标：** 实现 A1 列表（GET /api/operation-logs 四维筛选分页）与 A2 导出（GET /api/operation-logs/export xlsx 六列上限 10000 行）两接口，挂 auth 组完成装配。
> **架构：** OperationLogService 消费 01 已交付的 ListPage/ListByFilter 仓储，handler 复用 handleServiceError 与 profile 导出 blob 旁路先例；行 DTO 内嵌详情全量字段（changes/detail），详情弹窗零二次请求。
> **技术栈：** Go 1.25 + Gin + excelize/v2（既有依赖，profile_export.go 同款）。

- [ ] **T1: OperationLogService（List + Export）**

  **文件：**
  - 创建：`hr-backend/internal/service/operation_log.go`
  - 测试：`hr-backend/internal/service/operation_log_test.go`

  **契约：**
  - 签名：
    ```go
    // package service
    type OperationLogService interface {
        List(ctx context.Context, q OperationLogQuery) (*OperationLogListResult, error)
        Export(ctx context.Context, q OperationLogQuery) ([]byte, string, error)
    }
    type OperationLogQuery struct {
        Operator  string // 已去首尾空格
        Module    string // 空=全部
        Result    string // 空=全部
        StartDate string // yyyy-MM-dd，与 EndDate 成对
        EndDate   string
        Page      int
        PageSize  int
    }
    type OperationLogListResult struct {
        List     []OperationLogItem `json:"list"`
        Total    int64              `json:"total"`
        Page     int                `json:"page"`
        PageSize int                `json:"page_size"`
    }
    type OperationLogItem struct {
        ID        string              `json:"id"`         // 雪花 string 化
        CreatedAt string              `json:"created_at"` // yyyy-MM-dd HH:mm:ss Local
        Operator  string              `json:"operator"`
        Module    string              `json:"module"`
        Target    string              `json:"target"`
        Summary   string              `json:"summary"`
        Result    string              `json:"result"`
        Changes   []domain.ChangeItem `json:"changes"` // changes_json 空串时 nil（JSON null）
        Detail    string              `json:"detail"`   // 空串原样
    }
    func NewOperationLogService(repo repository.OperationLogRepository) OperationLogService
    ```
  - 关键逻辑：
    - 校验（List/Export 共用，任一失败返 `NewError(errcode.BadRequest)` 1400）：Module 非空时须属八类枚举；Result 非空时须 success/fail；StartDate/EndDate 只传一端 1400；两端都传时 `time.Parse("2006-01-02")` 失败 1400、start > end 1400；分页缺失兜底 1/10、<1 钳 1、>100 钳 100（profile 同款宽松超集）。
    - 时间换算：`StartAt = time.Date(y, m, d, 0, 0, 0, 0, time.Local)`、`EndAt = time.Date(y, m, d, 23, 59, 59, 0, time.Local)`（双闭区间，03 §1.8）。
    - List：调 repo.ListPage；DTO 组装——ID `fmt.Sprintf("%d", l.ID)`、CreatedAt `l.CreatedAt.Local().Format("2006-01-02 15:04:05")`、Changes 在 ChangesJSON 空串时保持 nil（json 输出 null）、非空时 json.Unmarshal 到 []domain.ChangeItem（非法 JSON 容错降级 nil 并 ERROR 日志）；Detail 空串原样。
    - Export：调 repo.ListByFilter(ctx, filter, exportMaxRows=10000 常量，收敛本文件)；总命中行 total 先调 `ListPage(ctx, filter, 1, 1)` 取回（零 repo 扩面）再 ListByFilter 取数；超限（total > 10000）时文件第 1 行为备注行 `实际导出 10000 行（命中 {total} 行，超出截断）`、第 2 行表头，未超限第 1 行直接表头；六列表头 `[操作时间, 操作人, 操作类型, 操作对象, 详情摘要, 结果]`；module 中文名与 result 中文名用导出侧常量 map（`opModuleNames`：login→登录/account→用户管理/dimension→维度与权重/system_params→系统参数/llm_config→大模型配置/question_bank→题库管理/assessment→评估运营/system_job→系统任务；`opResultNames`：success→成功/fail→失败），与前端 i18n 措辞对齐（enneagramTypeNames 同模式）；文件名 `操作日志_` + time.Now().Format("20060102_150405") + `.xlsx`；excelize 用法照 profile_export.go（NewFile/defer Close/SetSheetRow/bytes.Buffer Write）。
  - 依赖：`repository.OperationLogRepository`（01 交付）、`domain.ChangeItem`、`errcode.BadRequest/Internal`、excelize/v2。

  **验收锚点：**
  - 核心断言：
    - `TestOperationLogListValidation`：Module="bad" 返回 code 1400；只传 StartDate 返回 1400；start=2026-09-05 end=2026-09-01 返回 1400。
    - `TestOperationLogListBoundary`：fake repo 记录收到的 filter——传 StartDate=2026-09-01 EndDate=2026-09-30，断言 repo 收到 StartAt 的 Format("2006-01-02 15:04:05")=="2026-09-01 00:00:00"、EndAt=="2026-09-30 23:59:59"。

    - `TestOperationLogExportTruncation`：fake total=12000（ListPage(1,1) 返回）+ ListByFilter 返回 3 行样例，断言 xlsx 第 1 行 A1 单元格值为「实际导出 10000 行（命中 12000 行，超出截断）」（excelize GetCellValue 读回）、第 2 行为表头、文件名匹配 `^操作日志_\d{8}_\d{6}\.xlsx$`；total=3 时第 1 行即表头。
