## 1. 设计依据与冲突说明

### 1.1 SSOT 与优先级

业务需求层面以 specs 为准（字段、规则、状态、权限），技术实现层面以规则文件为准（方法约定、响应结构、错误码、表名）。冲突逐条在 §1.2-1.6 声明。

### 1.2 三接口全 POST 与令牌位置

specs §5.1.4 规则2 只约束「挂公开路由组（非 JWT 鉴权组），令牌自证鉴权」，未指定 HTTP 方法。本设计按规则文件 §2.1（GET 仅查询、POST 仅变更）归一化为三个 POST 接口，理由有两层：

1. A1（作答页数据组装）内嵌 F7 StartSession 会话上报（specs §5.1.2 步骤3），pending → in_progress 是状态变更，GET 语义承载不了；A2 落库、A3 终态化推进均为变更。
2. 一次性令牌是鉴权凭据，放 URL 查询串会进 Nginx access log 与浏览器历史，统一放 POST body 收敛泄露面（specs §5.1.5 令牌日志只记摘要的口径延伸）。

资源根取 `/api/answer`，动词后缀 context / reply / submit，与 F7 `/api/assessment/test-tasks` 的「资源根 + 动词」先例同构。

### 1.3 错误码段位：19xx 归 answer 域

F7 已占 18xx 段（1801-1805，errcode 注释「主动测试 1801-1805」）。本功能的接口面归 answer 模块（架构 2.2 独立模块），错误码分配 **19xx 段**（百位 9=员工作答），与 TST 段分段维护，避免两 Feature 后续各自扩码冲突。员工侧无任务主键消费场景，接口不回显任何雪花 ID，`task_no` 是唯一标识锚点（防枚举加分项：任务号非遍历键）。

### 1.4 对话剧本文案的前后端分工

specs §4.1.4 规则1 定义 AI 消息为「系统预设剧本（开场白、题目包装、题间确认、完成提示），按当前题号生成，不随员工回复内容变化」。本设计把剧本拆为两半：**服务端权威产出推进事实**（当前题号、下一题全文、完成判定，specs §5.2.4 规则1 服务端为进度权威），**前端 i18n 渲染剧本文案**（开场白、题间确认、重答提示、完成提示）。理由：前端已建 i18next 双语基建（根 CLAUDE.md 前端约定），服务端下发文案会绕开语言切换；且文案与推进逻辑解耦后，剧本措辞调整不动后端。specs §5.2.2 步骤4 的「返回推进指令」即按此落地为结构化字段（action + next_question）。

### 1.5 A3 提交幂等的令牌校验特例

specs §4.2.4 规则1 要求令牌失效统一呈现（防枚举），但 §5.3.4 规则2 要求「重复提交被终态守卫拦截时若任务已 completed 仍返回成功结果（页面转成功态）」。两者在「提交成功后的重复提交」场景相交：此时链接已 used，统一失效口径会把成功过的员工转失效态，违背员工视角一致。本设计的裁决：A3 令牌校验链放行「链接 used 且所属任务 completed」的组合（幂等成功短路返回，不重复进事务），其余失效情形（不存在 / invalid / 任务 canceled / used 但任务未 completed 的异常态）仍统一 1901。A1/A2 无此特例。

### 1.6 题目文本现读口径

题目全集经任务快照 ID 现读 questions（Unscoped 含软删行，F7 03 §4.6 注记既定口径）：取题集合以快照为准，文本以题库行现读为准。A1 下发的题目文本与 A2 推进指令携带的下一题全文各自现读，作答期间题库编辑会造成两次读取间的文本微差，属既定口径的可接受行为（快照集合不变，员工作答的题目对象恒定）。

### 1.7 完成判定口径：≥ 而非 =

specs §5.3.4 规则 1 的权威表述为「未答完不允许提交」（不等式语义），§5.3.2 步骤 1 括号内的「已落库回复数 = 题目总数」是正常链路（每题恰一条合法回复）下的等价简化。04 文档 §3 已识别并发双发异常路径可产生同题多行（COUNT 超题目总数），等号判定在此异常态永不成立，A1 finished=false 让员工侧无提交入口、A2 后续回复按 1902 兜底，形成 UI 死锁而 A3 反而放行。本设计的裁决：完成判定三接口统一按 **≥** 口径（A1 finished、A2 action=finished、A3 完整性门槛同取 specs §5.3.4 规则 1 的不等式语义），异常态下员工至少拿到提交按钮闭环；正常链路下 ≥ 与 = 等价，无行为差异。

## 2. 通用约定

### 2.1 基础配置

| 配置项 | 值 | 来源 |
|-------|------|------|
| Base URL 前缀 | `/api` | 规则文件 §2.1 |
| 版本控制 | 不分段，无 /v1 | 规则文件 §2.1 |
| 方法约定 | 全 POST（§1.2 裁决） | 规则文件 §2.1 |
| 认证方式 | 一次性令牌自证（请求体 token 字段） | specs §2.1 令牌即权限边界 |
| 路由归属 | 公开路由组（与 /api/login、/api/setup 同层，不挂 JWT） | specs §2.1 / §5.1.4 规则2 |

作答接口与主平台 JWT 体系物理隔离：不读 Authorization 头、不触发 401 登出链路（specs §2.1）。前端作答页专用请求通道不消费 auth store 的 httpClient 实例。

**限流：** IP 维度限流按端点分桶（复用平台 RateLimit 中间件，specs §5.1.4 规则2）：context/submit 各 30/min（`sili-smart-hr:rl:answer-ctx:` / `answer-submit:`），reply 单独 120/min（`sili-smart-hr:rl:answer-reply:`）。原设计三接口共享 30/min 单桶，实现评审发现组卷逐子能力启用题全取题量无上限（8 子能力各 5 题即 40+ 次调用），共享桶会拦截合法连续作答，按「阈值为注册处常量，实现期可调」授权调整为分桶口径。超限返回 429，员工等待窗口后可继续。

### 2.2 统一响应格式

遵循规则文件 §2.2。`data` 无 omitempty，成功无载荷时为 `null`。本功能无分页场景（单任务全量题目与对话，specs §8.3 偏离记录已声明无列表分页对象）。

### 2.3 错误码段位

19xx 段归 answer 域（§1.3），本功能新增 3 个码见 §5；通用复用 1400/1500。Handler 错误映射沿用 `handleServiceError`：成功 HTTP 200；业务错误（1901/1902/1903/1400）HTTP 200 带 code；非 `*service.Error` HTTP 500 带 1500。**本域无 401 路径**（无 JWT，令牌失效走 1901）。

### 2.4 防枚举与令牌安全

- 令牌校验失败统一 1901，不区分不存在 / 已使用 / 已失效 / 任务已完成 / 任务已取消（specs §4.2.4 规则1），message 为固定英文模板，响应体不携带任何任务对象信息。
- 服务端日志口径：WARN 记令牌摘要（哈希前 8 位），不记全文（specs §5.1.5）；ERROR 记任务号。
- 令牌原文经 URL 分发（F7 产出），本域三接口只接收与哈希比对，不产出、不下发令牌。

### 2.5 雪花 ID 传输约束

本域接口响应不回显任何雪花 ID：员工侧无任务主键消费方，`task_no`、`seq` 承载全部标识语义。`assessment_test_answers` 表的 `task_id` 列在 domain 模型层仍按规则文件 §1.2 打 `,string`（未来运营侧查询面的预留，双层覆盖惯例）。

## 3. 接口列表

共 3 个新接口，全部挂公开路由组，按作答页生命周期组织。specs 第 5 章三项非页面功能与三个接口一一对应（5.1 → A1、5.2 → A2、5.3 → A3），无独立会话上报接口（上报内嵌 A1，specs §5.1.2 步骤3）。

### A. 作答页

#### A1. 作答页上下文（令牌校验与会话建立）

**接口路径：** `POST /api/answer/context`

**需求追溯：** [需求：F8-4.1.3 进入作答页（令牌校验）] [需求：F8-4.1.3 前端自动流程 会话上报/对话恢复] [需求：F8-4.2 失效态触发] [需求：F8-5.1]

**说明：** 作答页加载（首次进入与重进同路径）的唯一数据接口。处理链：令牌哈希点查链接行 → 校验（链接 valid 且所属任务 status ∈ {pending, in_progress}）→ 调 F7 StartSession 契约（幂等，任务 pending 转进行中，使逾期 tick 顺延）→ 组装作答上下文（元信息锚点、题目全集现读、已有对话记录按序）。校验链只读不落库（StartSession 幂等推进除外），重进任意次无副作用（specs §5.1.4 规则1）。任一校验不通过返回 1901，前端转失效态（4.2）。题目文本现读口径见 §1.6。

前端据响应自渲染系统预设文案：类型标签 / 测评标题 / 用途说明 / 预计用时 / 作答须知按 test_type 走 i18n 预设（specs §4.1.2 A，数据来源列为「系统预设」），开场白与第一题由 questions[0] 与剧本模板渲染，`finished=true` 时直接进入完成待提交态（specs §4.1.3 对话恢复）。

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| token | string | 是 | 一次性作答令牌（URL 路径参数同源值，base64url 43 字符） |

**请求示例：**

```json
{ "token": "AbCdEfGh...43chars" }
```

**响应示例：**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "task_no": "T202609290001",
    "test_type": "ai_mgmt",
    "question_total": 5,
    "answered_count": 2,
    "finished": false,
    "questions": [
      {
        "seq": 1,
        "dimension_name": "目标设定与对齐",
        "scenario": "你负责推动一项「用 AI 工具提升客服响应效率」的项目……",
        "requirement": "请选择最符合您实际做法的选项并说明理由：A. …… B. …… C. …… D. ……"
      },
      {
        "seq": 2,
        "dimension_name": "授权分工",
        "scenario": "……",
        "requirement": "……"
      }
    ],
    "replies": [
      { "seq": 1, "content": "C，因为……" },
      { "seq": 2, "content": "……" }
    ]
  }
}
```

**响应字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| task_no | string | 任务号（T/E 前缀 + yyyyMMdd + 4 位序号），成功态参考编号的数据源（specs §4.1.2 C） |
| test_type | string | 测试类型 [可选值：ai_mgmt/enneagram]，驱动前端预设文案与输入校验分支 |
| question_total | integer | 题目总数（任务快照 question_ids_json 数组长度） |
| answered_count | integer | 已落库回复数（断点位置，specs §5.2.4 规则1 服务端权威口径） |
| finished | boolean | 是否全部作答完成（answered_count ≥ question_total，完成口径见 §1.7），true 时前端进完成待提交态 |
| questions | array | 题目全集（按快照顺序，现读全文），条目字段见下 |
| questions[].seq | integer | 题目序号（1-based，任务快照内顺序，员工侧「第 X 题」的编号来源） |
| questions[].dimension_name | string | 子能力名（ai_mgmt 经题目 DimensionID 现读 dimensions；enneagram 恒空串，前端不渲染） |
| questions[].scenario | string | 情境描述（ai_mgmt）/ 题项陈述（enneagram），语义按 test_type 切换（与题库三段文本换名口径同构） |
| questions[].requirement | string | 作答要求（ai_mgmt，选项全文行内书写）/ 作答方式说明（enneagram，1-5 级说明） |
| replies | array | 已有作答对话记录（按 seq 升序），重进恢复渲染消息流用；全部作答中无时间戳展示（specs §8.3 偏离记录），条目只携带定位与内容 |
| replies[].seq | integer | 该回复落库的题目序号 |
| replies[].content | string | 员工回复内容 |

**错误码：**

| 错误码 | 说明 |
|--------|------|
| 1901 | 作答令牌不可用（统一口径：不存在 / 已使用 / 已失效 / 任务已完成或已取消；前端转失效态） |
| 1400 | 请求参数格式错误（token 字段缺失或空串） |
| 1500 | 服务内部错误（StartSession 推进失败、题目现读失败；阻断作答防逾期误判，specs §5.1.5 第二三行，前端呈现加载失败与重试） |

#### A2. 作答回复（逐题落库）

**接口路径：** `POST /api/answer/reply`

**需求追溯：** [需求：F8-4.1.3 发送回复] [需求：F8-4.1.4 规则1 规则化施测/规则2 逐题落库] [需求：F8-4.1.5 九型非法提示] [需求：F8-5.2] [需求：F8-5.2.4 规则1/2/3] [需求：F8-4.1.4 规则5 作答中被取消拦截]

**说明：** 员工每次发送回复调用一次。处理链：令牌校验（同 A1 校验链，作答中被取消的任务在此被拦转 1901，specs §4.1.4 规则5）→ 按已落库记录数推算当前题号（服务端权威，请求体无客户端题号字段）→ 格式校验（非空去首尾空格；ai_mgmt ≤500 字符；enneagram 为 1-5 整数）→ 落库一行 → 返回推进指令。格式不通过返回 1902 不落库不推进（specs §5.2.4 规则2），前端按 test_type 渲染重答剧本文案（enneagram「请回复 1 到 5 之间的数字」，输入框保留员工输入，specs §4.1.5）。

推进指令为结构化字段：`action=next` 携带下一题全文（现读），前端渲染题间确认剧本 + 下一题包装；`action=finished` 表示全部完成（answered_count ≥ question_total，完成口径见 §1.7），前端转完成待提交态（输入区原位替换为提示与提交按钮）。

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| token | string | 是 | 一次性作答令牌 |
| content | string | 是 | 回复内容（前端先做本地校验：非空按钮禁用、字数计数器预拦；服务端兜底校验，specs §5.2.5）。键缺失归 1400（字段缺失），空串/纯空白归 1902（格式不符），见错误码表 |

**请求示例：**

```json
{
  "token": "AbCdEfGh...43chars",
  "content": "C，因为……"
}
```

**响应示例（推进下一题）：**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "question_seq": 3,
    "answered_count": 3,
    "question_total": 5,
    "action": "next",
    "next_question": {
      "seq": 4,
      "dimension_name": "监督验收",
      "scenario": "……",
      "requirement": "……"
    }
  }
}
```

**响应示例（全部完成）：**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "question_seq": 5,
    "answered_count": 5,
    "question_total": 5,
    "action": "finished",
    "next_question": null
  }
}
```

**响应字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| question_seq | integer | 本条回复实际落库的题号（服务端推算，供前端对齐，specs §5.2.4 规则1） |
| answered_count | integer | 落库后累计回复数（含本条），前端对话进度「已完成 X / N」的数据源 |
| question_total | integer | 题目总数 |
| action | string | 推进指令 [可选值：next 推进下一题 / finished 全部完成转待提交态] |
| next_question | object \| null | action=next 时携带下一题条目（结构同 A1 questions 条目，现读全文）；action=finished 时为 null |

**错误码：**

| 错误码 | 说明 |
|--------|------|
| 1901 | 作答令牌不可用（含作答中任务被取消、链接被重发作废，specs §5.2.5 第一行；前端转失效态） |
| 1902 | 回复格式不符（空串 / ai_mgmt 超 500 字符 / enneagram 非 1-5 整数；不落库不推进，前端渲染重答提示并保留输入。另含完成态兜底：全部作答完成后再发回复（推算题号 > 题目总数）同返 1902 不落库，防完成态后多余落库，04 文档 §3 推进单调性规则） |
| 1400 | 请求参数格式错误（token 或 content 字段缺失；content 键存在但值为空串走 1902，两者归类不同） |
| 1500 | 服务内部错误（落库失败；前端保留输入内容供重试发送，specs §5.2.5） |

#### A3. 提交作答（作答数据接收）

**接口路径：** `POST /api/answer/submit`

**需求追溯：** [需求：F8-4.1.3 提交并结束] [需求：F8-4.1.4 规则3 提交事务性/规则4 令牌一次性] [需求：F8-4.3 成功态] [需求：F8-5.3] [需求：F8-5.3.4 规则1/2/3]

**说明：** 员工点击「提交并结束」调用。处理链：令牌校验（同 A1 校验链，特例放行「链接 used 且任务 completed」的幂等重复提交直接返回成功，§1.5）→ 作答完整性校验（已落库回复数 ≥ 题目总数，specs §5.3.4 规则1 不等式语义，完成口径见 §1.7）→ 调 F7 CompleteTask 契约（单事务三步推进 + 阅卷任务投递，投递失败整体回滚，specs §5.2.5 口径由 F7 repo 承载）→ 返回任务号，前端转成功态。作答记录在提交时无额外终态化动作（逐题落库已是终态形态，specs §5.3.4 规则3）。并发提交竞态（校验链读到 pending 而 CompleteTask 落地时任务已被另一请求推 completed）重读任务态，completed 仍返回成功（specs §5.3.4 规则2 员工视角一致）；其余终态守卫拦截收敛 1901。提交失败（事务失败）返回 1500，留在作答态可重试（specs §5.3.5）。

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| token | string | 是 | 一次性作答令牌 |

**请求示例：**

```json
{ "token": "AbCdEfGh...43chars" }
```

**响应示例：**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "task_no": "T202609290001"
  }
}
```

**响应字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| task_no | string | 任务号，成功态「参考编号」展示源（等宽字体，specs §4.3.2） |

**错误码：**

| 错误码 | 说明 |
|--------|------|
| 1901 | 作答令牌不可用（invalid / 任务 canceled / used 但任务未 completed 的异常态；前端转失效态） |
| 1903 | 存在未作答题目（已落库回复数 < 题目总数，specs §5.3.4 规则1 的不等式语义为完成判定的权威口径，§1.7；前端回到作答态断点续答） |
| 1400 | 请求参数格式错误（token 字段缺失或空串） |
| 1500 | 服务内部错误（事务失败含阅卷投递失败整体回滚，specs §5.3.5；前端 toast 后留在作答态可重试提交） |

## 4. 服务内部契约

### 4.1 令牌校验链（三接口共享）

```
输入:  token（请求体）
流程:  1. SHA-256(token) hex 点查 assessment_test_links（uk_token_hash，F7 04 §3.2）
       2. 无行 → 1901（统一口径，不区分不存在与失效，specs §4.2.4 规则1）
       3. 链接 status=invalid → 1901；status=used → 走 4 的任务态判定
       4. 读所属任务行：status ∈ {pending, in_progress} → 走 5
          status=completed 且链接 used → 仅 A3 幂等放行（§1.5），A1/A2 返回 1901
          其余（completed/expired/canceled）→ 1901
       5. 到期即时判定：link.ExpiresAt < now 且任务 status ≠ in_progress → 1901
          （豁免 in_progress：已建会话的任务顺延至提交或取消，链接对已建立
           会话保持可用，specs §4.1.3 / F7 specs §5.3.4）
返回:  通过 → (task, link) 供各接口续作；不通过 → *service.Error{1901}
日志:  校验失败 WARN 记令牌摘要（哈希前 8 位）与链接状态，不记令牌全文
```

**需求追溯：** specs §5.1.2 步骤1-2、§5.2.2 步骤1、§5.3.2 步骤1、§4.2.4 规则1、§4.1.3（in_progress 顺延豁免）。

到期即时判定（步骤 5）收口 tick 空窗：每分钟 ExpirePending 只扫 pending 任务，先于 tick 被 A1 救活的过期链接若不在此拦下，任务转 in_progress 后永不过期。判定只拦未建会话的任务（pending；expired 任务的链接恒为 invalid 已被步骤 3 拦下），in_progress 按 specs §4.1.3 顺延口径豁免：员工跨过链接到期时刻后 reply 续答与重进 context 均保持可用，直至提交或运营取消。

### 4.2 对 F7 服务契约的消费点

| F7 契约 | 消费接口 | 调用方式 | 需求追溯 |
|---------|---------|---------|---------|
| StartSession(taskID) | A1 | 校验通过后进程内直调（幂等，pending → in_progress 条件更新；失败返回 1500 阻断作答，防作答中任务停留待作答被逾期判定命中，specs §5.1.5） | specs §5.1.2 步骤3、§6.2 |
| CompleteTask(taskID) | A3 | 完整性校验通过后进程内直调（事务内任务 completed + 链接 used + 阅卷投递，投递失败整体回滚；completed 幂等路径 F7 repo 已承载） | specs §5.3.2 步骤2、F7 03 §4.6 |

answer 域 service 依赖注入 AssessmentTestTaskService 接口（F7 已定义，含两契约方法），复用既有 Wire 装配链，不新建平行实现。

### 4.3 阅卷作答对话段接入（本 feature 实现范围）

F7 grading 引擎的 prompt 组装中「作答对话段」当前为空占位（`emptyAnswerSectionPlaceholder`，F7 03 §4.4 步骤2b「F8 落库的作答记录，未建前无触发路径」）。本 feature 落地时同步接入：

- grading.Grader 增加答案读取窄接口（AnswerRepo：按 task_id 取全部回复按 seq 升序），构造签名与 Wire 装配随之调整。
- prompt 作答对话段替换为真实记录拼接：逐题一行「第 X 题作答：{content}」，空记录（理论不可达，提交门槛已保证全答）保留占位文案兜底。
- 阅卷按作答对话全过程评分（specs §5.2.3：全过程对话非仅最终选项），作答原文进入 prompt 前不脱敏（脱敏破坏阅卷证据，与 rationale 落库前 Redact 的分工不同：Redact 约束落库字段，prompt 是进程内一次性消费）。

**需求追溯：** specs §1.1（作答对话记录无落库方是本 feature 立项动机）、§5.3.6 下游影响。

## 5. 错误码

新增 19xx 段共 3 个码；通用 1400/1500 复用。本域不使用 F7 的 18xx（任务运营错误归运营侧接口）。

| 错误码 | 常量 | 含义 | 使用场景 |
|--------|------|------|---------|
| 1901 | AnswerTokenInvalid | 作答令牌不可用 | 三接口令牌校验失败（统一防枚举口径：不存在 / 已使用（A3 幂等特例除外）/ 已失效 / 任务已完成或已取消），specs §4.2.4 规则1 |
| 1902 | AnswerReplyInvalid | 回复格式不符 | A2 格式校验失败（空 / ai_mgmt 超 500 字符 / enneagram 非 1-5 整数），specs §5.2.2 步骤2；含完成态兜底（已完成后再发回复不落库，04 文档 §3 推进单调性） |
| 1903 | AnswerIncomplete | 存在未作答题目 | A3 完整性校验失败（记录数 < 题目数），specs §5.3.4 规则1 |

## 6. 与相邻域的边界

- **对 F7（P2_TST_001 主动测试运营）**：只读消费任务与链接数据（经令牌哈希点查）、进程内调用 StartSession/CompleteTask 两契约（§4.2）；不写 F7 三表（状态推进全部经 F7 service/repo 单点）。作答对话记录表归本域落库，阅卷引擎消费（§4.3）。
- **对 P2_QBN_001（题库）**：只读消费题目现读通道（ListByIDsUnscoped 含软删行，F7 已建）；不写题目表（reference_count 的 +1 在 F7 建任务事务内已完成，本域无计数动作）。
- **对 P2_DIM_001（维度）**：只读消费子能力名（A1 组装 dimension_name，经题目 DimensionID 现读）；不写维度表。
- **对 P1_ACC_001（账号）**：仅复用路由骨架与公开页面模式（/login 同构的挂路由根模式）；无 JWT 依赖、无 auth store 消费（specs §7.2 流程依赖）。
- **对 F9（个人画像，未建）**：本域产出经阅卷链路汇入（dimension_scores / assessment_test_results 均为 F7 写入），answer 域不直接产出画像数据。
- **对 grading（F7 阅卷引擎）**：本域落库的作答记录是其作答对话段数据源（§4.3 接入声明）；阅卷触发经 F7 CompleteTask 事务内投递，本域不直接投递任务。
