# AI生成出题 实现计划

> **目标：** 落地 question_generations 表与 LLM 出题全链路：发起生成（校验维度集合与题数、建 generation 行、投递 Asynq 任务）、worker 逐题生成（暂存 staging、进度更新、协作式取消、完成落库建批、失败零残留）、进度轮询接口，前端题目生成页四态（表单/进行中/完成/失败）与轮询。
> **架构：** 生成走 Asynq 异步任务 + 前端轮询（03 §二：HTTP WriteTimeout 30s 硬编码不可行长连接，specs 4.3.4 规则 3 已授权接口设计阶段定进度机制）。LLM 生成器独立 engine/questiongen 子包（evaluator 同构：专用 LLM client + 窄接口依赖注入 + 纯函数 prompt/schema 解析），worker 任务注册仿 person_evaluate 五步套路。MySQL staging 列 MEDIUMTEXT 钩子落 migrateDB A 段。
> **技术栈：** Go 1.25 + Asynq + GORM + LLM 底座（StreamChat）；React 19 + TanStack Query refetchInterval 轮询

        Create(ctx context.Context, g *domain.QuestionGeneration) error
        FindByID(ctx context.Context, id int64) (*domain.QuestionGeneration, error)
        // MarkRunning 领取：仅 status=QUEUED 时置 RUNNING（CAS：WHERE id=? AND status='QUEUED'），
        // RowsAffected=0 返回 ErrNotQueued（已被取消等）。

        // SaveProgress 更新进度与暂存：generated_count/current_dimension_id/staging 原子覆盖。
        SaveProgress(ctx context.Context, id int64, generatedCount int, currentDimensionID int64, staging string) error
        // FinishCompleted 完成事务（单事务收口，04 §3.3）：同事务内建 GENERATE 批次 + staging 展开
        // 插 questions（Q-AG 编号连续分配收在本方法事务内：MaxQuestionSeq("Q-AG-") Unscoped 取段递增，

        // question_generations 三表，repository 单方法收口，engine 只传参数不碰事务。
        // WHERE 恒带 status=RUNNING 前置。
        FinishCompleted(ctx context.Context, id int64, batch *domain.QuestionBatch, questions *[]domain.Question) error
        // FinishTerminal 失败/取消终态：置 status（FAILED/CANCELED）+ error_code + staging 清空。
        // 幂等：仅 RUNNING/QUEUED 可置（WHERE status IN (...)），已终态返回 ErrAlreadyTerminal（不报错上抛，调用方忽略）。

        // RequestCancel 协作式取消：仅 QUEUED/RUNNING 置 CANCELED（error_code=CANCELED），
        // 已终态幂等成功（RowsAffected=0 视为已终态，返回 nil）。
        RequestCancel(ctx context.Context, id int64) error
