**实现契约：**

`ratelimit.go` 新增 KeyFunc（紧随 ClientIPKey）：
```go
// AccountIDKey 以 JWT 中间件注入的 account_id 作限流桶标识。
// 用于已鉴权接口按账号限流；未鉴权（account_id 缺失）返回空串 fail-open。
func AccountIDKey(c *gin.Context) string {
    id, ok := AccountIDFromContext(c)
    if !ok {
        return ""
    }
    return strconv.FormatInt(id, 10)
}
```

import 追加 `"strconv"`。AccountIDFromContext 已在 middleware/jwt.go（同包）定义，返 `(int64, bool)`。

**关键逻辑：** AccountIDKey 复用现有 AccountIDFromContext，不重复读 ctx key。health-check 路由先挂 JWT 中间件（auth 组）注入 account_id，再挂 RateLimit 用 AccountIDKey 取值分桶，顺序由路由注册保证。

**核心断言（middleware 测试，package middleware_test 或 _test 同包）：**
- 构造 gin.Context 手动 `c.Set("account_id", int64(1845700000000000012))`，`AccountIDKey(c) == "1845700000000000012"`
- 空 ctx（无 account_id），`AccountIDKey(c) == ""`
- 验证命令：`go test ./internal/api/middleware/ -run TestAccountIDKey`，预期 PASS

`service/system.go`：

```go
// 组件健康状态值（03 §3.4 枚举，04 §8 不用字典表）
const (
    StatusConnected          = "connected"
    StatusDisconnected       = "disconnected"
    StatusReachable          = "reachable"
    StatusUnreachable        = "unreachable"
    StatusNotConfiguredModel = "not_configured_model"
    StatusNotConfiguredKey   = "not_configured_key"
    StatusNotConfigured      = "not_configured"
)

// DependencyProbe 探测 config 落地后的外部依赖（大模型、会话日志集成）可达性。
// config 未落地前由 NoopDependencyProbe 返回 not_configured，落地后替换为真实探测实现。
type DependencyProbe interface {
    ProbeLLM(ctx context.Context) string
    ProbeIntegration(ctx context.Context) string
}

type NoopDependencyProbe struct{}

func (NoopDependencyProbe) ProbeLLM(_ context.Context) string      { return StatusNotConfigured }
func (NoopDependencyProbe) ProbeIntegration(_ context.Context) string { return StatusNotConfigured }

type SystemService interface {
    GetSummary(ctx context.Context) (*SystemSummary, error)
    HealthCheck(ctx context.Context) (*HealthResult, error)
}

type SystemSummary struct {
    Initialized bool
    DBType      string
    Version     string
    StartedAt   time.Time
}

type HealthResult struct {
    Database    string
    Redis       string
    LLM         string
    Integration string
}

type systemService struct {
    systemInitRepo repository.SystemInitializationRepository
    dbProbe        func(context.Context) bool
    redisProbe     func(context.Context) bool
    probe          DependencyProbe
}

func NewSystemService(systemInitRepo repository.SystemInitializationRepository, dbProbe, redisProbe func(context.Context) bool, probe DependencyProbe) SystemService
```

**关键逻辑：**

GetSummary（specs §5.3.2）：
1. `initialized, _ := systemInitRepo.Exists(ctx)`，出错 initialized 取 false 并 slog.Error（specs §5.3.5）
2. `dbType := model.Current()`、`version := model.Version`、`startedAt := model.StartedAt`
3. 返回 `&SystemSummary{Initialized: initialized, DBType: dbType, Version: version, StartedAt: startedAt}`，始终 nil error（specs §5.3.5 接口始终 code 0）

HealthCheck（specs §5.4.2）：
1. `db := StatusConnected; if !dbProbe(ctx) { db = StatusDisconnected }`
2. `r := StatusConnected; if !redisProbe(ctx) { r = StatusDisconnected }`
3. `llm := probe.ProbeLLM(ctx)`（NoopDependencyProbe 返 not_configured）
4. `integ := probe.ProbeIntegration(ctx)`
5. 返回 `&HealthResult{Database: db, Redis: r, LLM: llm, Integration: integ}`，始终 nil error（specs §5.4.5 探测失败是业务结果）

**依赖可解析：** import `context`、`log/slog`、`time`、`sili-smart-hr/backend/internal/model`、`sili-smart-hr/backend/internal/repository`。dbProbe/redisProbe 复用子计划 01 的 ProvideDBProbe/ProvideRedisProbe provider（wire 注入同一闭包）。

**测试契约：** `service/system_test.go`（package service_test），用 fake systemInitRepo（可配置 exists 返回）+ 可控 dbProbe/redisProbe 闭包 + NoopDependencyProbe。仿 account_test.go 的 fake 模式。

**核心断言：**
- `TestGetSummary_NotInitialized`：fake exists=false → `Initialized==false`、`DBType=="sqlite"`（测试环境）、`Version=="v0.1.0"`（model.Version 默认）、`StartedAt` 非零（测试前可设 model.StartedAt = time.Now()，t.Cleanup 还原）
- `TestGetSummary_Initialized`：fake exists=true → `Initialized==true`
- `TestHealthCheck_AllConnected_NoopProbe`：dbProbe/redisProbe 返 true + NoopDependencyProbe → `Database=="connected"`、`Redis=="connected"`、`LLM=="not_configured"`、`Integration=="not_configured"`
- `TestHealthCheck_DBDown`：dbProbe 返 false → `Database=="disconnected"`、`Redis=="connected"`（其余项不受影响，BR21）
- `TestHealthCheck_CustomProbe`：注入自定义 DependencyProbe（返 reachable/unreachable）→ `LLM=="reachable"`、`Integration=="unreachable"`

import type { HealthResult, SystemSummary } from '@/lib/contracts';  // 追加到现有 import

/** useSystemSummary：运行状态摘要，受 _authenticated 布局保护，token 由拦截器自动附。 */
