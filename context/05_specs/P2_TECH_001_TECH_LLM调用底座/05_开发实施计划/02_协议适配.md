# LLM调用底座 实现计划 - 子计划 02 协议适配器与统一入口

> **目标：** 交付 OpenAI 兼容适配器（go-openai）与 Anthropic 适配器（anthropic-sdk-go）两个协议适配器，以及 `client.go` 统一入口（StreamChat 主流程、错误分类、适配器缓存、并发 gate 接入、slog 日志），配套端到端集成测试与性能测试，完整落地 specs §2.1 全部 5 项能力。
> **架构：** 两个适配器实现未导出接口 `adapter`，把各自 SDK 的流式调用与错误转换为底座统一契约（Stream / httpError）；`client.go` 编排 token 预检 → 启用模型解析 → 适配器选择与缓存 → 全局并发排队 → 重试 → 错误分类。子计划 01 冻结的类型契约在此只读消费，不改动。
>
> **登记（终审留痕）：** T8 对子计划 01 文件有两处最小增量修改，经子计划 02 终审核定为可接受：model.go 新增 `*Error.Is` 方法（sentinel 复制方案的必要前提，复制体需可通过 errors.Is 匹配，纯增量无行为变更）；concurrency.go 新增 `gate.QueueDepth()` 只读方法（specs §6.1 queue_depth 日志字段的直接依赖）。两处均未改动既有契约。
> **技术栈：** Go 1.25、sashabaranov/go-openai v1.7.0、anthropics/anthropic-sdk-go v1.47.0（stream 子包）、net/http/httptest（集成测试 mock）、log/slog（结构化日志）。

    ```go
    type Client interface {

    }
    // adapter 是协议适配器抽象，按服务商归属协议实现流式对话补全（specs §2.4 能力5）。
    type adapter interface {
        StreamChat(ctx context.Context, mc ModelConfig, req ChatRequest) (Stream, error)
    }
    type client struct {
        cfg      Config
        provider EnabledModelProvider
        gate     *gate
        mu       sync.Mutex

    }

    func New(cfg Config, provider EnabledModelProvider) Client
    func (c *client) StreamChat(ctx context.Context, req ChatRequest) (Stream, error)
    // applyDefaults 填充 Config 零值默认（specs §2.2 参数列表）。
    func applyDefaults(cfg Config) Config
    // classifyError 把 httpError/超时等收敛为底座领域错误（specs §2.3）。
    func classifyError(err error) error
    // gatedStream 包装底层 Stream，Close 时经 sync.Once 释放并发槽。
    type gatedStream struct {
        Stream
        once    sync.Once
        release func()
    }
    func (s *gatedStream) Close() error
    ```
    ```go
    // 编译期断言：client 未导出，同包内断言其满足 Client 接口（改动接口编译即报错）。
    var _ Client = (*client)(nil)
    ```
  - 关键逻辑：
    - `applyDefaults`：Timeout 0→120s、MaxRetries 0→3、InitialBackoff 0→30s、MaxBackoff 0→120s、RetryOnStatus 空→`[429, 500, 502, 503, 504]`、MaxConcurrency 0→4、QueueSize 0→1024、TokenCounter nil→`NewTikTokenCounter()`。
    - `StreamChat` 主流程（按序，任一失败短路）：
      1. 启用模型解析：`provider.GetEnabledModel(ctx)` 获取 `mc`，返回 error → `ErrProviderUnavailable`（specs §2.4 能力5 注意事项）。
      2. token 预检：`cfg.TokenBudget > 0` 时 `checkTokenBudget(ctx, cfg.TokenBudget, cfg.TokenCounter, mc.ModelID, req.Messages)`，超限返回 `ErrContextLengthExceeded` 且不进入 gate、不调适配器（specs §2.4 能力2、§5.1 token 预检）。
      3. 适配器选择与缓存：`adapterFor(mc)`，归属映射 `deepseek/openai/zhipu → newOpenaiAdapter`、`anthropic → newAnthropicAdapter`，未知 Provider → `ErrProviderUnavailable`；缓存 key 含 APIKey，模型切换或密钥轮换即时重建，相同 ModelConfig 复用（specs §5.1 适配器缓存）。
      4. 全局并发 gate：`gate.Acquire(ctx)`，队列满返回 `ErrQueueFull`（specs §2.4 能力4）。
      5. 重试发起：`retryWithBackoff(ctx, cfg, func() error { s, e := adp.StreamChat(ctx, mc, req); ... })` 内调适配器，占槽直至成功或失败。
      6. 失败：`gate.Release()`，返回 `classifyError(err)`；成功：返回 `&gatedStream{Stream: stream, release: gate.Release}`，`Close()` 时经 `sync.Once` 释放槽。
    - `classifyError`：`*httpError` 按 `status` 映射 401→`ErrAuth`、429→`ErrRateLimited`、400 且 message 含 `context_length_exceeded`→`ErrContextLengthExceeded`、`timeout==true`→`ErrTimeout`、其余 5xx→`ErrRetryExhausted`、其余→`ErrUnknown`；非 httpError 若 `errors.Is(ctx.Err())` 相关透传，否则 `ErrUnknown`。
    - 日志（specs §6.1）：每次调用完成 INFO，字段 `model`、`prompt_tokens`、`completion_tokens`、`duration`、`queue_wait`、`retries`、`ok`；重试进行中 WARN（`status`、`retry`、`backoff`、`queue_depth`）；重试耗尽 ERROR（`code`）；协议与流式细节 DEBUG（适配器请求构造、流式分块片段，同样脱敏）。禁止输出 API Key 与对话原文（specs §3.3 安全要求）。
