# 量表引入 实现计划

> **目标：** 落地两套九型量表内置模板与引入闭环：量表候选列表（含已引入标记）、引入事务（ensure 九型型别维度 → 批量建题 → 建 IMPORT 批次）、前端量表引入两步弹窗，引入后直接进入 SP2 批量审核视图。
> **架构：** 量表模板为 Go 侧代码常量（04 §4.1，不建表），置于独立 scaledata 包（题项数据独立文件便于整体替换全集）；引入事务复用 SP2 的 CreateBatchWithQuestions 与 NextBatchNo；并发重复引入经 ENNEAGRAM 维度行 SELECT ... FOR UPDATE 串行化拦截（03 §3.12）。前端在题库管理页工具栏接通「引入九型量表」两步弹窗。
> **技术栈：** Go 1.25 + GORM（行锁子句）；React 19 + shadcn/ui（RadioGroup 需新引入或手写单选卡片）

## 代码库依据

- 相关入口与复用：
  - SP2 已落 QuestionBatchRepository.CreateBatchWithQuestions（建批+批量插题+编号分配事务）与 NextBatchNo("S")，本计划直接消费。
  - SP1 已落 QuestionRepository.MaxQuestionSeq（编号连续取段依据）与 question_no/scale_key 列。
  - GORM 行锁：项目内无 FOR UPDATE 先例，GORM 用 `clauses.Locking{Strength: "UPDATE"}`（gorm.io/gorm/clauses）或 `tx.Clauses(...)`；SQLite 忽略锁子句（单写库天然串行），MySQL/PG 生效，测试以 SQLite 走通事务语义、锁行为靠方言正确性保证。
  - 维度 ensure：dimensions 表结构见 domain/dimension.go；复用判定按内置 code 查活跃行（GORM 默认过滤软删），软删行视为不存在并新建；anchor 必填 ≤500；module_code=ENNEAGRAM、data_source=TEST、weight=0、include_overview=false、is_reference=true（04 §4.2）。dimensions Create 走 repository.DimensionRepository.Create（雪花回调赋 ID、撞 uk_dimension_code 需容错）。
  - seed 先例：model/seed_dimensions.go 的 defaultDimensions() 硬编码切片 + Transaction 整批写入（本计划的型别维度定义与题项模板同范式，但归属 questionbank 包内置数据，不进 migrateDB seed）。
  - 前端单选卡片：无 RadioGroup UI 组件，量表的「单选卡片」用手写 button 组（选中态 border-primary + bg-accent），assessment tab 手写先例同款；引入弹窗用 Dialog 两步切换（step state）。
  - 已引入判定：GET /api/scales 实时查 questions 表（scale_key 前缀 + 未逻辑删除计数，Unscoped 排除软删）。
- 验证入口：同 SP1/SP2。量表题项数据源已确认：样本题先行（每套 9-18 题代表性样本，全链路可验收），数据独立文件便于后续整体替换 144/108 全集，替换后 QuestionCount/EstimatedMinutes 以模板常量为准自动生效。
- 规模与耦合判断：量表引入是自包含业务闭环（模板数据 + 引入事务 + 两步弹窗），依赖 SP1/SP2 已落的地基，无跨子计划共享文件冲突（router/wire/contracts 顺序追加，i18n 同 ns 扩展）。行锁是本计划唯一新机制，收敛在引入事务单点。

    ```go
    type ScaleRepository interface {
        // CountImported 按 scale_key 统计未逻辑删除题目数（Unscoped 排除软删：含 PENDING/ACTIVE/DISABLED/REJECTED 态），
        // >0 即已引入（specs 规则 8）。两 key 一次查回。tx 传 nil 用 r.db（ListScales 场景），
        // 引入事务内传外层 tx 与行锁同连接读（事务内当前读）。
        CountImported(ctx context.Context, tx *gorm.DB, keys []string) (map[string]int64, error)
        // LockEnneagramDimensions 引入事务内对 9 个 ENNEAGRAM 型别维度行加锁（SELECT ... FOR UPDATE，
        // GORM clauses.Locking{Strength:"UPDATE"}）：按内置 code 集合查活跃行锁定并返回；
        // SQLite 忽略锁子句不影响正确性（单写串行）。行缺失的 code 不在返回集中（由 service ensure 补建）。
        LockEnneagramDimensions(ctx context.Context, tx *gorm.DB, codes []string) ([]domain.Dimension, error)
        // EnsureEnneagramDimensions 锁内 ensure：code 已存在（活跃行）则复用（任意状态含停用），
        // 缺失则按模板定义新建（module_code=ENNEAGRAM、data_source=TEST、enabled=true、weight=0、
        // include_overview=false、is_reference=true、anchor=模板内置型别一句话描述 ≤500、version=1）。
        // 返回 code→维度 ID 映射。
        EnsureEnneagramDimensions(ctx context.Context, tx *gorm.DB, dims []scaledata.ScaleDimension) (map[string]int64, error)
        // ImportScale 引入事务主体：行锁+ensure 后判已引入（锁内最新已提交数据，>0 题 Return ErrScaleImported），
        // 然后按模板组装 questions 行（question_no 由 CreateBatchWithQuestions 在事务内按 Q-Scale- 前缀
        // 连续分配，调用方不预填；source=SCALE、status=PENDING、scale_key、dimension_id 取 ensure 映射、
        // version=1、reference_count=0），建 IMPORT 批次（复用 QuestionBatchRepository.CreateBatchWithQuestions
        // 并传入外层 tx 同事务提交，NextBatchNo("S")，title=量表名、source=SCALE、scale_key、dimension_ids 空串）。
        // 事务整体收口，撞 uk_question_batches_batch_no 上抛由 service 重试或映射错误。
        ImportScale(ctx context.Context, tpl *scaledata.ScaleTemplate, now time.Time) (*domain.QuestionBatch, error)
    }
    // 哨兵：var ErrScaleImported = errors.New("scale already imported")
    ```

  - 依赖：domain、scaledata、QuestionBatchRepository（结构体字段注入或同 repo 共享 db；实现内直接 newBatchRepo 字段复用，见 T2 实现自由度）、gorm clauses、dberr。
