# 维度与权重配置 实现计划 — 子计划1：后端维度域

> **目标：** 落地 dimension 域四层链路（domain → repository → service → handler → router → wire），提供 7 个接口支撑前端配置页。
> **架构：** 照 account 样板走四层 + Wire 注入。Dimension/DimensionSetting 两表 GORM AutoMigrate，dimension_settings 首启 seed 单行默认值。service 承载模块联动、编码生成、阈值校验、version 乐观锁，handler 复用 handleServiceError 错误映射。
> **技术栈：** Go 1.25、Gin、GORM（多库）、Wire、github.com/mozillazg/go-pinyin（中文转拼音，标准库无）、bwmarrin/snowflake（已在用）。

- [x] **T3: DimensionRepository 数据访问层**

  **文件：**
  - 创建：`hr-backend/internal/repository/dimension.go`
  - 测试：`hr-backend/internal/repository/dimension_test.go`（由实现者按 TDD 指导创建，用 :memory: SQLite + GORM Open）

  **契约：**
  - 接口 `DimensionRepository`（package repository）方法签名：
    - `ListAll(ctx context.Context) ([]domain.Dimension, error)` — 全量未软删除维度，按 `code ASC` 排序（spec §4.1.5），供维度树组装
    - `FindByID(ctx context.Context, id int64) (*domain.Dimension, error)` — 主键查，软删除自动过滤（GORM DeletedAt）
    - `FindByCodeExcludingDeleted(ctx context.Context, code string) (*domain.Dimension, error)` — 编码唯一性校验，排除软删除（WHERE code=? AND deleted_at IS NULL），返回 ErrRecordNotFound 表示可用
    - `Create(ctx context.Context, d *domain.Dimension) error` — 插入
    - `UpdateWithVersion(ctx context.Context, id int64, version int, updates map[string]any) (int64, error)` — 乐观锁更新：WHERE id=? AND version=? AND deleted_at IS NULL，更新可变字段列并 version=version+1，返回 RowsAffected（1=成功，0=版本冲突或不存在）
    - `SoftDeleteWithVersion(ctx context.Context, id int64, version int) (int64, error)` — 软删除带乐观锁：WHERE id=? AND version=?，GORM Delete 返回 RowsAffected
    - `GetActivitySetting(ctx context.Context) (*domain.DimensionSetting, error)` — 读 dimension_settings 单行表首行（系统级单例，固定取首行），供活跃度规则查询
    - `UpdateActivitySetting(ctx context.Context, activeThreshold, lowFrequencyThreshold int) error` — UPDATE dimension_settings 单行（保存即覆盖，无乐观锁，specs §3.7 业务规则）
  - dimension_settings 两方法与 dimensions 六方法并入同一 `DimensionRepository` 接口（减少 provider 数量），不另立 ActivityRuleRepository
  - 实现结构体 `dimensionRepository`（小写不导出）持有 `*gorm.DB`，`NewDimensionRepository(db *gorm.DB) DimensionRepository` 返回接口
  - `UpdateWithVersion` 的 updates 仅含可变字段（name/prompt/anchor/weight/include_overview/enabled/description），不可变字段 code/module_code/group_code/data_source 不在 updates，version 自增通过 GORM Expr 或显式写 `version = version + 1`
  - 全部用 GORM 链式 API + 占位符，不手写原生 SQL（无保留字列名，group_code 不是 SQL 保留字，无需 QuoteIdent）

  **验收锚点：**
  - 核心断言：`UpdateWithVersion` 在 version 匹配时返回 `(int64(1), nil)`、version 不匹配返回 `(int64(0), nil)`；`FindByCodeExcludingDeleted` 对已软删除记录返回 `gorm.ErrRecordNotFound`
  - 验证命令：`cd hr-backend && go test ./internal/repository -run TestDimension -v`
  - 预期输出：乐观锁更新、软删除过滤、编码查询的测试全部通过

- [x] **T4: DimensionService 业务层（维度 CRUD + 编码生成 + 模块联动）**

  - DTO 结构体（json tag 严格对齐 03 接口字段）：

    - `DimensionDetail`（详情全字段，id/code/name/module_code/group_code/data_source/prompt/anchor/weight/include_overview/enabled/is_reference/description/version/created_at/updated_at，承载雪花 ID 的 id 字段 `json:"id,string"`）
    - `CreateDimensionInput`、`UpdateDimensionInput`、`DeleteDimensionInput`（请求体）
    - `DimensionMutationResult`（新增/编辑响应，对齐 03 §3.3/§3.4 响应结构：id（`json:"id,string"`）/code/name/module_code/group_code/data_source/weight/include_overview/enabled/version；编辑响应另含 updated_at）
    - `ActivityRuleDTO`（active_threshold/low_frequency_threshold/updated_at）
  - 编码生成纯函数 `GenerateDimensionCode(moduleCode, name string) string`：按 specs §4.1.4 规则4 + 03 §3.3：
    - moduleCode→前缀映射 ACTIVITY→`ACT`、AI_USAGE→`AI`、AI_MGMT→`MGT`、ENNEAGRAM→`ENN`
    - name 经 go-pinyin 转全大写拼音（默认声调忽略），与前缀用下划线连接，如 `需求澄清能力`→`AI_XUQIU_CHENGQING_NENGLI`
    - 截断 ≤40 字符（specs 规则4 编码上限）
    - 同名去重序号由调用方（service.CreateDimension）在编码冲突时追加 `_2/_3`，GenerateDimensionCode 本身不负责去重（保持纯函数）
  - service 方法签名（接口 `DimensionService`）：
    - `GetTree(ctx context.Context) (*DimensionTreeNode, error)` — repo.ListAll 后按 module_code 分组组装四模块固定顺序（ACTIVITY/AI_USAGE/AI_MGMT/ENNEAGRAM），AI_USAGE 下分 BASE/UPPER，其余模块维度挂模块直属；模块/分组的 name/data_source/is_reference 由 service 据 module_code 派生（硬编码常量表，不查库，因模块不入库）
    - `GetDetail(ctx context.Context, id int64) (*DimensionDetail, error)` — repo.FindByID，不存在返 1201
    - `CreateDimension(ctx context.Context, in CreateDimensionInput) (*DimensionMutationResult, error)` — 校验 + 编码生成 + 唯一校验 + 入库：
      - name 校验 2~30 字符（utf8.RuneCountInString），不符返 1205
      - anchor 必填非空，不符返 1206；prompt 当 data_source=CONVERSATION 必填，不符返 1207；长度校验超长返 1400
      - 模块联动校验（specs §4.2.4 规则1 + §4.1.4 规则5）：调用私有 `applyModuleDefaults(moduleCode)` 派生 data_source/weight/include_overview/is_reference，显式传值则校验一致，不一致返 1400。联动表：ACTIVITY→RULE/w0/include_false/ref_false；ENNEAGRAM→TEST/w0/include_false/ref_true；AI_MGMT→TEST/w5/include_true/ref_false；AI_USAGE→CONVERSATION/w5/include_true/ref_false
      - group_code 仅 AI_USAGE 接受 BASE/UPPER，其余模块非空则返 1400
      - 编码生成：GenerateDimensionCode 后用 FindByCodeExcludingDeleted 查重，冲突追加序号去重（最多重试合理上限如 10 次），仍冲突返 1202
      - enabled 强制 true（specs §6.1）、version 初始 1，snowflake.NextID() 赋 ID，repo.Create
    - `UpdateDimension(ctx context.Context, in UpdateDimensionInput) (*DimensionMutationResult, error)` — repo.FindByID 取当前记录校验存在（不存在 1201），字段校验同 Create，模块联动兜底校验（ACTIVITY/ENNEAGRAM 的 weight≠0 或 include_overview=true 返 1400），repo.UpdateWithVersion(id, in.Version, updates)，RowsAffected=0 返 1204
    - `DeleteDimension(ctx context.Context, in DeleteDimensionInput) error` — repo.FindByID 校验存在，enabled=true 返 1203（specs §4.1.4 规则3），repo.SoftDeleteWithVersion(id, in.Version)，RowsAffected=0 返 1204
    - `GetActivityRule(ctx context.Context) (*ActivityRuleDTO, error)` — repo 读 dimension_settings 首行
    - `SaveActivityRule(ctx context.Context, in ActivityRuleInput) (*ActivityRuleDTO, error)` — 校验 1≤low<active≤999，不符返 1208；repo UPDATE 单行
  - repository 层 dimension_settings 单行表方法已在 T3 的 `DimensionRepository` 接口中定义（`GetActivitySetting`/`UpdateActivitySetting`），service 直接消费，不另建接口或 provider
  - error 模型沿用 `*service.Error{Code,Msg}` + `NewError(code)`，内部错误 `fmt.Errorf("...: %w", err)`
